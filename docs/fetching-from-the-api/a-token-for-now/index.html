A Token for Now

Every ticket route needs a token, and there's no login page yet, so for now you log in by hand and paste the token into .env.

  • Starting the API

    From now on the front-end needs the Support Desk API running, with its database migrated and seeded.

  • Logging In by Hand

    There's no login page until Stage 4, so you log in once with a REST client and keep the token it sends back.

  • The Token in .env

    The token goes in .env as VITE_DEV_TOKEN, a setting the API client can read, and .env.example lists it, empty.

  • getToken()

    One small function in client.js now returns the token from .env. It's the only change to the API client in this stage.

  • A Token Isn't a Setting

    Stage 0 said a front-end can't keep a secret. VITE_DEV_TOKEN breaks that rule on purpose, so it's only safe on your own machine, and only for now.
