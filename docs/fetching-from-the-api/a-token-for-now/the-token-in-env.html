The Token in .env

The token goes in .env as VITE_DEV_TOKEN, a setting the API client can read, and .env.example lists it, empty.

The token needs to be somewhere the front-end's code can read it, but not written into the code itself: it's different for every student, and it runs out. That's the job .env already does for VITE_API_URL (Stage 0, topic 02).

So .env.example gains a second setting:

# Figure 2.2: the stand-in token's setting (.env.example, excerpt)
# TEMPORARY (Stages 2 and 3 only): a token to send with every request,
# until Stage 4 adds a login page. Log in once with a REST client
# (POST /auth/login), and paste the `token` from the response here, without
# quotes. Leave it empty if your API has no authentication.
VITE_DEV_TOKEN=

It's empty in .env.example on purpose. That file is committed, so it lists the settings without anyone's values. Your token goes in .env, which git ignores.

Adding it to your .env

If your .env came from Stage 0's .env.example, it doesn't have this line yet. Add it, with the token you copied on the last slide pasted after the =:

VITE_API_URL=http://localhost:3000
VITE_DEV_TOKEN=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIi...

No quotes, and no spaces around the =. Save the file. As in Stage 0, Vite notices and restarts itself (.env changed, restarting server...), and you reload the page.

The name

  • VITE_: without this prefix, Vite wouldn't let the browser code read it at all (Stage 0, topic 02).
  • DEV_: it's for development only. A real user never pastes a token into a file; they log in.
  • TEMPORARY in the comment: the same word as at the top of Stage 1's sampleTickets.js, and for the same reason. It marks something a later stage removes.

Try it

Reload http://localhost:5173/tickets. You should see a table of tickets instead of "Authentication required".

Now change one character in the middle of the token in .env, save, and reload. What does the page say now? How is that different from having no token at all? Put the token back the way it was before you go on.
