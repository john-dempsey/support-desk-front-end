Try It Yourself

Challenges that use everything in this lesson. Run the tests after each one, and commit when they pass.

Each of these builds on something from this lesson. After each one, run npm test and npm run lint, and commit when both pass.

Warm-up

  1. Close the gap. If you didn't do it in topic 07, add the line to the list page's loading test that fails when tickets starts as [].
  2. The agent's email. Show the assigned agent's email under their name on the ticket's page. Did you need to change anything in tickets.api.js? Why not? Which test should check it?

Build something

  1. A Try again button. When the list page fails, show a Try again button under the error. Clicking it sends the request again. (Hint: add a piece of state, attemptNumber, starting at 1. Put it in the effect's dependency array, and make the button add one to it. What else must the cleanup reset, as on the detail page?) Test it with getTickets.mockRejectedValueOnce(...) followed by getTickets.mockResolvedValue(...), and userEvent.click.
  2. The tab's title. On the ticket's page, set the browser tab's title to the ticket's subject, with a second useEffect that sets document.title. What should its dependency array be? What should its cleanup set the title back to? (Screen reader users hear the page's title first, so this helps them too.)

Investigate

  1. Someone else's ticket. Put Casey's token in .env (log in as casey@example.com). Which tickets does the list show? Now open the URL of a ticket Casey can't see. What status does the API send, and what does the page say? Why might the API prefer 404 to 403 here? (Lesson 4, "Hiding What You Can't See".) Put Ada's token back.
  2. Offline. In the Network tab, change the throttling to Offline, and reload the Tickets page. Which message appears? Can the front-end tell "you're offline" apart from "the API isn't running"? Why not?
  3. Fresh or cached? Tick Disable cache in the Network tab, open a ticket, and note its status. Untick it and reload. What changed, and did the page look any different?

Commit

git add .
git commit -m "Stage 2: try again, tab titles, ..."

When your own case study loads its list and detail pages from your API, with loading, error and empty states and a test for each, it's ready for Stage 3: creating, editing and deleting.
