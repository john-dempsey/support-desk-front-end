Tracing a Click

Questions to practise the viva's trace with: Stage 2 has every part of it, from the component to the API and back.

Stage 1's trace stopped at routes, components and props. Stage 2 adds the rest, so its trace is the full one the viva asks for: component → API module → HTTP request → state update → re-render. Topic 06's diagram has it step by step, for both a 200 and a 404.

Questions to practise with

Answer these out loud, with the code open. Then try them again with it closed.

  1. You click Tickets in the navigation. Name every file the request passes through on the way to the API, in order.
  2. What does TicketListPage show on its first render, before any answer has arrived? Which three values decide that?
  3. Why does tickets start as null, not []? What would the user see with []?
  4. Where does the Authorization header come from? Which function would you change to send a different token?
  5. The API answers 401. Which line throws, which catch catches it, and what does the user see?
  6. You open /tickets/abc. What status does the API send, and why does the page say "Ticket not found" and not "Validation failed"? Which file made that decision?
  7. What does [ticketId] at the end of the effect do? What goes wrong if it's [], and what tells you before you even run the app?
  8. In development, every ticket is requested twice. Why, and why doesn't the page show it twice?
  9. The cleanup function does two things. What are they, and when does React run it?
  10. Which files did Stage 2 not change, and why didn't they need to?

Try it

Pick one question you couldn't answer with the code closed. Find the answer in the code, then explain it to someone else without looking.
