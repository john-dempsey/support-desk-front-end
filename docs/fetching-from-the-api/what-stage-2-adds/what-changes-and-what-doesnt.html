What Changes, and What Doesn't

Only the pages and the API layer change. The components that display tickets don't, because they never knew where the tickets came from.

Here's the whole of Stage 1's list page:

// Figure 2.1: the Tickets page in Stage 1 (src/pages/TicketListPage.jsx,
// at stage-01)
import TicketList from '../components/TicketList.jsx';
import sampleTickets from '../data/sampleTickets.js';

function TicketListPage() {
  return (
    <>
      <h1>Tickets</h1>
      <TicketList tickets={sampleTickets} />
    </>
  );
}

export default TicketListPage;

The page owns the data, and TicketList displays whatever it's given as its tickets prop. That split, from Stage 1, is what makes Stage 2 small. The page has to get its tickets from somewhere new, but TicketList will still get an array of tickets in the same shape, so it doesn't need to change.

The files

File In Stage 2
src/data/sampleTickets.js deleted
src/api/tickets.api.js new: getTickets() and getTicket(id)
src/api/client.js getToken() changes. Nothing else does
.env.example gains VITE_DEV_TOKEN
src/pages/TicketListPage.jsx loads the tickets from the API
src/pages/TicketDetailPage.jsx loads one ticket from the API
src/components/TicketList.jsx only a comment changes
StatusBadge.jsx, formatDate.js unchanged
App.jsx, NavBar.jsx unchanged: no new pages, no new links

The tests change too. Topic 07 covers them.

Why the shape mattered

Stage 1's sample tickets used the API's own field names and shapes: subject, assignedAgent as an object or null, and dates as ISO strings. That was the reason. If the sample data had used title and a plain agent name, every component would have to change now. Because it didn't, the code that displays tickets is finished, and this stage is only about getting them.

It's the same in the back-end. When Lesson 2 swapped the array for Prisma, the controllers didn't change, because they only ever called the service.

Try it

Is TicketList.jsx in the list? See exactly what changed in it:
