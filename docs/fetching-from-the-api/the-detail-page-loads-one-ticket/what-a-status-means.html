What a Status Means

The page, not the API module, decides what each error means to the user: 404 and 400 mean 'no such ticket', and anything else is a real error.

Topic 03 left a question open: getTicket() lets every error through, with its status, so who decides what to show? The page does, in its catch:

// Figure 2.14: choosing what to show (src/pages/TicketDetailPage.jsx,
// excerpt)
      } catch (error) {
        if (ignore) {
          return;
        }
        // The page decides what each status means to the user. 404:
        // there's no ticket with that ID. 400: the API's validation
        // rejected the ID itself (e.g. /tickets/abc). Either way, there's
        // no such ticket. Anything else (the API is down, a 500, ...) is
        // a real error.
        if (error.status === 404 || error.status === 400) {
          setIsNotFound(true);
        } else {
          setErrorMessage(error.message);
        }
      }

(The comment is reflowed to fit.)

if (ignore) return; comes first, and covers both branches at once: an answer for a ticket the page has moved on from changes nothing.

Why 400 counts as "not found"

To the API, /tickets/abc and /tickets/999 are different mistakes. abc fails validation before any database query (400), and 999 passes validation but isn't in the table (404).

To someone who typed a URL, they're the same: there's no such ticket. "Validation failed" would be confusing on this page, because the user didn't fill in a form. So the page treats both the same way.

From Stage 1 to Stage 2

The page shows the same thing for the same URLs as in Stage 1. Only the way it finds out has changed:

URL Stage 1 found out with Stage 2 finds out from The page shows
/tickets/2 find() found it 200 ticket 2
/tickets/999 find() gave undefined 404 Ticket not found
/tickets/abc Number('abc') is NaN 400 Ticket not found
/tickets/2.0 Number('2.0') is 2 200 ticket 2

Every other error

Anything else, such as the API being down (status 0), an expired token (401) or a server crash (500), is a real problem, and the page shows the error's message, as the list page does.
