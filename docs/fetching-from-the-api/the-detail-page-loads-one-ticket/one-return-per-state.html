One Return per State

The detail page shows a whole different page for each state, so it uses early returns instead of &&.

The list page shows its states with &&, all inside one return (Figure 2.9). The detail page uses early returns, as Stage 1's "Ticket not found" did: one if and one return for each state, before the main one.

// Figure 2.15: the early returns (src/pages/TicketDetailPage.jsx, excerpt)
  if (isLoading) {
    return <Loading message="Loading the ticket…" />;
  }

  if (isNotFound) {
    return (
      <>
        <h1>Ticket not found</h1>
        <p>There's no ticket with the ID "{ticketId}".</p>
        <p>
          <Link to="/tickets">Back to all tickets</Link>
        </p>
      </>
    );
  }

  if (errorMessage) {
    return (
      <>
        <h1>Couldn't load the ticket</h1>
        <ErrorMessage message={errorMessage} />
        <p>
          <Link to="/tickets">Back to all tickets</Link>
        </p>
      </>
    );
  }

After these comes the return you know from Stage 1, which shows the ticket.

Why not &&?

On the list page, the heading "Tickets" is right in every state, and only the part under it changes. Here, each state is a different page: "Ticket not found" and "Couldn't load the ticket" need their own <h1>, and a page should have only one. With &&, you'd need a condition on the heading as well as on everything under it.

With early returns, each state is written out once, in full, and you can read each if on its own.

Getting past them means there's a ticket

The last return reads ticket.subject, ticket.customer.name and so on. If ticket were null, that would crash the page. It can't be: any time ticket is still null, the page is loading, the ticket wasn't found, or there was an error, and one of the returns above has already ended the function.

Only one of the three states is ever true at a time, so the order of the three ifs doesn't change anything. What matters is that all of them come before the last return.

Try it

Delete the if (isLoading) block (or comment it out) and open a ticket. What happens? Open the Console in the developer tools and read the error. Which line of the file does it point to, and why is ticket null there? Put the block back.
