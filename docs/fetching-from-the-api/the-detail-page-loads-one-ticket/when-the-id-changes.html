When the ID Changes

The effect lists ticketId as a dependency, so if the URL moves to another ticket while the page is showing, the page starts again and loads that ticket.

The list page's effect ended with []: run once, when the page first appears. The detail page's ends with [ticketId].

The array lists the values from the component that the effect uses. After every render, React compares each one with its value last time. If any of them changed, React runs the cleanup function, then the effect again.

  • [] lists nothing, so nothing can change: the effect runs once.
  • [ticketId] means: run again whenever the ticket ID changes.

When does that happen?

Going from the list to a ticket, the page appears for the first time, so the effect runs anyway. But React Router keeps the same TicketDetailPage on screen when the URL changes from /tickets/1 to /tickets/2, since both match /tickets/:ticketId. Only useParams() gives a new value. (Nothing in Stage 2 links one ticket to another yet. The "Try it" below adds a link that does, and a later stage will too.)

With [], the effect wouldn't run again. The URL would say ticket 2, and the page would still show ticket 1.

Starting again

Running the effect again isn't quite enough. The page's state still describes the old ticket: its details, or isNotFound if it didn't exist. Nothing in the effect sets isNotFound back to false, so after a ticket that wasn't found, every ticket would say "Ticket not found".

So the cleanup function, which React runs before the effect runs again, puts everything back to how it started:

// Figure 2.13: starting again (src/pages/TicketDetailPage.jsx, excerpt)
    return () => {
      ignore = true;
      setTicket(null);
      setErrorMessage('');
      setIsNotFound(false);
      setIsLoading(true);
    };
  }, [ticketId]);

(The file has a comment above the four set calls, left out here.)

The cleanup already meant "this ticket is finished with": ignore stops its late answer from being used. Now it also forgets everything it found out. The page shows "Loading the ticket…" again, and the effect asks for the new one.

The linter checks the array for you

Leaving a value out of the array is an easy mistake, and oxlint catches it. With [] instead of [ticketId], npm run lint says:

warning react-hooks(exhaustive-deps): React Hook useEffect has a
missing dependency: 'ticketId'

(The warning is on one line. It's split here to fit.) The rule is called exhaustive deps: list every dependency the effect uses.

Try it

Add a temporary link under the "Back to all tickets" link at the top of the ticket's page:

<Link to={`/tickets/${ticket.id + 1}`}>Next ticket</Link>

Open ticket 1 and click Next ticket until you reach a ticket that doesn't exist, then press the browser's Back button. Now comment out the four set lines in the cleanup and do it again. What goes wrong? Then put them back, change [ticketId] to [], and try once more. What does npm run lint say? Put [ticketId] back and remove the link.
