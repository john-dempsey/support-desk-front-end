The Detail Page Loads One Ticket

TicketDetailPage loads the ticket whose ID is in the URL, reloads when that ID changes, and decides what each error status means.

  • One Ticket, from the URL

    TicketDetailPage reads the ID from the URL as before, then asks the API for that ticket, using the same pattern as the list with one extra piece of state.

  • When the ID Changes

    The effect lists ticketId as a dependency, so if the URL moves to another ticket while the page is showing, the page starts again and loads that ticket.

  • What a Status Means

    The page, not the API module, decides what each error means to the user: 404 and 400 mean 'no such ticket', and anything else is a real error.

  • One Return per State

    The detail page shows a whole different page for each state, so it uses early returns instead of &&.
