When It Fails

Whatever goes wrong, the page shows the error's message and stops loading, and the list never appears.

TicketListPage doesn't try to tell one failure from another. Whether the API is down, the token has expired or the server crashed, the page does the same thing:

  1. getTickets() throws (it's apiRequest()'s error, passed through).
  2. catch stores the error's message with setErrorMessage.
  3. finally turns off loading with setIsLoading(false).
  4. tickets is still null, so TicketList doesn't appear.

So the page shows the heading and one message, in ErrorMessage's role="alert" paragraph, which a screen reader reads out as soon as it appears (Stage 0, topic 07).

What the user reads

The message comes from wherever the problem was found:

Problem Message Written by
The API isn't running Can't reach the API at http://localhost:3000 — is the back-end running? client.js
No token in .env Authentication required the API
A wrong or expired token Invalid or expired token the API

When the API answers, its own error.message is shown. When nothing answers, there's no API message to show, so client.js writes one itself (Stage 0, topic 05).

Is one message for everything enough?

For a list, yes. Every one of these failures means the same thing to the user: the tickets can't be shown right now. The message says why, and none of them can be fixed by clicking something on the page.

The detail page is different. There, one kind of failure, "there's no such ticket", is a normal answer that deserves its own message. That's the next topic.

Try it

In the back-end's folder, stop the API's container:

docker compose stop api

Reload the Tickets page. Which message appears? Which file wrote it? Start the API again with docker compose start api, and reload. Do you need to restart the front-end?
