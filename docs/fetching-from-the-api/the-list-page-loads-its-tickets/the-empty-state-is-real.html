The Empty State Is Real

Stage 1 wrote an empty state that could never show. With real data, a new customer sees it straight away.

TicketList has handled an empty list since Stage 1:

// Figure 2.10: the empty state (src/components/TicketList.jsx, excerpt)
function TicketList({ tickets }) {
  // The "empty" state: the API can send an empty list, e.g. for a
  // brand-new customer who hasn't reported anything yet.
  if (tickets.length === 0) {
    return <p>There are no tickets to show.</p>;
  }

In Stage 1, this could never happen: sampleTickets always had four tickets. Its comment said so. Stage 2 changed only that comment, because now it can happen.

Who sees an empty list?

The API decides which tickets each person sees (Lesson 4), so the same page shows different lists to different people:

Logged in as GET /tickets gives
Ada (admin) every ticket
Alex (agent) the tickets assigned to Alex, plus unassigned ones
Casey (customer) only Casey's own tickets
a customer who just registered []

The front-end doesn't filter anything. It shows what it's given. A list page with no empty state would show a bare heading to every new customer, who'd wonder whether the page was broken.

Why empty isn't an error

An empty list is a successful answer: 200, with data: [] and meta.total of 0. Nothing went wrong, so the page shouldn't say anything went wrong. It should say what's true: there's nothing here yet.

That's why the empty message lives in TicketList, next to the table, and not in the page's error handling.

Try it

Register a brand-new customer in your REST client:

POST http://localhost:3000/auth/register
Content-Type: application/json

{ "name": "Sam Newcomer", "email": "sam@example.com",
  "password": "password123" }

Put the token from the response in .env as VITE_DEV_TOKEN, save, and reload the Tickets page. What do you see? Then try Casey's token (log in as casey@example.com). Which tickets does Casey see? Put Ada's token back when you're done.

(Registering counts towards the 10-a-quarter-hour limit, like logging in. Seeding the database again removes Sam.)
