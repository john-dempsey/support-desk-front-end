When the Ticket Isn't There →

Just the Data, for Now

GET /tickets sends the tickets and a meta object. getTickets() returns only the tickets, because nothing uses meta yet.

Here's what GET /tickets sends back with Ada's token, shortened to one ticket with some of its fields left out:

{
  "data": [
    {
      "id": 2,
      "subject": "Invoice discrepancy",
      "status": "open",
      "customer": { "id": 2, "name": "Priya Patel", "email": "..." },
      "assignedAgent": null,
      "createdAt": "2026-10-14T17:08:18.447Z"
    }
  ],
  "meta": { "page": 1, "pageSize": 10, "total": 4, "totalPages": 1 }
}

That's the back-end's list envelope from utils/response.js: the records in data, and facts about the whole list in meta.

What getTickets() returns

apiRequest() returns the whole body. getTickets() returns only responseBody.data, the array. So the page gets exactly what Stage 1's sampleTickets was: an array of tickets, ready to pass to TicketList.

meta is thrown away for now. It says which page of results this is: the API sends at most 10 tickets at a time unless asked for more. With 4 seeded tickets, page 1 holds them all, so nothing is missing yet. Stage 3 adds filtering and paging, and that's when getTickets() will return meta as well.

Returning only what the pages use today keeps each stage small. When Stage 3 needs meta, it changes this one function and the page that calls it.

Fields nobody shows

The real tickets also have fields that Stage 1's samples left out: customerId, assignedAgentId and slaBreachedAt. They come with the response, and no component reads them, so they make no difference. TicketList reads ticket.subject, ticket.status and so on, and ignores everything else in the object.

Try it

In your REST client, send GET /tickets?pageSize=2 with Ada's token. How many tickets are in data? What does meta say now? The Tickets page would only show those 2 if it sent the same query. Which file would you change to make it do that?
