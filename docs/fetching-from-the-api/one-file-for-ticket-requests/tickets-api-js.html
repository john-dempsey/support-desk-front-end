tickets.api.js

One file holds every ticket request, with one function per endpoint, just like the starter's welcome.api.js.

Stage 1 deleted welcome.api.js, the starter's only API module. Stage 2 adds the first Support Desk one. Here it is, apart from its top comment:

// Figure 2.5: the ticket requests (src/api/tickets.api.js)
import { apiRequest } from './client.js';

// GET /tickets: returns the array of tickets.
// The API sends them 10 at a time, newest first, with a `meta` object
// ({ page, pageSize, total, totalPages }) alongside. Only the tickets are
// returned for now; Stage 3 uses `meta` for filtering and pagination.
export async function getTickets() {
  const responseBody = await apiRequest('/tickets');
  return responseBody.data;
}

// GET /tickets/:id: returns one ticket. If the ticket doesn't exist, the
// API answers 404 and apiRequest() throws an error with status 404, so the
// page can tell "not found" apart from "something went wrong".
export async function getTicket(ticketId) {
  const responseBody = await apiRequest(`/tickets/${ticketId}`);
  return responseBody.data;
}

Put it next to getWelcome() from Stage 0 (Figure 0.20), and the shape is the same: call apiRequest() with a path, wait for the response, and return what's inside data. All the hard work (the base URL, the token, JSON, errors) happens in client.js, once.

One function per endpoint

Each function is named for what it does, not for how: getTickets(), not fetchTicketsFromServer(). A page reads like a sentence:

const ticketsData = await getTickets();

The page never sees /tickets, a header or a status code. If the back-end renamed the route, this file would be the only front-end file to change.

getTicket(ticketId) builds its path with a template literal, so getTicket('2') asks for /tickets/2. The ID comes from the URL, so it's a string, and that's fine: a URL is text anyway.

The front-end's service layer

The top comment of the file makes the comparison: this is the front-end's ticket.service.js. In the back-end, a controller decided what to do and called a service, and only the service knew where tickets lived (an array, then Prisma). Here, a page decides what to show and calls tickets.api.js, and only tickets.api.js knows where tickets live (/tickets on the API).

Back-end Front-end
