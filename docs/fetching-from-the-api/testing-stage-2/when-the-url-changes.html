When the URL Changes

A test for topic 05's bug: a fake that answers differently for each ID, and a click that changes the URL while the page stays on screen.

Topic 05 showed why the cleanup resets the page's state: after a ticket that wasn't found, the next ticket must not say "Ticket not found". This test checks it, and it needs two things the other tests don't.

1. A fake that depends on what it's asked

mockResolvedValue gives the same answer to every call. Here the fake must answer 404 for one ID and a ticket for another, so the test gives it a whole function instead, with mockImplementation:

// Figure 2.22: a fake with a rule (src/pages/TicketDetailPage.test.jsx,
// excerpt)
    // Ticket 999 doesn't exist; ticket 2 does.
    getTicket.mockImplementation(async (ticketId) => {
      if (ticketId === '999') {
        throw createApiError(404, 'Ticket 999 not found');
      }
      return unassignedTicket;
    });

Every time the page calls getTicket(ticketId), this function runs instead. It's async, so throw and return work the same way as mockRejectedValue and mockResolvedValue.

2. A click

// Figure 2.23: changing the URL (src/pages/TicketDetailPage.test.jsx,
// excerpt)
    renderWithProviders(
      <>
        <Link to="/tickets/2">Go to ticket 2</Link>
        <TicketDetailPage />
      </>,
      { route: '/tickets/999', path: DETAIL_PATH },
    );
    await screen.findByRole('heading', {
      level: 1, name: 'Ticket not found',
    });

    await userEvent.click(
      screen.getByRole('link', { name: 'Go to ticket 2' }),
    );

    expect(
      await screen.findByRole('heading', {
        level: 1, name: 'Invoice discrepancy',
      }),
    ).toBeInTheDocument();

(The test's opening line is left out, and the long calls are reflowed to fit.)

  • The Link is rendered next to the page, inside the same route. So clicking it changes the URL, but the same TicketDetailPage stays on screen, which is exactly the case the cleanup is for.
  • userEvent.click() clicks the way a user does. It comes from @testing-library/user-event, which the starter installed. It's async, so it's awaited.
  • The first findByRole waits for "Ticket not found" before the click, so the test knows the page really was in that state.

A test that was written after a bug

This test was written when the bug was found, and it failed until the cleanup reset the state. That's a good habit: when you fix a bug, write a test that fails because of it first. Then you know the test can catch it, and it'll catch the bug if it ever comes back.
