Testing Stage 2

Tests for an API module, for pages whose data comes from a faked API, for a page whose URL changes, and for code that reads .env.

  • Test Data in One Place

    The page tests no longer use the app's sample data, so they get tickets of their own, in the API's shape, in one shared file.

  • Testing an API Module

    tickets.api.js is tested by faking the layer under it, client.js, and checking the URL it asks for and what it returns.

  • One Test per State

    The list page has four states, and the fake API can put it in each one: waiting, success, empty and failed.

  • Errors with a Status

    The detail page decides by error.status, so its tests throw errors that carry one, the same shape apiRequest() throws.

  • When the URL Changes

    A test for topic 05's bug: a fake that answers differently for each ID, and a click that changes the URL while the page stays on screen.

  • Tests That Read .env

    Vitest loads your .env, so a test about 'no token' has to set the token itself, and the config puts it back afterwards.

  • Running Everything

    Stage 2 ends with 37 passing tests in nine files, no lint warnings and a working build.
