Tests That Read .env

Vitest loads your .env, so a test about 'no token' has to set the token itself, and the config puts it back afterwards.

Stage 0's client.test.js had a test, "sends no Authorization header when there is no token". In Stage 0, getToken() always returned null, so it always passed.

In Stage 2, getToken() reads VITE_DEV_TOKEN. And Vitest loads .env the same way Vite does, so in a test, import.meta.env holds your token. The test would fail on any machine with a token in .env, and pass on any machine without one.

vi.stubEnv

So the test sets the value it needs:

// Figure 2.24: no token, whatever .env says (src/api/client.test.js,
// excerpt)
  it('sends no Authorization header when there is no token', async () => {
    // Vitest reads your .env too, so without this the test would see your
    // real VITE_DEV_TOKEN. stubEnv() replaces it for this test only.
    vi.stubEnv('VITE_DEV_TOKEN', '');
    const fakeFetch = fakeFetchResponding(200, { data: {} });

    await apiRequest('/welcome');

    const requestOptions = fakeFetch.mock.calls[0][1];
    expect(requestOptions.headers.Authorization).toBeUndefined();
  });

vi.stubEnv(name, value) replaces one import.meta.env value. It's the .env version of vi.stubGlobal(), which this file already uses to fake fetch.

A new test next to it does the opposite: vi.stubEnv('VITE_DEV_TOKEN', 'test-token'), then checks for the header Authorization: Bearer test-token.

Putting it back

vite.config.js has one new line in its test section:

// Figure 2.25: undoing stubEnv (vite.config.js, excerpt)
    unstubGlobals: true,
    unstubEnvs: true,
    mockReset: true,

unstubEnvs: true puts every stubbed value back after each test, the way unstubGlobals already undid vi.stubGlobal(). Without it, the empty token from one test would still be empty in the next.

A test should give the same answer everywhere

A test that passes on your laptop and fails on a classmate's is worse than no test, because nobody trusts it. Anything outside the code that can differ between machines, such as .env, the time, or a running API, should be set by the test itself.

Try it

Comment out the vi.stubEnv('VITE_DEV_TOKEN', '') line and run npm test. Does the test fail? Now empty VITE_DEV_TOKEN in your .env and run it again. Put both back.
