App.test.jsx

App.test.jsx renders the whole app at a URL. At /tickets and /tickets/1, that now means a page that calls the API, so the test file fakes tickets.api.js too, with the shared testTickets.

At /tickets, the test checks the heading "Tickets", which is there from the first render, so getByRole still works. At /tickets/1, the ticket's heading only appears once the (fake) request has finished, so that test changed from getByRole to await findByRole, which waits. The other three tests didn't change.

Run the checks

npm test
npm run lint
npm run build

A passing test run ends like this:

 Test Files  9 passed (9)
      Tests  37 passed (37)

npm run lint prints nothing at all when there's nothing to report, and npm run build should end with a built in line. If all three pass, Stage 2 is done.

None of these needed the API running. Try it: stop the API with docker compose stop api and run npm test again.

Commit

git add .
git commit -m "Stage 2: load tickets from the API"

Check that .env isn't in the list git status shows before you commit. It holds your token, and .gitignore should keep it out.

Run npm run test:watch, and in TicketDetailPage.jsx change "Ticket not found" to "No such ticket". Which tests fail? Now change the same words in the test file to match. Is that the right fix, or should the test have stopped you? Change both back, and press q to stop watching.
