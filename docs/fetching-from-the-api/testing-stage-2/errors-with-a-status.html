Errors with a Status

The detail page decides by error.status, so its tests throw errors that carry one, the same shape apiRequest() throws.

TicketDetailPage reads error.status to choose between "Ticket not found" and an error message (topic 05). A plain new Error(...) has no status, so the test file has a small helper that makes the same kind of error apiRequest() throws:

// Figure 2.19: a fake API error (src/pages/TicketDetailPage.test.jsx,
// excerpt)
// The same kind of error apiRequest() throws: a message plus the status.
function createApiError(status, message) {
  const error = new Error(message);
  error.status = status;
  return error;
}

Then each status gets its own test:

// Figure 2.20: one status, one test (src/pages/TicketDetailPage.test.jsx,
// excerpt)
  it('shows "Ticket not found" when the API answers 404', async () => {
    getTicket.mockRejectedValue(
      createApiError(404, 'Ticket 999 not found'),
    );

    renderPageAt('/tickets/999');

    expect(
      await screen.findByRole('heading', {
        level: 1, name: 'Ticket not found',
      }),
    ).toBeInTheDocument();
  });

(The mockRejectedValue and findByRole calls are reflowed to fit.) The 400 and "any other error" tests have the same shape, with createApiError(400, 'Validation failed') and createApiError(0, "Can't reach the API").

renderPageAt(url) is a one-line helper in the same file: it calls renderWithProviders with the URL and the route's path, as Stage 1's detail page tests did.

Which ID did the page ask for?

The first test in the file doesn't look at the screen at all:

// Figure 2.21: the ID from the URL (src/pages/TicketDetailPage.test.jsx,
// excerpt)
  it('asks the API for the ticket whose ID is in the URL', () => {
    getTicket.mockReturnValue(new Promise(() => {}));

    renderPageAt('/tickets/2');

    expect(getTicket).toHaveBeenCalledWith('2');
  });

It checks the link between useParams() and the request: open /tickets/2, and the page must ask for '2'. Note that it's the string '2', because that's what comes out of a URL.
