Delete, Then Go Back

If the user clicks OK, the page sends DELETE, then goes back to the list. If the API refuses, its message appears under the buttons.

Here's the whole of what happens after the user clicks Delete ticket:

And the rest of the function, after the confirmation:

// Figure 3.33: deleting (src/pages/TicketDetailPage.jsx, excerpt)
  setDeleteErrorMessage('');
  try {
    await deleteTicket(ticket.id);
    navigate('/tickets');
  } catch (error) {
    setDeleteErrorMessage(error.message);
  }
}

(The comments are left out.)

It's the same shape as handleCreate and handleSave: clear the old error, try the request, then either move on or keep the error.

  • It worked (204): deleteTicket() returns nothing (topic 02), and there's nothing on this page left to show. navigate('/tickets') goes to the list, which loads fresh from the API, so the ticket isn't in it.
  • It failed: the message goes into deleteErrorMessage, and ErrorMessage shows it under the buttons (Figure 3.31). The ticket is still there, so the page stays.

Just the message, this time

handleCreate kept the whole error, because a form needs its details (topic 04). Deleting has no form and no fields, so there are no details to show. A string is all the page needs, as in Stage 2.

What can go wrong

Status When Message
409 the ticket still has comments (ticket 1 has one) This record cannot be deleted or changed because other records still depend on it
403 the token isn't an agent's or admin's You do not have permission to perform this action
404 someone else deleted it first Ticket 5 not found

The 409 message is the API's own, and it's not very friendly. The page could check error.status and say "Delete this ticket's comments first" for a 409 instead. You'll see a page reword an API message like that later in this lesson.

Clearing it for the next ticket

deleteErrorMessage is reset in the page's effect cleanup, with the rest of the page's state (Stage 2, topic 05). So a "cannot be deleted" message about ticket 1 doesn't follow the user to ticket 2.
