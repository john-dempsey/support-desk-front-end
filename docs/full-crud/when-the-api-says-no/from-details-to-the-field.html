From details to the Field

getFieldError() looks through the error's details for one field's message. The form asks once for each of its fields.

Here's the whole path a validation message takes, from the back-end to the screen:

Steps 1 to 3 are already familiar. Step 4 is a small new function in src/utils/:

// Figure 3.17: one field's message (src/utils/getFieldError.js)
export function getFieldError(error, fieldName) {
  if (!error || !error.details) {
    return '';
  }

  const problem = error.details.find(
    (detail) => detail.field === fieldName,
  );
  if (!problem) {
    return '';
  }

  return problem.message;
}

(The comment at the top is left out, and the find() line is split here to fit.)

  • No error, or no details (a 403, say): there's nothing to find, so it returns ''.
  • find() goes through the list and returns the first item whose field matches, or undefined if none does. It's the same find() Stage 1 used to look up a ticket by its id.
  • Found it: return its message.

It always returns a string, so the form can use the answer without checking for null or undefined first.

The form asks for each field

// Figure 3.18: asking for each field (src/components/TicketForm.jsx,
// excerpt)
const subjectError = getFieldError(error, 'subject');
const descriptionError = getFieldError(error, 'description');

These run on every render. Most of the time error is null, and both are ''. After a 400, each holds its field's message, or '' if that field was fine.

The field names are the API's names ('subject', 'description'), because they come from the back-end's details. That's one more reason the front-end uses the same names as the API everywhere.

Why a separate function?

Three forms in this stage need it (tickets, comments and tags). Written once in utils/, it's tested once, and every form uses it the same way. It works for any API that uses this error shape, so it'll work unchanged in your own front-end.

Try it

With Casey's token, send POST /tickets in your REST client with the body { "subject": "", "description": " " }. How many items are in details? Then type a subject of only spaces and a description of only spaces in the form. Does each message appear under the right field?
