Testing Stage 3

Tests that type and click like a user, check what was sent to a faked API, follow navigate(), answer the confirmation box, and drive the list through its URL.

  • What Stage 3 Tests

    Stage 3's tests do what a user does, typing, choosing and clicking, against the real pages, with fakes for everything outside them.

  • Typing and Choosing

    userEvent types into inputs one key at a time and chooses from dropdowns, just as a user would, so every onChange runs.

  • Checking What Was Sent

    After the clicks, the test asks the fake API module what it was called with. That checks the whole journey from the inputs to the request.

  • Where Did It Go?

    To check navigate(), a test gives the router somewhere to go: a stand-in route with a plain heading. If the heading appears, the page went there.

  • Answering the Confirm Box

    A test can't click OK in a browser's confirmation box. vi.spyOn() replaces window.confirm with a fake that answers for it.

  • Errors, and Waiting

    The fake API can fail on purpose, with a status and details, so the tests can check each message lands in the right place. A promise that never answers holds the page mid-request.

  • One Answer, Then Another

    When a page calls the same API function twice, mockResolvedValueOnce() gives each call its own answer. beforeEach() gives every test a sensible default.

  • Testing Through the URL

    The list page's tests start it at a URL and check the query that reaches the API. After a click, they check the last call: the new query.

  • Running Everything

    Stage 3 ends with 87 passing tests in 17 files, no lint warnings and a working build.
