Checking What Was Sent

After the clicks, the test asks the fake API module what it was called with. That checks the whole journey from the inputs to the request.

When a page saves something, the important question is: did it send the right thing? The fake API module remembers every call, so the test can ask:

// Figure 3.59: what the edit page sent
// (src/pages/EditTicketPage.test.jsx, excerpt)
getTicket.mockResolvedValue(unassignedTicket);
getAgents.mockResolvedValue(testAgents);
updateTicket.mockResolvedValue(unassignedTicket);
renderEditPageFor(2);

await userEvent.selectOptions(
  await screen.findByLabelText('Status'), 'Resolved',
);
await userEvent.selectOptions(
  screen.getByLabelText('Assigned to'), 'Sam Support',
);
await userEvent.click(
  screen.getByRole('button', { name: 'Save changes' }),
);

expect(updateTicket).toHaveBeenCalledWith('2', {
  subject: 'Invoice discrepancy',
  description: 'Charged twice for March',
  status: 'resolved',
  assignedAgentId: 5,
});

(The userEvent calls are each one line in the file, split here to fit, and a comment is left out.)

toHaveBeenCalledWith passes only if updateTicket was called with exactly those arguments. One test covers a long chain: the ticket fills the form (topic 05, slide 03), the dropdowns change state, the form converts '5' to the number 5 (slide 05), and the page passes it all, with the id from the URL, to updateTicket(). A mistake anywhere in the chain fails it.

Look at assignedAgentId: 5. If the form forgot Number(), it would send '5', and this test would fail. That's the test pinning down topic 05's round trip.

Just one field: expect.objectContaining()

The next test only cares about one field, that "Unassigned" sends null:

expect(updateTicket).toHaveBeenCalledWith(
  '1',
  expect.objectContaining({ assignedAgentId: null }),
);

expect.objectContaining() passes if the object has at least those fields, whatever else it has. The test says what it's about, and isn't broken by changes to fields it doesn't care about.

In TicketForm.jsx, change Number(assignedAgentId) to just assignedAgentId. Run the tests. Which fail, and what does Vitest show as the difference? Put it back.
