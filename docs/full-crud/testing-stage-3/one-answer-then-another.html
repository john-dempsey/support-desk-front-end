One Answer, Then Another

When a page calls the same API function twice, mockResolvedValueOnce() gives each call its own answer. beforeEach() gives every test a sensible default.

Two calls, two answers

After adding a tag, TagsPage calls getTags() a second time (topic 08, slide 04). The first answer should be the list before, and the second the list with the new tag:

// Figure 3.63: an answer per call (src/pages/TagsPage.test.jsx,
// excerpt)
getTags.mockResolvedValueOnce(testTags);
getTags.mockResolvedValueOnce([
  ...testTags,
  { id: 3, name: 'urgent' },
]);
createTag.mockResolvedValue({ id: 3, name: 'urgent' });
await renderTagsPage();

await userEvent.type(screen.getByLabelText('New tag name'), 'urgent');
await userEvent.click(screen.getByRole('button', { name: 'Add tag' }));

expect(createTag).toHaveBeenCalledWith('urgent');
expect(await screen.findByText('urgent')).toBeInTheDocument();
expect(screen.getByLabelText('New tag name')).toHaveValue('');

(The comment is left out, and the second mockResolvedValueOnce is one line in the file, split here to fit.)

mockResolvedValueOnce answers one call, then it's used up. Two of them line up two answers, in order. If the page didn't ask again, "urgent" would never appear, and the test would fail: so this test proves the page reloads after adding.

The last line checks the other half of topic 08: the input is empty, because onSubmit returned true.

A default for every test

On the ticket's page, every test needs getComments() to answer something, but most don't care what. So the file sets a default:

// Figure 3.64: a default answer
// (src/pages/TicketDetailPage.test.jsx, excerpt)
beforeEach(() => {
  getComments.mockResolvedValue([]);
});

beforeEach runs before every test in the describe block. The tests about comments set their own answer afterwards, which replaces this one for that test. mockReset (Stage 0, topic 08) wipes it after each test, and beforeEach sets it again for the next.
