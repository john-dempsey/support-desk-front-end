Answering the Confirm Box

A test can't click OK in a browser's confirmation box. vi.spyOn() replaces window.confirm with a fake that answers for it.

Every delete starts with window.confirm() (topic 06). In a test, there's no box for anyone to click: jsdom, the pretend browser, doesn't show one, and complains that it isn't implemented. So the tests replace it:

// Figure 3.61: answering for the user
// (src/pages/TicketDetailPage.test.jsx, excerpt)
function answerConfirmWith(answer) {
  vi.spyOn(window, 'confirm').mockReturnValue(answer);
}

(The comment above it is left out.)

vi.spyOn(object, 'name') replaces one function on an existing object with a fake, here window.confirm. .mockReturnValue(true) makes it answer OK; false makes it answer Cancel. It's like vi.mock(), but for one function on something that already exists, rather than a whole module of yours.

OK, and Cancel

it('does nothing when the user cancels', async () => {
  answerConfirmWith(false);
  await renderDeletableTicket();

  await userEvent.click(
    screen.getByRole('button', { name: 'Delete ticket' }),
  );

  expect(deleteTicket).not.toHaveBeenCalled();
});

The Cancel test is as important as the OK test. It proves that the early return (topic 06, slide 02) works: no request is sent at all.

Putting it back

The fake must not leak into the next test, or a later test might get an answer it didn't ask for. vite.config.js sets mockReset: true, which puts every vi.spyOn() back to the real function after each test (Stage 0, topic 08). So no test needs to tidy up after itself.
