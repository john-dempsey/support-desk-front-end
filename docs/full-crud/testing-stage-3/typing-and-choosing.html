Typing and Choosing

userEvent types into inputs one key at a time and chooses from dropdowns, just as a user would, so every onChange runs.

Stage 2 used userEvent.click() to follow a link. Stage 3's tests type and choose too:

// Figure 3.58: filling in the form like a user
// (src/pages/NewTicketPage.test.jsx, excerpt)
async function fillInAndSubmit(subject, description) {
  await userEvent.type(screen.getByLabelText('Subject'), subject);
  await userEvent.type(
    screen.getByLabelText('Description'),
    description,
  );
  await userEvent.click(
    screen.getByRole('button', { name: 'Create ticket' }),
  );
}

(The comment is left out, and the last two calls are each one line in the file, split here to fit.)

userEvent.type()

userEvent.type(input, 'Printer') presses P, r, i, ... one key at a time. Each key fires the same events a real keyboard would, so the input's onChange runs seven times, and TicketForm's setSubject() with it. The test exercises the controlled input exactly as a user does (topic 03, slide 02).

It finds the input by its label, getByLabelText('Subject'). If the <label> and htmlFor didn't match, the test couldn't find the input, and neither could a screen reader. So the test checks the accessibility too, for free.

userEvent.selectOptions() and clear()

await userEvent.selectOptions(
  screen.getByLabelText('Status'), 'Resolved',
);

chooses the option whose text is "Resolved", the way a user picks it, and onChange gets its value, 'resolved'.

userEvent.clear(input) empties an input first. The rename test uses it, because the rename input starts with the tag's name in it.

Always await

Every userEvent call is async: it waits for React to finish updating after each event. Forget the await, and the test checks the screen before the typing has happened.

A helper for repeated steps

Four of NewTicketPage's tests fill in the form the same way, so the steps are in fillInAndSubmit(). Each test reads as what's different about it: what the fake API answers, and what should happen.

Try it

In NewTicketPage.test.jsx, remove the await before the userEvent.type() for the subject. Run the tests. Which fail, and what do they say? Put it back.
