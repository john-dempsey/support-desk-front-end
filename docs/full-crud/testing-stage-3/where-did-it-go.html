Where Did It Go?

To check navigate(), a test gives the router somewhere to go: a stand-in route with a plain heading. If the heading appears, the page went there.

After creating a ticket, NewTicketPage calls navigate('/tickets/9'). How can a test see that?

The test's router is a MemoryRouter, with no address bar to look at. But if there's a route for /tickets/:ticketId, React Router will show it when the page navigates there. The test doesn't need the real TicketDetailPage (which would need its own fakes); a plain heading will do:

// Figure 3.60: somewhere to land
// (src/pages/NewTicketPage.test.jsx, excerpt)
function renderNewTicketPage() {
  renderWithProviders(
    <Routes>
      <Route path="/tickets/new" element={<NewTicketPage />} />
      <Route
        path="/tickets/:ticketId"
        element={<h1>Ticket page</h1>}
      />
    </Routes>,
    { route: '/tickets/new' },
  );
}

(The second <Route> is one line in the file, split here to fit.)

The test starts at /tickets/new, fills in the form, and then:

expect(
  await screen.findByRole('heading', { level: 1, name: 'Ticket page' }),
).toBeInTheDocument();

If "Ticket page" appears, the page navigated to some /tickets/:ticketId. findByRole waits, because the navigation only happens once the (fake) request has answered.

The same trick, three times

Test Starts at Stand-in route Checks that
NewTicketPage /tickets/new /tickets/:ticketId creating goes to the ticket
EditTicketPage /tickets/2/edit /tickets/:ticketId saving goes back to the ticket
TicketDetailPage /tickets/1 /tickets deleting goes to the list

It's renderWithProviders() from Stage 1, given a whole <Routes> instead of one page. Stage 2's "URL changes" test used it the same way.

Try it

The stand-in only proves the page went to a ticket. Make the test stricter: change the stand-in's element to <TicketIdShown />, a small component you write in the test file that uses useParams() and shows Ticket {ticketId}. Then check that "Ticket 9" appears, matching the id the fake createTicket returns.
