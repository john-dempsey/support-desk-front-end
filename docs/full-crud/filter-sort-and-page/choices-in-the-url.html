Choices in the URL

The list's filter, sort order and page number are kept in the URL, not in useState, so a refresh, the Back button and a shared link all keep them.

The Tickets page now has three dropdowns above the list, Status, Sort by and Order, and Previous and Next buttons below it when there's more than one page.

The API has done the hard part since Lesson 3: GET /tickets already takes status, sortBy, order, page and pageSize as query parameters. The front-end only has to send the user's choices.

Where to keep the choices?

Each choice could be a piece of state:

const [status, setStatus] = useState('');

That would work, until the user:

  • refreshes the page: state starts again from scratch, so the filter is gone
  • clicks a ticket and presses Back: the list page appears again, with new state, so the filter is gone
  • copies the link to send to a colleague: the link is just /tickets, so the filter is gone

So the choices go in the URL instead, as a query string:

/tickets?status=open&sortBy=subject&order=asc&page=2

The URL survives all three. It's also how Laravel's pagination worked: $tickets->links() made links like ?page=2, and a GET search form put its fields in the query string.

The API's names

The URL uses exactly the API's names for its parameters. That's the trick that keeps this simple: the page can pass its own query string straight to the API, without translating anything (slide 03).
