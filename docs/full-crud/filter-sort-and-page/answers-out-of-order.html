Answers Out of Order

With filters, a slow answer to an old question can arrive after the answer to a new one. The ignore flag from Stage 0 stops it from replacing the right tickets.

Since Stage 0, every effect that loads data has had an ignore flag (Stage 0, topic 06), so a response that arrives too late is ignored. Until now, it was hard to see that matter: each page asked one question, when it appeared.

The ticket list asks a new question every time a dropdown changes. Requests don't always come back in the order they were sent. A request can be held up by the network, or the database might take longer for one query than another:

How the flag works here

Each time the effect runs, it makes its own ignore, set to false. When queryString changes, React runs the cleanup of the old effect before starting the new one:

// Figure 3.57: the cleanup (src/pages/TicketListPage.jsx, excerpt)
return () => {
  ignore = true;
  setTickets(null);
  setMeta(null);
  setErrorMessage('');
  setIsLoading(true);
};

(The comment is left out.)

  • ignore = true marks the old request's answer as out of date. When it arrives, every if (!ignore) in that old loadTickets is false, so it changes nothing.
  • The other four lines put the page back to loading, as the ticket's page did when its id changed (Stage 2, topic 05). So the old tickets and any old error disappear while the new ones are on their way.

Only the newest request can ever change the page, so what's shown always matches the dropdowns.

Try it

In loadTickets, just after the line with await getTickets(...), add:

if (ignore) {
  console.log('ignored an old answer for', queryString);
}

Set the Network tab to Slow 4G, and change the Status dropdown three times, quickly. Read the console: which answers were ignored? You'll also see one when the page first loads: that's StrictMode running the effect twice (Stage 0, topic 06). Remove the lines, and set throttling back.
