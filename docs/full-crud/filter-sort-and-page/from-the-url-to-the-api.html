From the URL to the API

The page turns its query string into a plain string, and the effect sends it to the API whenever it changes. getTickets() now returns meta as well.

The page's query string goes to the API unchanged. First, the page turns it into text:

// Figure 3.53: the query, as text (src/pages/TicketListPage.jsx,
// excerpt)
const queryString = searchParams.toString();

useEffect(() => {
  // ... the ignore flag, as before
  async function loadTickets() {
    try {
      const result = await getTickets(queryString);
      if (!ignore) {
        setTickets(result.tickets);
        setMeta(result.meta);
      }
    } // ... catch and finally, as before
  }
  // ...
}, [queryString]);

searchParams.toString() gives the query string without the ?: 'status=open&page=2', or '' on plain /tickets.

Why a string in the dependency array?

The effect must run again whenever the query changes. React decides by comparing each dependency with its value last time. Two strings with the same letters are equal, so queryString changes only when the query really does. searchParams is an object, and two objects are only equal if they're the very same object (topic 07, slide 06), so it's safer not to depend on it.

getTickets() grows up

In Stage 2, getTickets() took nothing and returned only the tickets, and its comment promised that Stage 3 would use meta. Here it is:

// Figure 3.54: getTickets(), now (src/api/tickets.api.js, excerpt)
export async function getTickets(queryString = '') {
  let path = '/tickets';
  if (queryString) {
    path = `/tickets?${queryString}`;
  }

  const responseBody = await apiRequest(path);
  return { tickets: responseBody.data, meta: responseBody.meta };
}

(The comment above it is left out.)

  • With no query, it asks for /tickets, as before. = '' makes the argument optional.
  • It returns an object with both parts of the response: the tickets, and meta ({ page, pageSize, total, totalPages }), which the page needs for its Previous and Next buttons (slide 05).

The whole loop

Steps 1 to 4 run when the page first appears, and again every time the URL changes. Steps 5 and 6 are the next slide.
