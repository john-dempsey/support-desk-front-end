Filter, Sort and Page

The ticket list gets a status filter, a sort order and Previous/Next buttons. The choices live in the URL, and go straight to the API.

  • Choices in the URL

    The list's filter, sort order and page number are kept in the URL, not in useState, so a refresh, the Back button and a shared link all keep them.

  • Reading the URL

    useSearchParams() gives the page the URL's query string. The dropdowns show what's in it, with the API's defaults when something is missing.

  • From the URL to the API

    The page turns its query string into a plain string, and the effect sends it to the API whenever it changes. getTickets() now returns meta as well.

  • Changing the URL

    Choosing a filter or a page makes a new copy of the query, changes it, and hands it to setSearchParams(). The URL changes, and the effect does the rest.

  • Pages of Tickets

    Pagination shows Previous and Next, and which page this is, from the API's meta. With only 4 seeded tickets, ?pageSize=2 is the way to see it.

  • Answers Out of Order

    With filters, a slow answer to an old question can arrive after the answer to a new one. The ignore flag from Stage 0 stops it from replacing the right tickets.
