DELETE, and the Empty Answer

A successful DELETE answers 204 No Content. deleteTicket() has nothing to return, but it can still fail.

// Figure 3.5: deleting a ticket (src/api/tickets.api.js, excerpt)
// DELETE /tickets/:id: the API answers 204 No Content, so there's
// nothing to return. A 409 means the ticket still has comments.
export async function deleteTicket(ticketId) {
  await apiRequest(`/tickets/${ticketId}`, { method: 'DELETE' });
}

A method, but no body: the URL already says everything.

Nothing to return

When the delete works, the back-end answers 204 No Content, with no body at all. Stage 0's apiRequest() checks for that first and returns null (Figure 0.16), so it never tries to read JSON that isn't there.

There's no responseBody.data to return, so deleteTicket() returns nothing. The function has no return line at all. A page that calls it only needs to know one thing: did it work?

It can still fail

await still matters. It waits for the answer, and if the answer is an error, apiRequest() throws and deleteTicket() throws the same error, as getTicket() did with a 404 (Stage 2, topic 03).

The one to expect here is 409 Conflict. In the database, each comment points at its ticket, so the back-end won't delete a ticket that still has comments (Lesson 3 met this as a foreign key error). In the seeded data, ticket 1 has a comment:

Request Status
DELETE /tickets/1 409: "This record cannot be deleted or changed because other records still depend on it"
DELETE /tickets/999 404: "Ticket 999 not found"

Topic 06 shows how the page shows these to the user.

Summary: three ways to send data

Function Sends Success Returns
createTicket(newTicket) POST /tickets with a body 201, the new ticket the ticket, with its id
updateTicket(id, changes) PATCH /tickets/:id with a body 200, the ticket now the ticket
deleteTicket(id) DELETE /tickets/:id, no body 204, no body nothing

Every error, for all three, arrives the same way: thrown by apiRequest(), with status, message and, for a 400, details.
