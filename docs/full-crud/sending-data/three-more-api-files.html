Three More API Files

Comments, tags and agents each get their own file in src/api/, with the same shape as tickets.api.js. Each one is shown in the topic that uses it.

tickets.api.js is no longer the only API module. Stage 3 adds three more, one per resource, just as the back-end has one service per resource:

File Functions Back-end routes Shown in
users.api.js getAgents() GET /users?role=agent topic 05
comments.api.js getComments(), createComment(), deleteComment() /tickets/:ticketId/comments topic 07
tags.api.js getTags(), createTag(), updateTag(), deleteTag() /tags topic 08

Each function has the same three steps as Figures 3.3 to 3.5. Here's the shortest one, which fills the "Assigned to" dropdown on the edit page:

// Figure 3.6: the list of agents (src/api/users.api.js, excerpt)
export async function getAgents() {
  const responseBody = await apiRequest('/users?role=agent');
  return responseBody.data;
}

The query string is part of the path. The page that calls getAgents() doesn't need to know the API filters users by role. It just asks for agents.

Why /users exists

The back-end got GET /users in Lesson 7, "Preparing the API for a Client". Without it, the edit page would have no way to find out which agents there are, so an admin could never choose who to assign a ticket to. The front-end needed it, so the back-end added it: the two halves are designed together.

Why one file per resource

The pages read better for it:

import { getComments, createComment } from '../api/comments.api.js';

says exactly where comments come from. And each file is small enough to read in one go. One long api.js with every function would work, but it would be the front-end's version of a single back-end file holding every route.

Try it

Before you look at it, write comments.api.js's getComments(ticketId) yourself from the table above. (Stage 2's first slide on tickets.api.js asked you to try this, as getTicketComments().) Then compare it with the real file. What does createComment(ticketId, commentText) have to send as its body? Check the back-end's createCommentSchema.
