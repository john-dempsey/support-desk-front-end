Full CRUD

The app stops only reading tickets and starts changing them: create, edit and delete tickets, add and delete comments, manage tags, and filter, sort and page the list.

  • What Stage 3 Adds

    Three new pages, a link in the navigation, and a map of how they fit together, before any of the code.

  • Sending Data, Not Just Asking for It

    POST, PATCH and DELETE through the same apiRequest(): what each sends, and what each gives back.

  • Creating a Ticket

    The first form: controlled inputs, a page that sends the request, a function passed down as a prop, and navigate() to the new ticket.

  • When the API Says No

    The browser checks the basics, but the API has the final say. Its validation details are shown under the field they belong to.

  • Editing a Ticket

    The same TicketForm, filled in with a ticket's values, plus a status and an agent to choose. Two requests at once, and converting between strings and numbers.

  • Deleting a Ticket

    A button, a confirmation, a DELETE request, and back to the list, or a message if the API refuses.

  • Comments

    A list and a form on the ticket's page, connected through the page. Adding and deleting update the list the page already has, with a new array each time.

  • Tags: CRUD on One Page

    List, add, rename and delete tags, all on one page. A recap of the lesson so far, plus renaming in place, asking again for a sorted list, and rewording an unhelpful error.

  • Filter, Sort and Page

    The ticket list gets a status filter, a sort order and Previous/Next buttons. The choices live in the URL, and go straight to the API.

  • Testing Stage 3

    Tests that type and click like a user, check what was sent to a faked API, follow navigate(), answer the confirmation box, and drive the list through its URL.

  • Making It Yours

    Tracing clicks through Stage 3, then creating, editing and deleting your own case study's data from your front-end.
