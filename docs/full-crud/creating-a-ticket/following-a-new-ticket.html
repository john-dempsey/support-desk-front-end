Following a New Ticket

Every step from typing in the form to seeing the new ticket, through each file, across to the API and back, including the way back when the API says no.

Stage 2 traced a request that reads a ticket (Stage 2, topic 06). Here's one that creates a ticket. The bottom half has the same shape: the API answers, and there are two ways back.

What's new compared with reading

  • It starts with the user, not the page. In Stage 2, useEffect sent the request as soon as the page appeared. Here, nothing is sent until the user clicks.
  • Two components take part. Steps 1 and 2 are in the form, step 3 is in the page, and the call from one to the other is the onSubmit prop (slide 03).
  • The request carries data. Step 5 sends a body, and step 6 validates it.
  • Success means going somewhere else. The page doesn't show the ticket itself; it navigates, and the ticket's page loads it, exactly as in Stage 2.

In the back-end

Step 6 runs the middleware in ticket.routes.js in order: authenticate, then authorize('customer'), then validate({ body: createTicketSchema }), then the controller. The order decides which error you see first: with Ada's token, authorize rejects the request (403) before validate ever looks at the body. Topic 04 comes back to this.

Be ready to trace it

In the viva, you may be asked to trace a click like this one through your own code, without notes. Practise on this one: point at each line of code that runs, in order, and say which file it's in.

Try it

Put a console.log at the start of handleSubmit in TicketForm, at the start of handleCreate in NewTicketPage, and at the start of createTicket in tickets.api.js. Create a ticket and read the console. Is the order what the diagram says? Remove the console.logs.
