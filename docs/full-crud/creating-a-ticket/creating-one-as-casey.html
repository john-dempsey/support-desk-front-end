Creating One as Casey

Only customers can create tickets, so with Ada's token the form shows a 403. Switch to Casey's token to create one, then switch back.

Fill in the form with Ada's token in .env, and click Create ticket. The form shows:

You do not have permission to perform this action

That's the API's authorize('customer') (topic 01): admins can do almost everything, but they can't report a problem. The front-end shows the API's message, which is the right thing to do. Stage 4 will hide the New ticket link from anyone who isn't a customer.

Switching to Casey

To create a ticket now, use a customer's token for a while:

  1. In your REST client, send POST http://localhost:3000/auth/login with { "email": "casey@example.com", "password": "password123" }.
  2. Copy the token into .env as VITE_DEV_TOKEN, in place of Ada's. Keep Ada's somewhere (a comment line in .env, starting with #, is fine), because you'll want it back.
  3. Save .env. Vite restarts itself; reload the page.
  4. Create a ticket. You land on its page.

The API allows only 10 logins every 15 minutes. If you get 429 Too many requests, wait a few minutes, and keep both tokens in .env so you don't have to log in again.

Seeing the app as Casey

While Casey's token is in .env, look around:

  • The Tickets page shows only Casey's tickets, including the new one. The API scopes the list by who's asking (Lesson 4).
  • Edit ticket and Delete ticket are still there, because Stage 3 shows every control. Try them. The edit page can't even load: it asks for the list of agents, and GET /users is for agents and admins only, so it gets a 403. Delete gets a 403 too, because customers can't delete tickets.

That's what Stage 4 fixes: the front-end will know who's logged in, and won't offer Casey buttons that can only fail.

Switching back

Put Ada's token back in .env when you've finished creating tickets. The rest of this lesson uses it.

Try it

As Casey, create two tickets. Switch back to Ada. Are Casey's new tickets in Ada's list? Who is each one's customer, and who is it assigned to? Where did the front-end send the customer's name? (It didn't. Where did it come from?)
