A Function as a Prop

Props can be functions. The page passes handleCreate down as onSubmit, and the form calls it when the user clicks Create ticket.

Every prop so far has been data: a ticket, a list of tickets, a status, a message. Look at this one in Figure 3.7:

onSubmit={handleCreate}

handleCreate is a function, declared inside NewTicketPage. No brackets after it, so it isn't called here: the function itself is handed to TicketForm, as its onSubmit prop.

Later, when the user submits the form, TicketForm calls it:

// Figure 3.9: calling the page's function (src/components/TicketForm.jsx,
// excerpt)
function TicketForm({
  initialValues = EMPTY_TICKET,
  agents,
  submitLabel,
  onSubmit,
  error,
}) {
  // ...
  await onSubmit(values);

(The function's first line is one line in the file, split here to fit.)

Inside TicketForm, onSubmit(values) runs handleCreate(values), back in the page. The form doesn't know or care what the function does.

Data down, calls up

A component can't change its parent's state directly. saveError belongs to NewTicketPage, and only setSaveError() can change it, which only the page can reach. So the two directions work differently:

  • down: the page passes data to the form as props (submitLabel, error)
  • up: the form calls a function the page gave it (onSubmit), and the page's function changes the page's state

You met the same idea on the previous slide: onChange={...} hands the input a function, and the input calls it when something happens. onSubmit is a name chosen to match: "call this when the form is submitted".

Why not call createTicket() in the form?

The form could import createTicket() and call it itself. But then:

  • the edit page couldn't reuse it, because it needs updateTicket()
  • a component would be calling the API, which is the pages' job

By passing a function in, the form stays the same for both pages, and each page decides what submitting means.

Try it

  1. In NewTicketPage.jsx, rename the prop: onSave={handleCreate} instead of onSubmit={handleCreate}. Save, fill in the form and click Create ticket. What does the console say, and what does the button show? Which line of TicketForm failed, and why? Put it back.
  2. Don't try this one, think it through: what would onSubmit={handleCreate()}, with brackets, do? When would handleCreate run, how often, and what would it pass to the form?
