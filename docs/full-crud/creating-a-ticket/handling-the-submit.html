Handling the Submit

handleSubmit stops the browser's own form handling, gathers the values from state, and disables the button until the page has finished.

When the user clicks Create ticket (or presses Enter in the subject), the browser fires the form's submit event, and React runs handleSubmit:

// Figure 3.10: submitting the form (src/components/TicketForm.jsx,
// excerpt)
async function handleSubmit(event) {
  event.preventDefault();

  let values = { subject, description };
  if (agents) {
    // ... the edit page's extra fields: topic 05
  }

  setIsSubmitting(true);
  await onSubmit(values);
  setIsSubmitting(false);
}

// ...
<form className="form" onSubmit={handleSubmit}>

(The comments are left out.)

preventDefault(): no reload

Left to itself, a browser sends a form: it posts the inputs to the form's action URL and loads whatever page comes back. That's how every Blade form you've written worked, and Laravel answered with a redirect().

Here, that would reload the whole app and throw away its state. event.preventDefault() tells the browser not to do its default thing. From then on, it's up to the code: the values are already in state, and the page will send them with fetch().

The values come from state

{ subject, description } builds the object to send, straight from the two pieces of state. Nothing is read from the inputs, because the inputs only ever show what's in state (slide 02).

({ subject, description } is short for { subject: subject, description: description }.)

isSubmitting: one click, one ticket

A request takes time. If the user clicks Create ticket twice while it's on its way, two tickets would be created. So the form waits, and shows that it's waiting:

// Figure 3.11: the button (src/components/TicketForm.jsx, excerpt)
<button type="submit" disabled={isSubmitting}>
  {isSubmitting ? 'Saving…' : submitLabel}
</button>
  1. setIsSubmitting(true): the button is disabled (it can't be clicked) and says Saving….
  2. await onSubmit(values) waits until the page's handleCreate has finished, whether it worked or not.
  3. setIsSubmitting(false): the button is back.

If the ticket was created, the page has already moved on to the new ticket by step 3, and TicketForm is no longer on screen. React simply ignores state changes for a component that has gone, so step 3 does no harm.
