The page itself has no inputs. They're all in TicketForm, a new component in src/components/.

Two jobs, two components

Filling in a form and sending it are two different jobs:

  • The form owns the typing. What's in each input, and whether it's waiting for an answer. Nothing else needs to know those while the user types.
  • The page owns the request. It calls the API, decides what happens next, and keeps the API's error if there is one.

It's the Stage 1 rule again, pages own the data, components display it, with one addition: a form component keeps the values the user is typing, because only it uses them until the form is sent.

Why split it?

Because a second page needs the same form. Editing a ticket (topic 05) shows the same subject and description inputs, filled in, and sends a PATCH instead of a POST. With the inputs in TicketForm, both pages use one form, and each page decides what "save" means. The submitLabel prop lets each page choose the button's text.
