Going to the New Ticket

handleCreate sends the ticket, then uses navigate() to go to its page, the front-end's version of a redirect. If it fails, it keeps the error.

This is the function the form calls:

// Figure 3.12: sending the new ticket (src/pages/NewTicketPage.jsx,
// excerpt)
const navigate = useNavigate();
const [saveError, setSaveError] = useState(null);

async function handleCreate(newTicket) {
  setSaveError(null);
  try {
    const savedTicket = await createTicket(newTicket);
    navigate(`/tickets/${savedTicket.id}`);
  } catch (error) {
    setSaveError(error);
  }
}

(The comments are left out.)

Step by step:

  1. setSaveError(null) clears the error from any earlier attempt, so an old message doesn't stay on screen.
  2. createTicket(newTicket) sends POST /tickets (topic 02) and waits for the saved ticket.
  3. If that worked, navigate(...) goes to the new ticket's page.
  4. If it threw, setSaveError(error) keeps the error, the page re-renders, and the form gets it as its error prop. Topic 04 shows what the form does with it.

The try/catch is the same shape as the pages' useEffects in Stage 2, without the ignore flag. That flag guarded against a response arriving after the user had moved on; here, the user is the one waiting for the answer.

useNavigate()

So far, only the user has changed the URL, by clicking a <Link>. useNavigate(), from React Router, gives the page a function that changes it from code:

navigate('/tickets/5');

It's the same as clicking a link to /tickets/5: no reload, and React Router shows TicketDetailPage, which loads ticket 5 from the API.

It's the front-end's version of what a Laravel controller does after saving: return redirect()->route('tickets.show', $ticket). The one thing it needs is the new ticket's id, which the API sent back (topic 02).

Why the page, not the form?

Where to go after saving is the page's decision. After creating, it makes sense to see the new ticket. Another page using the same form might go somewhere else, or nowhere. So navigate() is in NewTicketPage, and TicketForm doesn't know it happens.
