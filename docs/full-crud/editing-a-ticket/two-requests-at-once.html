Two Requests at Once

The edit page needs the ticket and the agents. Promise.all() sends both requests together and waits for both, so the page waits only as long as the slower one.

Before it can show the form, the edit page needs two things from the API: the ticket, and the list of agents. Neither depends on the other. So it asks for both at the same time:

// Figure 3.23: loading two things at once
// (src/pages/EditTicketPage.jsx, excerpt)
useEffect(() => {
  let ignore = false;

  async function loadTicketAndAgents() {
    try {
      const [ticketData, agentsData] = await Promise.all([
        getTicket(ticketId),
        getAgents(),
      ]);
      if (!ignore) {
        setTicket(ticketData);
        setAgents(agentsData);
      }
    } catch (error) {
      // ... setLoadErrorMessage, as in Stage 2
    } finally {
      // ... setIsLoading(false)
    }
  }
  // ...
}, [ticketId]);

Everything apart from the Promise.all() line is Stage 2's pattern: the ignore flag, try/catch/finally, and ticketId in the dependency array.

Promise.all()

getTicket(ticketId) and getAgents() each return a promise, as soon as they've sent their request. Neither is awaited on its own. Instead, both promises go into an array, and Promise.all() makes one promise from them that:

  • succeeds when both have succeeded, with an array of their results, in the same order as the promises went in
  • fails as soon as either fails, with that one's error

const [ticketData, agentsData] = ... takes the array apart: the first result is the ticket, the second is the agents. The back-end does the same in ticket.service.js, where getAllTickets gets a page of tickets and their count with const [tickets, total] = await Promise.all([...]).

Why not one after the other?

This would work too:

const ticketData = await getTicket(ticketId);
const agentsData = await getAgents();

But the second request wouldn't start until the first had finished:

With Promise.all(), the page waits only as long as the slower of the two. The two requests are independent, so there's no reason to wait for one before sending the other.

If one fails

If either request fails, Promise.all() fails, and the catch shows the error. That's right here: without the ticket there's nothing to edit, and without the agents the form would be missing a field.
