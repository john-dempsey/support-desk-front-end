Editing a Ticket

The same TicketForm, filled in with a ticket's values, plus a status and an agent to choose. Two requests at once, and converting between strings and numbers.

  • The Edit Page

    EditTicketPage loads a ticket, shows it in the same TicketForm as the new ticket page, and saves the changes with PATCH.

  • Two Requests at Once

    The edit page needs the ticket and the agents. Promise.all() sends both requests together and waits for both, so the page waits only as long as the slower one.

  • Starting With the Ticket's Values

    The page turns the ticket into the form's initialValues. The form reads them only once, which is why it isn't shown until the ticket has loaded.

  • The Status and Agent Dropdowns

    When TicketForm is given agents, it shows two more fields: a status dropdown built from a list, and an agent dropdown built from the API's agents.

  • Strings and Numbers

    A dropdown's value is always a string. The agent's id goes from a number to a string for the form, and back to a number (or null) for the API.

  • One List of Statuses

    The status words used to live in StatusBadge. Now three files need them, so they move to their own file in utils/.

  • Saving, and Going Back

    handleSave sends PATCH, then returns to the ticket's page, which loads the ticket fresh. There's no state to update by hand.
