The Edit Page

EditTicketPage loads a ticket, shows it in the same TicketForm as the new ticket page, and saves the changes with PATCH.

A ticket's page has an Edit ticket link (topic 06 shows it), which goes to /tickets/2/edit. That's EditTicketPage. It does three things:

  1. Load the ticket, and the list of agents for the dropdown
  2. Show them in TicketForm, with the ticket's current values filled in
  3. Save the changes with PATCH /tickets/:id, then go back to the ticket's page

Here's its state, and what it shows once everything has loaded:

Two pages' patterns in one

Look at the state. The page does two jobs you've seen separately:

  • Loading, like Stage 2's detail page: ticket, isLoading and loadErrorMessage, filled by a useEffect, with the same "loading" and "couldn't load" returns before the main one.
  • Saving, like NewTicketPage: saveError, and a function passed to TicketForm as onSubmit.

The two errors are kept apart on purpose. If loading fails, there's no form to show, so the page shows only the message. If saving fails, the form stays, with the error inside it (topic 04).

The same form, with more in it

TicketForm is the component from topic 03, with two more props:

  • initialValues: the ticket's current values, so the inputs start filled in (slide 03)
  • agents: the list for the "Assigned to" dropdown. Passing it also tells the form to show the Status and Assigned to fields (slide 04)

submitLabel is "Save changes" here, and onSubmit is this page's handleSave. The form doesn't know it's editing rather than creating.
