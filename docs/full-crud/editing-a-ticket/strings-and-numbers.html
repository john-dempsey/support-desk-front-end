Strings and Numbers

A dropdown's value is always a string. The agent's id goes from a number to a string for the form, and back to a number (or null) for the API.

HTML has no numbers. Whatever you put in an <option>'s value, the browser keeps it as text, and event.target.value is always a string. So an agent's id has to change type twice on its way through the edit page:

On the way in, EditTicketPage turns the agent's id into a string with String(), or uses '' for no agent (Figure 3.24). Then value={assignedAgentId} matches one of the options exactly.

On the way out, TicketForm turns it back, in handleSubmit:

// Figure 3.27: back to what the API expects
// (src/components/TicketForm.jsx, excerpt)
let values = { subject, description };
if (agents) {
  let agentIdToSend = null;
  if (assignedAgentId !== '') {
    agentIdToSend = Number(assignedAgentId);
  }
  values = {
    subject,
    description,
    status,
    assignedAgentId: agentIdToSend,
  };
}

(The comments are left out, and values = {...} is one line in the file, split here to fit.)

  • '' (Unassigned) becomes null, which is how the API says "no agent" (topic 02, slide 02).
  • Anything else becomes a number, with Number('3'), which is 3.

The new ticket page has no agents, so it skips all of this and sends only { subject, description }.

Does the API care?

Try sending the strings as they are, with your REST client and Ada's token:

Body of PATCH /tickets/2 The API's answer
{ "assignedAgentId": "" } 400: Number must be greater than 0
{ "assignedAgentId": "abc" } 400: Expected number, received nan

The back-end's schema uses z.coerce.number() (Lesson 3), so it turns a string into a number before it checks it. '' becomes 0, which isn't a valid id. That's the real reason the form must send null for "Unassigned".

It would turn '3' into 3 without complaint. The form converts it anyway: sending the type the API documents means the front-end works with any API, not only one that's forgiving.

Try it

Number() is lenient in other ways too. In the browser's console, try Number(''), Number(' 3 '), Number('3abc') and Number(null). Which ones surprise you? Could any of them reach Number() from this dropdown? Why not?
