Saving, and Going Back

handleSave sends PATCH, then returns to the ticket's page, which loads the ticket fresh. There's no state to update by hand.

When the user clicks Save changes, TicketForm calls onSubmit with the values, exactly as before. On this page, that's handleSave:

// Figure 3.30: saving the changes (src/pages/EditTicketPage.jsx,
// excerpt)
async function handleSave(changes) {
  setSaveError(null);
  try {
    await updateTicket(ticketId, changes);
    navigate(`/tickets/${ticketId}`);
  } catch (error) {
    setSaveError(error);
  }
}

(The comment is left out.)

Put it next to handleCreate (Figure 3.12). Only two things differ: updateTicket() instead of createTicket(), and where it goes after saving. It uses ticketId from the URL, because the ticket already exists.

What about the saved ticket?

updateTicket() returns the ticket as it is after the change (topic 02). handleSave doesn't even keep it. Why not?

Because the page it goes to, TicketDetailPage, loads the ticket from the API every time it appears (Stage 2). So it shows exactly what was saved, including things the front-end didn't send, like the new updatedAt time. There's no copy of the ticket on this page to keep up to date by hand.

This is one of two ways to show the result of a change:

  • ask the API again, as here: the simplest, and always right
  • update the state you already have from the response, which saves a request

Topic 07 uses the second way for comments, and explains when it's worth it.

The back-end reacts

A PATCH does more than change a row. In back-end Lesson 5, ticket.service.js fires domain events when a ticket's status changes or it's assigned to an agent, and a listener sends an email for each. Mailpit catches them, at http://localhost:8025:

Change Who's emailed
the status the ticket's customer
the assigned agent the agent

The service compares the ticket before and after, so saving without changing the status or the agent sends no email.

(If your own API doesn't have Lesson 5's events, nothing is emailed, and everything else works the same.)
