The Status and Agent Dropdowns

When TicketForm is given agents, it shows two more fields: a status dropdown built from a list, and an agent dropdown built from the API's agents.

A new ticket is always open and unassigned: the back-end sets both, and a customer can't choose. So the new ticket page doesn't show those fields. The edit page does, because changing them is what agents and admins edit tickets for.

TicketForm decides with its agents prop. The new ticket page doesn't pass it, so it's undefined; the edit page passes the list:

// Figure 3.25: two extra fields (src/components/TicketForm.jsx, excerpt)
{agents && (
  <>
    <div className="form-field">
      <label htmlFor="ticket-status">Status</label>
      <select
        id="ticket-status"
        value={status}
        onChange={(event) => setStatus(event.target.value)}
      >
        {TICKET_STATUSES.map((statusValue) => (
          <option key={statusValue} value={statusValue}>
            {STATUS_LABELS[statusValue]}
          </option>
        ))}
      </select>
    </div>

    {/* ... the "Assigned to" field, below */}
  </>
)}

agents && (...) is the same && you've used for loading and error messages: if agents is undefined, nothing is shown. The <>...</> fragment groups the two fields so && can show both or neither.

A controlled <select>

A <select> is controlled exactly like an <input> (topic 03, slide 02): value={status} chooses which option shows as selected, and onChange saves the user's choice. event.target.value is the chosen option's value, so 'in_progress', not the words "In progress".

The options are built by map(), one per status, from two lists in src/utils/ticketStatuses.js (slide 06): TICKET_STATUSES for the values, and STATUS_LABELS for the words. Each <option> needs a key, like any list in React.

The agent dropdown

// Figure 3.26: choosing an agent (src/components/TicketForm.jsx,
// excerpt)
<select
  id="ticket-agent"
  value={assignedAgentId}
  onChange={(event) => setAssignedAgentId(event.target.value)}
>
  <option value="">Unassigned</option>
  {agents.map((agent) => (
    <option key={agent.id} value={agent.id}>
      {agent.name}
    </option>
  ))}
</select>

(Its <label> and the <div> around it are left out. They're the same shape as the status field's.)

  • One option is always there: Unassigned, with the value ''.
  • One option per agent from GET /users?role=agent, with the agent's id as the value and their name as the words. The user chooses a name; the code gets an id.
