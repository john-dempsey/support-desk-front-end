Starting With the Ticket's Values

The page turns the ticket into the form's initialValues. The form reads them only once, which is why it isn't shown until the ticket has loaded.

A new ticket's form starts empty. An edit form starts with the ticket's current values, so the user changes only what they need to. TicketForm takes those as its initialValues prop. The page builds them from the ticket, just before its main return:

// Figure 3.24: the form's starting values
// (src/pages/EditTicketPage.jsx, excerpt)
let assignedAgentId = '';
if (ticket.assignedAgent) {
  assignedAgentId = String(ticket.assignedAgent.id);
}
const initialValues = {
  subject: ticket.subject,
  description: ticket.description,
  status: ticket.status,
  assignedAgentId,
};

(The comment above it is left out.)

subject, description and status are copied as they are. The agent needs converting: the ticket has an assignedAgent object (or null), and the form needs a string. Slide 05 explains why.

The last line, assignedAgentId, on its own, is short for assignedAgentId: assignedAgentId.

Where initialValues goes

In TicketForm, each piece of state starts from one of these values (Figure 3.8):

const [subject, setSubject] = useState(initialValues.subject);

The new ticket page doesn't pass initialValues, so TicketForm uses its default, EMPTY_TICKET, where everything is '' (and the status is 'open').

Read once, on the first render

There's a catch. The value you pass to useState() is used only on the first render, to set the state up. After that, useState() returns whatever the state now holds, and ignores the value you pass.

So if TicketForm appeared before the ticket had loaded, its state would start empty, and stay empty when the ticket arrived a moment later. The user would see a blank form for a ticket that has a subject.

That's why the order of the page's returns matters:

  1. while isLoading is true, return <Loading />, not the form
  2. if loading failed, return the error
  3. only then build initialValues and return <TicketForm>

By the time TicketForm first renders, the ticket is there, and the form's state starts with the right values.
