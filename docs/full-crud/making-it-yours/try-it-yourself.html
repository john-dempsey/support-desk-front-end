Try It Yourself

Challenges that use everything in this lesson. Run the tests after each one, and commit when they pass.

Each of these builds on something from this lesson. After each one, run npm test and npm run lint, and commit when both pass.

Warm-up

  1. How many tickets? Under the Tickets heading, show "4 tickets" (or "1 ticket"), using meta.total. Does it change when you filter? Add a test.
  2. Clear the filters. Add a Clear filters link above the list that goes to plain /tickets. Should it be a <Link> or a <button>? Why does it need no state and no handler?

Build something

  1. Edit a comment. The API has PATCH /tickets/:ticketId/comments/:id. Add updateComment() to comments.api.js, and an Edit button on each comment that turns it into a form, using TagsPage's rename as your model (topic 08, slide 03). Should the page update its list from the response, or ask again? Test it.
  2. Close ticket. Add a Close ticket button to the ticket's page, which sends PATCH with { "status": "closed" } and stays on the page. Update ticket from what updateTicket() returns (topic 07, slide 08). Hide the button when the ticket is already closed. Test both.
  3. Tickets per page. Add a fourth dropdown above the list, for 10, 25 or 50 tickets per page. Which existing function can handle its onChange without any changes? What should happen to page?
  4. Past the end. On /tickets?pageSize=2&page=3, the list is empty and Pagination says "Page 3 of 2". Make the page offer a link back to the last real page instead. Test it.

Investigate

  1. Two tabs. Open ticket 2 in two tabs. In the first, edit it and change its status. Look at the second. What does it show, and why? What makes it show the change?
  2. Who gets the email? With Mailpit open, add a comment to ticket 1 as Ada. Who is emailed? Is Alex, the assigned agent? Find the reason in the back-end's comment.service.js.
  3. Every request. With the Network tab on Fetch/XHR, create a ticket as Casey. List every request, in order, from clicking Create ticket to the new ticket's comments appearing. Which page sent each one? Why are some there twice in development?

Commit

git add .
git commit -m "Stage 3: ticket count, clear filters, ..."

When your own case study can create, edit and delete its records from your front-end, with validation errors by the field, confirmation before deleting, and tests for each, it's ready for Stage 4: logging in, and showing each user only what their role allows.
