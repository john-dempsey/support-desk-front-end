One Form, Used Twice

TagForm is a one-field form. The page uses it to add a tag and to rename one, which is why each use needs its own input id, and only one has a Cancel button.

TagForm is CommentForm (topic 07) with an input instead of a textarea. It looks after the name being typed, and calls onSubmit, which returns true if the tag was saved, so the form knows to empty its input. It also has three props the other forms didn't need:

// Figure 3.43: the tag form's props (src/components/TagForm.jsx,
// excerpt)
function TagForm({
  inputId,
  label,
  initialName = '',
  submitLabel,
  onSubmit,
  onCancel,
  error,
}) {
  // ...
  <label htmlFor={inputId}>{label}</label>
  <input id={inputId} ... />
  // ...
  {onCancel && (
    <button type="button" className="secondary-button" onClick={onCancel}>
      Cancel
    </button>
  )}

(The function's first line is one line in the file, split here to fit. ... marks the parts left out.)

The page uses it twice:

// Figure 3.44: the two uses (src/pages/TagsPage.jsx, excerpt)
<TagForm
  inputId="new-tag-name"
  label="New tag name"
  submitLabel="Add tag"
  onSubmit={handleAddTag}
  error={addError}
/>
// ... and, in the row of the tag being renamed:
<TagForm
  inputId={`tag-name-${tag.id}`}
  label={`New name for "${tag.name}"`}
  initialName={tag.name}
  submitLabel="Save"
  onSubmit={handleRenameTag}
  onCancel={() => setEditingTagId(null)}
  error={renameError}
/>

inputId: every id is different

TicketForm and CommentForm could use fixed ids like ticket-subject, because there's only ever one of each on a page. But both tag forms can be on screen at once, and an id must be unique on a page: <label htmlFor> and aria-describedby find their element by it. Two inputs with the same id, and clicking the second label would put the cursor in the first input.

So the page passes the id. The rename form's includes the tag's own id: tag-name-1, tag-name-2, ... The form builds its error's id from it too: `${inputId}-error`.

label: say what it's for

"New tag name" and New name for "bug" tell a screen reader user which form they're in, and which tag they're renaming.

onCancel: optional

Adding needs no Cancel: you just don't click Add tag. Renaming does, to put the row back. So onCancel is optional: the add form doesn't pass it, it's undefined, and onCancel && (...) shows no button.

Try it

Give the rename form the same inputId as the add form, "new-tag-name". Save, click Rename on a tag, and then click the words New name for "..." above the rename input. Where does the cursor go? Why that input? Put it back.
