In the User's Words

For a duplicate name, the API's message mentions a database index. The page replaces it with one a user understands, because the page decides what a status means.

Add a tag called bug. The API already has one, so it answers 409, with this message:

A record with that Tag_name_key already exists

Tag_name_key is the name of the database's unique index on the name column. The back-end's errorHandler.js builds its 409 message from what Prisma reports (Lesson 3), and for MySQL that's the index's name, not the field's. It's accurate, but it means nothing to someone using the app.

The front-end can't change the API's message. But it decides what to show: that's been the pages' job since Stage 2. So TagsPage says it in its own words:

// Figure 3.50: rewording a 409 (src/pages/TagsPage.jsx, excerpt)
function describeTagError(error) {
  if (error.status === 409) {
    return new Error('A tag with that name already exists.');
  }
  return error;
}
// ...
} catch (error) {
  setAddError(describeTagError(error));

(The comment above it is left out.)

  • For a 409, it returns a new error with a clear message. The form shows that instead.
  • For anything else (a 400, the API being down), it returns the error as it was, details and all.

It's a plain function outside the component, because it uses nothing from the component: no state and no props.

Why only for adding and renaming?

When adding or renaming, a 409 can only mean one thing: the name is taken. When deleting, a 409 means the tag is on a ticket (slide 05). "A tag with that name already exists" would be wrong there, so handleDeleteTag doesn't use describeTagError.

The database decides what "the same" means

The unique index is in MySQL, and MySQL compares the names ignoring case. So these are all "already exists" too:

Name Why
Bug the same as bug, ignoring case
bug Zod trims the spaces first (.trim()), then it's bug

No browser check could have told the user that. It needs the database, which is why the API's answer, not the form's required, has the final say (topic 04).

Three errors, three places

The page keeps three errors apart, so each shows next to what caused it:

State Shown Kept as
addError in the add form the error (for details)
renameError in the rename form, in that row the error (for details)
deleteErrorMessage above the list just the message
