Which Row Is Being Renamed?

One piece of state, editingTagId, holds the id of the tag being renamed. Each row compares its own id with it, and shows either its name or a TagForm.

Clicking Rename turns that one row into a small form, with the tag's name ready to change. Clicking Cancel, or saving, turns it back. The page needs to remember which row, if any, is being renamed. One piece of state does it:

// Figure 3.45: which tag, if any (src/pages/TagsPage.jsx, excerpt)
const [editingTagId, setEditingTagId] = useState(null);
// ...
function startRenaming(tagId) {
  setRenameError(null);
  setEditingTagId(tagId);
}

null means no tag is being renamed. Otherwise, it's the id of the one that is. Each row then asks: is it me?

// Figure 3.46: each row (src/pages/TagsPage.jsx, excerpt)
{tags.map((tag) => (
  <li key={tag.id}>
    {tag.id === editingTagId ? (
      <TagForm ... />
    ) : (
      <>
        <span className="tag-name">{tag.name}</span>
        <button ... onClick={() => startRenaming(tag.id)}>
          Rename
        </button>
        <button ... onClick={() => handleDeleteTag(tag)}>
          Delete
        </button>
      </>
    )}
  </li>
))}

? : with JSX

condition ? (this) : (that) is the same ternary you used for "Unassigned" in Stage 1, with a piece of JSX on each side instead of a string. && shows something or nothing; ? : shows one thing or the other.

Why an id, not true or false?

A true/false like isRenaming couldn't say which tag. A true or false per tag could, but then two rows could be in rename mode at once, and the page would need a way to keep them all. One id says both things at once: whether anything is being renamed, and what.

startRenaming also clears renameError, so an error from renaming one tag doesn't appear when you start renaming another.
