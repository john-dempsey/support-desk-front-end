Tags: CRUD on One Page

List, add, rename and delete tags, all on one page. A recap of the lesson so far, plus renaming in place, asking again for a sorted list, and rewording an unhelpful error.

  • A Whole Resource on One Page

    Tags have only a name, so all four CRUD operations fit on one page. It's the pattern to copy for a simple resource in your own API.

  • One Form, Used Twice

    TagForm is a one-field form. The page uses it to add a tag and to rename one, which is why each use needs its own input id, and only one has a Cancel button.

  • Which Row Is Being Renamed?

    One piece of state, editingTagId, holds the id of the tag being renamed. Each row compares its own id with it, and shows either its name or a TagForm.

  • Asking Again for a Sorted List

    The API sorts tags by name, so a new or renamed tag could belong anywhere in the list. The page asks the API for the list again, instead of working out where.

  • Deleting a Tag

    Deleting a tag doesn't change the order of the others, so the page just leaves it out of its list. A tag that's on a ticket can't be deleted.

  • In the User's Words

    For a duplicate name, the API's message mentions a database index. The page replaces it with one a user understands, because the page decides what a status means.
