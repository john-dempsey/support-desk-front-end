A Whole Resource on One Page

Tags have only a name, so all four CRUD operations fit on one page. It's the pattern to copy for a simple resource in your own API.

A tag is a label, such as bug or billing. It has an id and a name, and nothing else. With so little to show, there's no need for a page per tag, or a separate page to create one. /tags does everything:

On the page Request Topic
the list, sorted by name GET /tags this slide
an Add a tag form at the top POST /tags slides 02 and 04
a Rename button on each tag PATCH /tags/:id slides 03 and 04
a Delete button on each tag DELETE /tags/:id slide 05

The requests

// Figure 3.42: the tag requests (src/api/tags.api.js, excerpt)
export async function getTags() {
  const responseBody = await apiRequest('/tags');
  return responseBody.data;
}

export async function createTag(name) {
  const responseBody = await apiRequest('/tags', {
    method: 'POST',
    body: { name },
  });
  return responseBody.data;
}

export async function updateTag(tagId, name) {
  const responseBody = await apiRequest(`/tags/${tagId}`, {
    method: 'PATCH',
    body: { name },
  });
  return responseBody.data;
}

export async function deleteTag(tagId) {
  await apiRequest(`/tags/${tagId}`, { method: 'DELETE' });
}

(The comments are left out, and the POST and PATCH calls are each one line in the file, split here to fit.)

Nothing here is new. These are the four shapes from topic 02, for a different resource. { name } is short for { name: name }.

Loading the list

TagsPage loads its tags exactly as Stage 2's list page loaded tickets: tags starts as null, a useEffect with an empty dependency array calls getTags() once, and the page shows loading, error, empty ("There are no tags yet.") or the list.

A model for your own API

Most case-study APIs have a simple resource like this: a category, a location, a type of something. This page is the pattern to copy for one. Everything else in this topic is about the few things that are new: renaming in place, keeping a sorted list in order, and a better error message.
