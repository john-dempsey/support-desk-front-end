Deleting a Tag

Deleting a tag doesn't change the order of the others, so the page just leaves it out of its list. A tag that's on a ticket can't be deleted.

// Figure 3.49: deleting a tag (src/pages/TagsPage.jsx, excerpt)
async function handleDeleteTag(tagToDelete) {
  const isConfirmed = window.confirm(
    `Delete the tag "${tagToDelete.name}"?`,
  );
  if (!isConfirmed) {
    return;
  }

  setDeleteErrorMessage('');
  try {
    await deleteTag(tagToDelete.id);
    setTags(tags.filter((tag) => tag.id !== tagToDelete.id));
  } catch (error) {
    setDeleteErrorMessage(error.message);
  }
}

(The comment is left out, and window.confirm(...) is one line in the file, split here to fit.)

It's handleDeleteComment (topic 07) with tags instead of comments: confirm, send DELETE, then filter() the tag out of the list.

Why not ask again this time?

Adding and renaming ask the API again, because they can change the order. Deleting can't: take one tag out of a sorted list, and the rest are still sorted. So the page knows exactly what the new list is, and filter() is enough. The right choice depends on the change, not on the page.

Tags on tickets

Try to delete bug or billing, the two seeded tags. The API answers 409:

This record cannot be deleted or changed because other records still depend on it

The seed puts each of them on a ticket. In the database, a TicketTag row links a ticket to a tag, so the tag can't be deleted while that link exists: the same foreign key rule as a ticket with comments (topic 06).

There's no API request to take a tag off a ticket (or to put one on), so from the front-end, those two tags can't be deleted. Tags you add yourself can.
