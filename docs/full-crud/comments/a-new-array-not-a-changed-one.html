A New Array, Not a Changed One

React only re-renders when it's given a different value. So adding to a list in state means making a new array with the spread syntax, never push().

To add the new comment, the page writes:

setComments([...comments, newComment]);

Why not the obvious way?

comments.push(newComment);
setComments(comments);

React compares, then decides

When you call a state setter, React compares the new value with the one it already has. If they're the same, nothing has changed, so it doesn't re-render. That saves a lot of work.

For an array, "the same" means the same array, not "an array with the same items". push() adds to the array you already have. So setComments(comments) hands React the very array it's already holding. React sees no change, skips the re-render, and the new comment doesn't appear:

The comment is in the array, but not on the screen, and it may appear later, when something else happens to re-render the page. It's a confusing bug, because the data looks right in the debugger.

The spread syntax

[...comments, newComment] makes a new array:

  • ...comments spreads the existing comments into it, one by one
  • newComment goes on the end

The old array isn't touched. React gets a different array, so it re-renders. It's the same ... the back-end uses to copy objects, such as { ...req.body, customerId: req.user.id }.

Deleting: filter()

Deleting needs a new array too. filter() always makes one: it keeps every item for which the function returns true.

setComments(
  comments.filter((comment) => comment.id !== commentToDelete.id),
);

Every comment except the deleted one goes into the new array.

The rule

Never change state directly. Make a new value, and pass that to the setter. It applies to objects as well as arrays, and to every piece of state in every component.

Try it

In handleAddComment, replace the setComments(...) line with the two push() lines above. Save, and add a comment. Does it appear? Type a character in the comment box: does it appear now? (The form's state changes, but does the page re-render?) Then delete a different comment, and click OK. What appears, and why then? Put the line back.
