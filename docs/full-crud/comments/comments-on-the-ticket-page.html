Comments on the Ticket's Page

Under a ticket's description, its comments, and a box to add one. Every comment request goes through comments.api.js, using the API's nested URLs.

At the bottom of a ticket's page, under its description, there's now a Comments section: each comment with its author and date, a Delete button on each, and an Add a comment box.

Nested URLs

In the API, comments belong to a ticket, and their routes say so: every one starts with /tickets/:ticketId/comments (Lesson 3). So every function in comments.api.js needs the ticket's id:

// Figure 3.34: two of the comment requests
// (src/api/comments.api.js, excerpt)
export async function getComments(ticketId) {
  const responseBody = await apiRequest(
    `/tickets/${ticketId}/comments`,
  );
  return responseBody.data;
}

export async function createComment(ticketId, commentText) {
  const responseBody = await apiRequest(
    `/tickets/${ticketId}/comments`,
    { method: 'POST', body: { body: commentText } },
  );
  return responseBody.data;
}

(The comments are left out, and both apiRequest() calls are laid out differently in the file. They're rearranged here to fit.)

The third, deleteComment(ticketId, commentId), sends DELETE /tickets/:ticketId/comments/:id, with both ids in the URL.

{ body: commentText }

That line looks odd. The API calls a comment's text body (the column in the Prisma schema, and the field in createCommentSchema). So the request's body is an object with a body field:

{ "body": "Have you checked your spam folder?" }

Inside the front-end, the text is called commentText, so it's never confused with the body of a request. It only becomes body here, at the edge, where the API's name has to be used.

What a comment looks like

GET /tickets/1/comments returns the comments oldest first, each with its author, as the back-end's comment.service.js includes them:

{
  "id": 1,
  "body": "Looking into this now — can you confirm ...",
  "ticketId": 1,
  "authorId": 3,
  "author": { "id": 3, "name": "Alex Agent", "email": "..." },
  "createdAt": "2026-10-14T20:04:29.777Z"
}

(Shortened. Your ids and dates will be different.)
