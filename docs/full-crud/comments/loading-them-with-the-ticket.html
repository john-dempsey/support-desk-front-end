Loading Them With the Ticket

The ticket's page now asks for the ticket and its comments together, with Promise.all(), in the effect it already had.

The ticket's page already had a useEffect that loaded the ticket (Stage 2). Stage 3 adds the comments to the same effect, with the same Promise.all() as the edit page (topic 05):

// Figure 3.35: the ticket and its comments
// (src/pages/TicketDetailPage.jsx, excerpt)
const [ticket, setTicket] = useState(null);
const [comments, setComments] = useState([]);
// ...
const [ticketData, commentsData] = await Promise.all([
  getTicket(ticketId),
  getComments(ticketId),
]);
if (!ignore) {
  setTicket(ticketData);
  setComments(commentsData);
}

Nothing else in the effect changes. In particular, the "not found" handling still works: for a ticket that doesn't exist, both requests get a 404 (the back-end checks the ticket before it looks for its comments), Promise.all() fails, and the catch sets isNotFound as before.

[], not null

comments starts as [], unlike ticket, which starts as null. Does that break the rule from Stage 2, that null means "not loaded yet"?

No: the comments are never shown on their own. The page shows <Loading /> until both have loaded, so by the time CommentList appears, comments has always been set from the API. Starting with [] just means comments is always an array, so the code that uses it never has to check for null.

Clearing them for the next ticket

The effect's cleanup already reset the ticket's state when the URL changed to another ticket (Stage 2, topic 05). It now resets the comments and their error too:

// Figure 3.36: the cleanup (src/pages/TicketDetailPage.jsx, excerpt)
return () => {
  ignore = true;
  setTicket(null);
  setComments([]);
  // ... the error messages and isLoading, as before
  setCommentError(null);
};

Without that, ticket 2's page could briefly show ticket 1's comments.
