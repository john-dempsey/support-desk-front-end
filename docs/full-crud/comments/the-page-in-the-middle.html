The Page in the Middle

The comment form and the comment list are siblings. They can't talk to each other, so the comments live in the page, their closest shared parent.

At the bottom of the ticket's page, the list and the form sit side by side:

// Figure 3.38: comments on the page
// (src/pages/TicketDetailPage.jsx, excerpt)
<h2>Comments</h2>
<CommentList comments={comments} onDelete={handleDeleteComment} />
<CommentForm onSubmit={handleAddComment} error={commentError} />

When the user adds a comment in the form, it has to appear in the list. But a component can only pass things down to its own children, and call functions its parent gave it (topic 03, slide 03). CommentForm and CommentList are siblings: neither is the other's parent. They have no way to reach each other.

So the comments live in the page, the closest component that contains both:

Follow a new comment round:

  1. CommentForm calls onSubmit(commentText), which is the page's handleAddComment.
  2. The page sends it to the API, and adds the saved comment to its comments state.
  3. The page re-renders, and passes the longer comments array down to CommentList.
  4. CommentList re-renders with one more comment.

The form never knew the list existed.

Where should state live?

This is a rule React developers use all the time: put state in the closest component that contains everything that uses it. It's often called lifting state up.

  • comments is used by the list (to show) and changed because of the form (to add), so it lives in the page, above both.
  • commentText is used only by the form, so it lives in the form. The page doesn't need to know what's being typed until it's sent.
