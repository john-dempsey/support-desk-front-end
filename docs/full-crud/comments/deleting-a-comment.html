Deleting a Comment

Confirm, send DELETE, and remove the comment from the list. Only a comment's author, or an admin, may delete it, and the API says so if you try.

When a comment's Delete button is clicked, CommentList calls onDelete(comment) (slide 03). That's the page's handleDeleteComment:

// Figure 3.41: deleting a comment (src/pages/TicketDetailPage.jsx,
// excerpt)
async function handleDeleteComment(commentToDelete) {
  const isConfirmed = window.confirm(
    "Delete this comment? This can't be undone.",
  );
  if (!isConfirmed) {
    return;
  }

  setCommentError(null);
  try {
    await deleteComment(ticket.id, commentToDelete.id);
    setComments(
      comments.filter((comment) => comment.id !== commentToDelete.id),
    );
  } catch (error) {
    setCommentError(error);
  }
}

(The comments are left out, and the long lines are split here to fit. The file writes the message with single quotes and \'.)

It's handleDeleteTicket (topic 06) again, with two differences:

  • It stays on the page. The ticket is still there, so instead of navigating away, it removes the comment from the list with filter() (the previous slide). The DELETE sent back a 204 with no body, so there's nothing else to use.
  • Its errors go to commentError, which the form shows, just above the comment box. That keeps a comment's error with the comments, rather than up by the ticket's buttons.

Only your own comments

The API has a rule for comments (Lesson 4): only the comment's author may delete it, or an admin. Anyone else gets:

You can only modify your own comments

Ada is an admin, so with her token, every Delete button works. Stage 4 will hide the Delete button on other people's comments. As with every control in this stage, hiding it will only be for the user's sake: the API's check is what protects the comments.
