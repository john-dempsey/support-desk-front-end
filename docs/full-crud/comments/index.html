Comments

A list and a form on the ticket's page, connected through the page. Adding and deleting update the list the page already has, with a new array each time.

  • Comments on the Ticket's Page

    Under a ticket's description, its comments, and a box to add one. Every comment request goes through comments.api.js, using the API's nested URLs.

  • Loading Them With the Ticket

    The ticket's page now asks for the ticket and its comments together, with Promise.all(), in the effect it already had.

  • The Comment List

    CommentList shows each comment with a Delete button. The button's onClick needs to say which comment, so it wraps the call in an arrow function.

  • The Page in the Middle

    The comment form and the comment list are siblings. They can't talk to each other, so the comments live in the page, their closest shared parent.

  • Adding a Comment

    The page adds the saved comment to its list, and tells the form whether it worked, so the form only empties its box when the comment was saved.

  • A New Array, Not a Changed One

    React only re-renders when it's given a different value. So adding to a list in state means making a new array with the spread syntax, never push().

  • Deleting a Comment

    Confirm, send DELETE, and remove the comment from the list. Only a comment's author, or an admin, may delete it, and the API says so if you try.

  • Update, or Ask Again?

    After a change, a page can update the state it has from the response, or ask the API again. The edit page asks again; the comments update. Here's how to choose.
