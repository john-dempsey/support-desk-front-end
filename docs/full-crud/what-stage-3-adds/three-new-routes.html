Three New Routes

Each new page gets a line in App.jsx. One of them, /tickets/new, also fits the pattern /tickets/:ticketId, and React Router still picks the right page.

Every page in the app has a line in the route table, App.jsx (Stage 0, topic 04). Stage 3 adds three lines for the three ticket and tag pages:

// Figure 3.1: the route table (src/App.jsx, excerpt)
<Routes>
  <Route path="/" element={<HomePage />} />
  <Route path="/tickets" element={<TicketListPage />} />
  <Route path="/tickets/:ticketId" element={<TicketDetailPage />} />
  <Route path="/tickets/new" element={<NewTicketPage />} />
  <Route
    path="/tickets/:ticketId/edit"
    element={<EditTicketPage />}
  />
  <Route path="/tags" element={<TagsPage />} />

  <Route path="*" element={<NotFoundPage />} />
</Routes>

(The comments are left out, and the edit route is split over several lines here to fit. It's one line in the file.)

Each new page is imported at the top of the file, like the others.

/tickets/new or ticket "new"?

Look at /tickets/new. It also fits the pattern /tickets/:ticketId, with ticketId as the text 'new'. So which page shows?

React Router compares the routes and picks the most specific one that fits (Stage 0, topic 04). A fixed word like new is more specific than :ticketId, which fits anything. So /tickets/new shows NewTicketPage, and /tickets/2 still shows TicketDetailPage. The order of the lines makes no difference.

Express is different. In the back-end, routes are tried in the order they're registered, and the first one that fits wins. If a back-end route file had router.get('/:id', ...) above router.get('/new', ...), a request for /new would reach the first one, with req.params.id set to 'new'. In React Router, that mistake can't happen.

:ticketId in the middle

/tickets/:ticketId/edit has its parameter in the middle of the path. That works the same way: on /tickets/2/edit, useParams() gives { ticketId: '2' }. It's the same shape as the back-end's nested comment routes, /tickets/:ticketId/comments.

A link to Tags

The ticket pages link to each other (the diagram on the previous slide), but nothing links to /tags. So NavBar.jsx gets a third NavLink, exactly like the other two:

// Figure 3.2: the new link (src/components/NavBar.jsx, excerpt)
<li>
  <NavLink to="/tags">Tags</NavLink>
</li>

The new and edit pages don't need links in the navigation bar, because you reach them from the ticket pages.
