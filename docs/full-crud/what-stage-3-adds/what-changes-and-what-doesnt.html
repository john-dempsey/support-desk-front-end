What Changes, and What Doesn't

Most of Stage 3 is new files. client.js doesn't change at all: the starter already knew how to send a body, read a 204 and keep validation details.

Stage 3 is the biggest stage so far, but most of it is new files that sit beside the old ones. Here's every file in src/ it touches, leaving out the tests (topic 10):

Folder New Changed
api/ comments.api.js, tags.api.js, users.api.js tickets.api.js: four new functions (topic 02, topic 09)
pages/ NewTicketPage, EditTicketPage, TagsPage TicketDetailPage: comments and Delete. TicketListPage: filters and pages
components/ TicketForm, FieldError, CommentList, CommentForm, TagForm, TicketFilters, Pagination NavBar: the Tags link. StatusBadge: its labels move out (topic 05)
utils/ getFieldError.js, ticketStatuses.js
App.jsx: three routes. index.css: forms and buttons

What doesn't change

  • api/client.js. Not one line. Stage 0's apiRequest() could already send a body as JSON, return null for a 204, and attach status and details to an error (Stage 0, topic 05). Nothing used those parts until now. This is the payoff for writing the client once, completely, at the start.
  • TicketList, Loading, ErrorMessage, formatDate. The new pages reuse them as they are.
  • main.jsx, HomePage, NotFoundPage.

The same split as before

Every new page follows the rule from Stage 1: pages own the data, components display it. Pages call the API and hold what comes back. Components get props.

Forms add one twist, which topic 03 explains: a form component holds what's being typed, because only it needs that while the user types. The page still makes the request.
