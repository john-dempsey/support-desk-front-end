Previewing the Build

npm run preview serves dist/ on your own machine, so you can check the real thing before it's deployed.

A build can behave differently from the dev server. A missing file, or a .env value you forgot to set, only shows up in the built version. So before deploying, try the build on your own machine:

npm run build
npm run preview

npm run preview serves the files in dist/ at http://localhost:4173. Unlike npm run dev, it doesn't translate anything or watch for changes. It just sends the built files, like a real web server would, including the index.html fallback for unknown URLs. If you change the code, you have to build again.

npm run dev npm run preview

Try it

With the API running:

  1. Run npm run build, then npm run preview, and open http://localhost:4173. Does the home page look the same as on port 5173?
  2. Open the Network tab and reload. How many requests to welcome are there now? Compare that with topic 06's StrictMode slide: why is it different?
  3. Open the .js file in dist/assets/ in your editor. Can you find the text Connecting to the API? Can you find the name HomePage? What happened to it?
  4. Go to http://localhost:4173/no-such-page. Which part of the app shows the "Page not found" message: the preview server or React?

Stop the preview server with Ctrl+C when you're done.
