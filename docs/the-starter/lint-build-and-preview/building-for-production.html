Building for Production

npm run build turns the whole app into a few plain files that any web server can host.

npm run dev is for working on the app. It's not how the app is given to users: it translates files every time they're asked for, and it includes extra code for hot updates and StrictMode's checks.

For users, the app is built once:

npm run build

For the starter, the output looks like this:

dist/index.html                   0.53 kB │ gzip:  0.34 kB
dist/assets/index-BQTvWgPy.css    1.17 kB │ gzip:  0.54 kB
dist/assets/index-DhwRkgzD.js   259.54 kB │ gzip: 82.58 kB
✓ built in 158ms

What's in dist/

All your components, React itself, React Router and your CSS end up in just three files:

  • index.html: the same empty page from topic 03, now pointing at the files below instead of src/main.jsx
  • one .css file: every stylesheet the app imports, combined
  • one .js file: every component, every library in dependencies, and none of the devDependencies, all translated from JSX into plain JavaScript and minified (spaces, comments and long names removed to make it smaller)

The gzip column is the size after the server compresses it, which is roughly what a user downloads: about 83 kB of JavaScript, most of it React.

The odd file names

index-DhwRkgzD.js has a hash in its name, made from the file's contents. Browsers keep downloaded files for a while (they cache them). When you change the code and build again, the contents change, so the name changes, so browsers know to download the new version instead of using an old one.

Things to know about the build

  • .env is read at build time. VITE_API_URL is copied into the .js file (topic 02). To point a built app at a different API, change .env and build again.
  • dist/ is never committed. It's in .gitignore, like node_modules, because it can always be made again from the source.
  • No Node or Vite is needed to host it. These are ordinary static files. Any web server can send them, as long as it sends index.html for URLs it doesn't recognise: the fallback from topic 04.
