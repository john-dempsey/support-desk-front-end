Showing the Right Thing

Using && to show a piece of the page only when a condition is true.

Here's what HomePage returns:

// Figure 0.22: what the page shows (src/pages/HomePage.jsx, excerpt)
  return (
    <>
      <h1>Welcome</h1>
      {isLoading && <Loading message="Connecting to the API…" />}
      {errorMessage && <ErrorMessage message={errorMessage} />}
      {welcome && (
        <p>
          The API says: <strong>{welcome.message}</strong>
        </p>
      )}
    </>
  );

The heading is always shown. Each of the other three lines shows its piece only if a condition is true. That's done with &&.

How && works here

You know && as "and". In JavaScript, a && b gives back:

  • a, if a is falsy (false, null, undefined, '', 0)
  • otherwise, b

And React shows nothing for false, null, undefined or ''. So:

Expression When the condition is false When it's true
{isLoading && <Loading />} false: nothing shown the <Loading> component
{errorMessage && <ErrorMessage />} '': nothing shown the <ErrorMessage> component
{welcome && <p>...</p>} null: nothing shown the paragraph

Read each line as "if this, then show that". It's JSX's version of Blade's @if ... @endif. Remember if statements can't go inside { } (topic 03), but && is an expression, so it can.

{welcome && ...} also protects the line inside it. While welcome is null, reading welcome.message would crash the page. && stops before it gets there.

One trap: 0

React does show the number 0. So with a count:

{ticketCount && <p>You have {ticketCount} tickets</p>}

when ticketCount is 0, the page shows a lone 0. Write a real true/false condition instead: {ticketCount > 0 && ...}.

Either-or: ? :

When you want one thing or another (rather than "something or nothing"), use the conditional operator:

{isLoading ? <Loading /> : <p>Done!</p>}

That's Blade's @if ... @else ... @endif.
