State: Data That Changes

Blade drew a page once per request. A React component is drawn again every time its data changes, and useState is how it gets that data.

A Blade view ran once per request. The controller gathered the data, Blade turned it into HTML, and that page never changed again. To show something new, the browser asked for a whole new page.

A React page stays on screen while things happen: a click, a response from the API, a timer. When something changes, the component has to be drawn again with the new data. React calls this re-rendering, and the data that triggers it is called state.

A small example

This isn't in the starter. It's the smallest possible example of state:

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}
  • useState(0) creates one piece of state, starting at 0. It returns two things in an array, which are unpacked with array destructuring: the current value (count) and a function to change it (setCount).
  • onClick is how React attaches a click handler: a prop that takes a function. (Event props are camelCase: onClick, not onclick.)
  • Clicking calls setCount(count + 1). React stores the new value, then calls Counter() again. This time useState gives back 1, the function returns a button that says "Clicked 1 times", and React updates the page to match.

React compares what the component returned this time with last time, and only changes the parts of the real page that are different. Here, that's just the text inside the button.

Why not an ordinary variable?

function Counter() {
  let count = 0;   // doesn't work
  return <button onClick={() => count++}>Clicked {count} times</button>;
}

Two reasons this fails. First, changing count doesn't tell React anything has changed, so nothing is redrawn. Second, even if React did call Counter() again, the function would start from the top and set count back to 0. State lives outside the function, kept by React between calls. The setter is how you change it and tell React to redraw.

Hooks

useState is a hook: a React function whose name starts with use. Hooks have one rule that matters: call them at the top level of the component, never inside an if, a loop or a nested function. React tells the pieces of state apart by the order the hooks are called in, so that order must be the same every time the component runs. The linter (topic 09) checks this for you.
