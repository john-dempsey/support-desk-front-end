Cleanup and the ignore Flag

What happens to a response that arrives after the page has gone, and why StrictMode sends every request twice.

Look at Figure 0.23 again. The effect starts with let ignore = false, every setter is wrapped in if (!ignore), and the effect returns a function:

    return () => {
      ignore = true;
    };

That returned function is the effect's cleanup. React calls it when the component is removed from the page, for example when the user clicks a link to another page.

The problem it solves

A request takes time. Suppose the user opens the home page and, before the API has answered, clicks a link to another page. HomePage is removed. Then the response arrives, and loadWelcome carries on: it calls setWelcome for a page that isn't there any more.

That's wasted work at best. In later pages it can be a real bug: if a page asks for ticket 1, then ticket 2, and ticket 1's slower answer arrives last, the page would show the wrong ticket.

The fix is a flag. When the page goes, the cleanup sets ignore to true. When the late response arrives, every if (!ignore) is false, and nothing is changed.

How a variable can do this: closures

loadWelcome and the cleanup function were both created inside the same run of the effect, so they share that run's ignore variable. This is a closure, which you met in the back-end's Lesson 1: a function keeps access to the variables around it, even after the code that created them has finished.

Each time the effect runs, it creates a new ignore. Setting one to true doesn't affect any other.

StrictMode: every request twice

In topic 03, main.jsx wrapped the app in <StrictMode>, which "makes React do some work twice on purpose". Here's that work. While you develop, StrictMode puts each component on the page, removes it, and puts it back, to check that its effects clean up properly. For HomePage, that means:

  1. The effect runs. ignore (the first one) is false. Request A starts.
  2. StrictMode removes the page, so the cleanup sets the first ignore to true.
  3. StrictMode puts the page back. The effect runs again with a new ignore, false. Request B starts.
  4. A's answer arrives. Its ignore is true, so it's ignored.
  5. B's answer arrives, and updates the page.

So in development, /welcome is requested twice, and the page still shows one correct answer. That's StrictMode proving the cleanup works. In the production build (topic 09), StrictMode does nothing, and there's one request.

Try it

  1. Open the Network tab and reload the home page. How many requests to welcome are there?
  2. Delete the return () => { ignore = true; }; lines and reload. Does anything look different on the page? Why not? (Both responses carry the same message, so you can't see a problem here. The flag matters when two answers differ.) Put the lines back afterwards.
