Tracing a Page Load

Everything from this lesson in order: what happens, in which file, from opening the home page to seeing the API's message.

Here is everything that happens when you open http://localhost:5173/ with the API running, in order. Each step names the file it happens in.

  1. index.html. The browser loads the empty page, which loads main.jsx.
  2. main.jsx. createRoot takes over <div id="root"> and renders <App />.
  3. App.jsx. <Routes> sees the URL / and picks <HomePage />. NavBar is rendered above it.
  4. HomePage.jsx, first render. The three useState calls give their starting values: welcome is null, errorMessage is '', isLoading is true. The page returns the heading and <Loading message="Connecting to the API…" />. React puts it on screen.
  5. HomePage.jsx, the effect. Now that the page is showing, useEffect runs loadWelcome(), which calls getWelcome().
  6. welcome.api.js. getWelcome() calls apiRequest('/welcome').
  7. client.js. apiRequest builds the headers (no token, so no Authorization) and calls fetch('http://localhost:3000/welcome').
  8. The API. The request crosses to the back-end, which answers 200 with { "data": { "message": "Hello world!" } }.
  9. client.js. response.ok is true, so apiRequest returns the body.
  10. welcome.api.js. getWelcome returns responseBody.data: { message: 'Hello world!' }.
  11. HomePage.jsx, the state updates. setWelcome(...) stores the data. Then finally runs setIsLoading(false). The two happen one straight after the other, so React waits for both and re-renders once.
  12. HomePage.jsx, second render. React calls HomePage() again. Now isLoading is false, so Loading disappears, and welcome is set, so "The API says: Hello world!" appears.

(In development, StrictMode adds the extra run from the previous slide between steps 5 and 8.)

And if the API is down?

Steps 1 to 7 are the same. At step 7, fetch() rejects, apiRequest throws its "Can't reach the API" error, it passes up through getWelcome, and HomePage's catch stores the message with setErrorMessage. On the second render, errorMessage && ... shows <ErrorMessage>.

Practise saying it

This is exactly the kind of trace the viva asks for: component, API module, HTTP request, state update, re-render. Try explaining it out loud, with the code open, without reading these steps. Then close the code and try again.
