useEffect: Loading After the First Render

Why the request can't go straight into the component, and how useEffect runs it once, after the page appears.

Why not just call the API?

The obvious place to ask for data is the top of the component:

function HomePage() {
  const [welcome, setWelcome] = useState(null);
  getWelcome().then(setWelcome);   // don't do this
  // ...
}

Follow it through. React calls HomePage(), which starts a request. When the answer arrives, setWelcome changes the state, so React calls HomePage() again, which starts another request, whose answer changes the state again... The page would ask the API for data forever.

A component function should just describe the page. Work that reaches outside it (like a network request) is called a side effect, and it goes in useEffect.

useEffect

// Figure 0.23: loading the data (src/pages/HomePage.jsx, excerpt)
  useEffect(() => {
    let ignore = false;

    async function loadWelcome() {
      try {
        const welcomeData = await getWelcome();
        if (!ignore) {
          setWelcome(welcomeData);
        }
      } catch (error) {
        if (!ignore) {
          setErrorMessage(error.message);
        }
      } finally {
        if (!ignore) {
          setIsLoading(false);
        }
      }
    }

    loadWelcome();

    return () => {
      ignore = true;
    };
  }, []);

useEffect takes two arguments:

  1. A function to run. React runs it after the component's markup is on the page, so the user sees the heading and the loading message straight away.
  2. A list of dependencies: []. React runs the effect again only when something in this list changes. An empty list means "nothing ever changes", so it runs once, when the page first appears. That's what breaks the loop.

Ignore ignore for now. It's the next slide.

Inside the effect

  • Why a separate async function? The function passed to useEffect must return nothing, or a cleanup function (the return at the bottom). An async function always returns a promise, so it can't be passed to useEffect directly. Instead, the effect defines an async function and calls it straight away.
  • try: ask for the data. If it arrives, store it with setWelcome.
  • catch: client.js threw an error (topic 05). Store its message, such as "Can't reach the API...", with setErrorMessage.
  • finally: runs after either one. Success or failure, the page has stopped waiting, so setIsLoading(false).

Each setter causes a re-render, and the && lines from the last slide decide what appears.
