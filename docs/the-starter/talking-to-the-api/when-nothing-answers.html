When Nothing Answers

fetch() doesn't fail on a 404 or a 500. It only fails when no response arrives at all, and the client turns that into a clear message.

There's a surprise in how fetch() reports problems:

  • If the API answers anything, even 404 Not Found or 500 Internal Server Error, fetch() succeeds. It got a response; it's up to your code to check whether that response was good news. That's why apiRequest() checks response.ok itself (previous slide).
  • fetch() only fails (its promise rejects) when no response arrived at all: the API isn't running, the URL points at the wrong port, the network is down, or the browser blocked the response because of CORS (topic 01).

That second case is what the try/catch around fetch() is for (the fetch() options from Figure 0.14 are shortened to /* ... */ here, and the throw, one line in the file, is split to fit):

// Figure 0.18: no response at all (src/api/client.js, excerpt)
  let response;
  try {
    response = await fetch(`${API_URL}${path}`, { /* ... */ });
  } catch {
    throw createApiError(
      0,
      `Can't reach the API at ${API_URL} — is the back-end running?`,
    );
  }

The browser's own error here is just TypeError: Failed to fetch, which doesn't help anyone. So the client throws its own error instead, with:

  • status 0, meaning "no HTTP status": there was no HTTP response to have one
  • a message that says what to check, including the URL it tried, so a wrong port in .env is easy to spot

catch { with no (error) is allowed in modern JavaScript when the catch block doesn't need the original error.

let response; is declared before the try so it can still be used after it. A variable declared inside try { } would only exist inside those braces.

When the body isn't JSON

One more thing can go wrong: a response whose body isn't JSON. A proxy server's HTML error page is one example. response.json() would throw on that, so the client reads the body through a small helper:

// Figure 0.19: reading JSON safely (src/api/client.js, excerpt)
async function readJson(response) {
  try {
    return await response.json();
  } catch {
    return null;
  }
}

If the body can't be read as JSON, this gives null instead of crashing, and the ?. checks from the previous slide take it from there.
