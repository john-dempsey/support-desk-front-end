Sending a Request

fetch(), the request options, and why the Authorization header is only sent when there's a token.

The browser's built-in way to send an HTTP request is fetch(). It takes a URL and an options object, and returns a promise (the same async/await you used throughout the back-end):

const response = await fetch('http://localhost:3000/welcome');
const body = await response.json();

Two awaits: the first waits for the response to start arriving (its status and headers), and response.json() waits for the rest of the body and turns it from JSON text into a JavaScript object.

Here's how apiRequest() calls it:

// Figure 0.14: sending the request (src/api/client.js, excerpt)
export async function apiRequest(path, options = {}) {
  const method = options.method || 'GET';
  const hasBody = options.body !== undefined;

  let response;
  try {
    response = await fetch(`${API_URL}${path}`, {
      method,
      headers: buildHeaders(hasBody),
      body: hasBody ? JSON.stringify(options.body) : undefined,
    });
  } catch {
    // ... see "When Nothing Answers"
  }
  • path is just the part after the base URL, such as '/welcome'. API_URL (topic 02) is added here, so no other file needs to know it.
  • options is optional (= {}). A plain apiRequest('/welcome') is a GET with no body.
  • body is a normal JavaScript object. JSON.stringify() turns it into JSON text, which is what goes over the network. It's the reverse of the express.json() middleware in the back-end, which turned that text back into req.body.

The headers

// Figure 0.15: the request headers (src/api/client.js, excerpt)
export function getToken() {
  return null;
}

function buildHeaders(hasBody) {
  const headers = {};

  if (hasBody) {
    headers['Content-Type'] = 'application/json';
  }

  const token = getToken();
  if (token) {
    headers.Authorization = `Bearer ${token}`;
  }

  return headers;
}
  • Content-Type: application/json tells the API the body is JSON, so express.json() knows to read it. It's only sent when there is a body.
  • Authorization: Bearer ... is how the back-end's authenticate middleware expects a token. But getToken() returns null: the starter has no login. So no Authorization header is sent at all.

That second point is deliberate. Not every API in this module has authentication. A client that always sent a header (even an empty one) could confuse an API that doesn't expect one. A client that sends one only when there's a token works unchanged against an API with authentication and one without. If your app gets a login page later, getToken() is the only function in this file that changes.
