Finding Things Like a User

getBy, queryBy and findBy, and why tests look for roles and text instead of class names.

After render(<HomePage />), the test has to find things on the page. Testing Library's screen object has a set of queries for that, and their names follow a pattern: how they behave, then what they search by.

How: getBy, queryBy, findBy

Query If it finds it If it doesn't Use it when
getBy... returns it fails the test straight away it should already be there
queryBy... returns it returns null checking something is not there
findBy... returns it (in a promise, so await it) keeps trying for up to a second, then fails it appears later, e.g. after a fake request 
// it's there straight away: the loading message
expect(screen.getByRole('status')).toHaveTextContent('Connecting');

// it appears after the fake getWelcome() resolves
expect(await screen.findByText('Hello world!')).toBeInTheDocument();

// it should not be there at all
expect(screen.queryByRole('alert')).not.toBeInTheDocument();

Forgetting await before a findBy is the most common mistake. The test then checks a promise instead of an element, and the result is confusing.

What: by role, text or label

Query ends in Finds Example
ByRole an element by what it is getByRole('heading', { level: 1, name: 'Welcome' })
ByText an element by the text it shows findByText('Hello world!')
ByLabelText a form input by its <label> getByLabelText('Email')

ByRole is the first choice. It finds elements the way a screen reader does (topic 07): a heading, a link, a navigation, a status. The name option is the element's accessible name, usually its text. If a test can't find a button by role, often a screen reader user can't either. So these tests check accessibility as well.

Not by class name

You could find the error with document.querySelector('.error-message'). Don't. A user can't see class names. If someone renamed the class, the page would look and work exactly the same, but the test would fail. A test should only fail when something the user notices is broken.

The checks: jest-dom

Check Passes when
toBeInTheDocument() the element is on the page
toHaveTextContent('...') the element's text contains this
toHaveAttribute('href', '/') the element has this attribute and value
