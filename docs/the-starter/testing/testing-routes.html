Testing Routes

MemoryRouter starts the app at any URL, so a test can check which page shows where.

App.test.jsx checks the route table: does each URL show the right page?

There's a problem. In the real app, <BrowserRouter> (in main.jsx) reads the browser's address bar. A test has no address bar, so it uses MemoryRouter instead: a router that keeps the URL in memory and starts at whatever URL you give it.

// Figure 0.31: starting the app at a URL (src/App.test.jsx, excerpt)
vi.mock('./api/welcome.api.js');

function renderAppAt(url) {
  render(
    <MemoryRouter initialEntries={[url]}>
      <App />
    </MemoryRouter>,
  );
}

describe('App routes', () => {
  it('shows the not found page for an unknown URL', () => {
    renderAppAt('/no-such-page');

    expect(
      screen.getByRole('heading', { level: 1, name: 'Page not found' }),
    ).toBeInTheDocument();
  });

(The expect is split over three lines here to fit the page.)

  • initialEntries={[url]} is the list of URLs the router starts with. One URL means "start here".
  • renderAppAt is a small helper, so each test is one line of set-up instead of five.
  • vi.mock('./api/welcome.api.js') is needed even in a routing test. At /, App shows HomePage, which calls getWelcome(). Without the fake, the test would try to reach a real API.

The file's three tests check that / shows the home page, that an unknown URL shows the not-found page, and that the navigation appears on every page.

Try it

  1. Make a test fail on purpose. In NotFoundPage.jsx, change the heading to "Not found". Run npm test. Read the failure message: which test failed, what did it look for, and what did it find instead? Change it back.
  2. Write a test. Add a test to HomePage.test.jsx that checks the page shows no error while it's still loading. (You'll need queryByRole.)
  3. Watch mode. Run npm run test:watch, then edit and save a test. What happens?
