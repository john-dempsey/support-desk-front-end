Testing the Client With a Fake fetch

Replacing the browser's fetch() with a fake, so client.js can be tested without a back-end, including the failures that are hard to cause for real.

client.js calls fetch(). To test it, you could start the API and send real requests, but then the tests would fail whenever the API was down, and some cases (a 400 with details, a network failure) would be awkward to cause on purpose.

Instead, the test replaces fetch() with a fake that answers however the test wants. The starter has a small helper for that:

// Figure 0.28: a fake fetch() (src/api/client.test.js, excerpt)
function fakeFetchResponding(status, body) {
  const fakeFetch = vi.fn().mockResolvedValue({
    ok: status >= 200 && status < 300,
    status,
    json: async () => body,
  });
  vi.stubGlobal('fetch', fakeFetch);
  return fakeFetch;
}
  • vi.fn() makes a fake function, like jest.fn() in the back-end's service tests. .mockResolvedValue(...) makes it return a promise of that value, as the real fetch() would.
  • The value is a pretend response with only the three things apiRequest() reads: ok, status and json().
  • vi.stubGlobal('fetch', fakeFetch) swaps the browser's fetch for the fake, for this test only. unstubGlobals in the settings puts the real one back afterwards.
  • It returns the fake, so the test can check how it was called.

Two of the tests

// Figure 0.29: two client tests (src/api/client.test.js, excerpt)
it('calls the API base URL with the given path', async () => {
  const fakeFetch = fakeFetchResponding(200, { data: {} });

  await apiRequest('/welcome');

  const requestedUrl = fakeFetch.mock.calls[0][0];
  expect(requestedUrl).toBe('http://localhost:3000/welcome');
});

it('throws a helpful message when the API cannot be reached', async () => {
  vi.stubGlobal(
    'fetch',
    vi.fn().mockRejectedValue(new TypeError('Failed to fetch')),
  );

  await expect(apiRequest('/welcome')).rejects.toMatchObject({
    status: 0,
    message: expect.stringContaining("Can't reach the API"),
  });
});

(These two tests sit inside the file's describe, so they're indented one level further there. The vi.stubGlobal call is one line in the file, split here to fit.)

Each test has the same three parts, separated by blank lines: set up the fake, do the thing being tested, check the result.

  • fakeFetch.mock.calls records every call to the fake. [0][0] is the first call's first argument: the URL.
  • The second test makes fetch() reject, which is exactly what happens when the API isn't running (topic 05). No need to stop a real server.
  • await expect(...).rejects checks that a promise fails. toMatchObject checks the error has at least these properties.

The file has seven tests in all: success, the URL, a JSON body, no Authorization header without a token, 204, an error envelope, and a network failure. Between them they cover every path through apiRequest().
