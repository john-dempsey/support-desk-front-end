Testing a Page With a Fake API

Replacing a whole API module with fakes, so a page test controls exactly what "the API" says.

HomePage gets its data from getWelcome(). A test of the page needs to control what getWelcome() gives back, so it can check the page shows the message, the loading state and the error.

This time the test doesn't fake fetch(). It fakes the whole API module:

// Figure 0.30: faking an API module (src/pages/HomePage.test.jsx, excerpt)
import HomePage from './HomePage.jsx';
import { getWelcome } from '../api/welcome.api.js';

vi.mock('../api/welcome.api.js');

describe('HomePage', () => {
  it("shows the API's welcome message", async () => {
    getWelcome.mockResolvedValue({ message: 'Hello world!' });

    render(<HomePage />);

    expect(await screen.findByText('Hello world!')).toBeInTheDocument();
  });

vi.mock('../api/welcome.api.js') replaces every function that file exports with a vi.fn() fake. HomePage still imports getWelcome and calls it as normal, but it gets the fake. Vitest moves vi.mock to the top of the file before anything runs, so the order of the lines doesn't matter. (In the back-end, jest.unstable_mockModule did the same job, but needed an await import(...) afterwards. vi.mock doesn't.)

Each test then tells the fake what to do, and mockReset in the settings wipes that before the next test.

Three answers, three tests

The test wants It tells the fake The page should show
success getWelcome.mockResolvedValue({ message: 'Hello world!' }) the message
still waiting getWelcome.mockReturnValue(new Promise(() => {})) the loading message
failure getWelcome.mockRejectedValue(new Error("Can't reach the API")) the error

The middle one is a neat trick: a promise that never settles keeps the page waiting forever, so the test can look at the loading state without racing against it.

Why fake the module, not fetch()?

Because of the layers from topic 05. HomePage doesn't know about fetch(), URLs or JSON. It knows "I call getWelcome(), and I get data or an error". Its test should work at the same level. If client.js changed how it sends requests, the page tests wouldn't need to change at all. client.test.js already covers that layer.

The rule: page tests fake the API modules; only client.test.js fakes fetch().
