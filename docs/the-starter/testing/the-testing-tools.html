The Testing Tools

Vitest runs the tests, jsdom pretends to be a browser, and Testing Library looks at the page the way a user would.

You tested the back-end with Jest. The front-end's tests look almost the same (describe, it, expect), but they need a few more tools, because they test things that normally only happen in a browser.

Tool Its job Back-end equivalent
Vitest finds and runs the tests (describe, it, expect, vi) Jest (jest becomes vi)
jsdom a pretend browser: document, window and HTML elements, inside Node none needed: the back-end had no browser
React Testing Library puts a component on that pretend page, and finds things on it Supertest, which sent pretend requests to the API
jest-dom extra checks such as toBeInTheDocument() none

Vitest is built on Vite, so it understands JSX and import.meta.env with no extra setup. (Jest would need extra configuration for both.)

The settings

Vitest reads the test section of vite.config.js, the part topic 02 left out:

// Figure 0.26: the test settings (vite.config.js, excerpt)
  test: {
    environment: 'jsdom',
    setupFiles: './src/test/setup.js',
    unstubGlobals: true,
    mockReset: true,
  },
  • environment: 'jsdom' gives every test the pretend browser.
  • setupFiles runs setup.js (below) before each test file.
  • unstubGlobals and mockReset undo every fake after each test, so one test can't leak into the next. The next two slides show the fakes they undo.
// Figure 0.27: before every test file (src/test/setup.js)
import { afterEach } from 'vitest';
import { cleanup } from '@testing-library/react';
import '@testing-library/jest-dom/vitest';

afterEach(() => {
  cleanup();
});

The import adds jest-dom's checks to expect. cleanup() removes whatever the last test put on the pretend page, so every test starts with an empty one.

Running the tests

npm test               # run every test once
npm run test:watch     # re-run the tests every time you save; q to quit

A passing run of the starter ends like this:

 Test Files  3 passed (3)
      Tests  13 passed (13)

Test files sit next to the file they test, with .test in the name: HomePage.jsx and HomePage.test.jsx. You never need to tell Vitest where they are.
