Tracing a Click

One click followed through every layer of the starter: the skill the viva asks for.

In your viva, you'll be asked to trace a click through your own code, with no notes and no AI: which component, which API function, which HTTP request, which state change, and what is re-rendered. The starter is small enough to practise on now.

Here's one click, all the way through. You're on http://localhost:5173/no-such-page, and you click Go to the home page:

It's the page-load trace from topic 06, starting one step earlier: with a <Link> (topic 04) instead of typing the URL. Notice that step 1 sends no request. The only request is step 6, and it's for data, not for a page.

Questions to practise with

Answer these out loud, with the code open. Then try them again with it closed.

  1. When the link is clicked, why doesn't the browser load a new page? Which component makes that happen?
  2. How does the app know to show HomePage and not NotFoundPage? Which file would you open to check?
  3. Why is "Connecting to the API…" on screen before the request is even sent?
  4. Why is the request made inside useEffect, and not in the body of HomePage? What does the [] do?
  5. HomePage calls getWelcome(), not fetch(). Name two things client.js does that HomePage doesn't have to know about.
  6. The API sends { "data": { "message": "Hello world!" } }. Which function removes the data wrapper?
  7. Which two setters run when the answer arrives? What makes the message appear after they run?
  8. The API is stopped. Follow the same click. At which step does it go differently, and what does the user see?
