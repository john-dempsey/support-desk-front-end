package.json for a Front-End

The same file you know from the back-end, but dependencies now means "code that's sent to the browser".

You've already met package.json in the back-end (its Figure 1.1). Figure 0.1 is the first half of the front-end's:

// Figure 0.1: scripts and dependencies (package.json, excerpt)
{
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "lint": "oxlint",
    "test": "vitest run",
    "test:watch": "vitest"
  },
  "dependencies": {
    "react": "^19.3.0",
    "react-dom": "^19.3.0",
    "react-router": "^8.4.0"
  },

and Figure 0.2 is the rest:

// Figure 0.2: development tools (package.json, excerpt)
  "devDependencies": {
    "@testing-library/jest-dom": "^7.0.1",
    "@testing-library/react": "^16.3.3",
    "@testing-library/user-event": "^14.6.7",
    "@vitejs/plugin-react": "^6.1.2",
    "jsdom": "^30.1.2",
    "oxlint": "^1.81.0",
    "vite": "^8.3.4",
    "vitest": "^5.0.3"
  }
}

"type": "module", the ^ version ranges and npm run <name> all work exactly as they did in the back-end.

dependencies vs devDependencies

The split means something slightly different here, and it's worth getting right:

  • dependencies are libraries your app's own code imports. When you run npm run build, they're bundled in with your code and sent to every user's browser. There are only three:
    • react: components, state and the other building blocks
    • react-dom: puts those components into a web page. It's separate from react because React can also draw to other places, such as phone apps (React Native).
    • react-router: shows a different page for each URL
  • devDependencies are tools that only ever run on your machine: Vite and its React plugin, the linter (oxlint), and the test tools (vitest, jsdom and the three Testing Library packages). None of them reaches the browser.

So adding a dependency here has a cost the back-end didn't have: every user downloads it. That's one reason this module keeps the list short.

The scripts

Command What it runs Used for
npm run dev vite the dev server, while you work
npm run build vite build the production files in dist/
npm run preview vite preview serving dist/ locally to check the build
npm run lint oxlint checking for common mistakes
npm test vitest run running every test once
npm run test:watch vitest re-running tests each time you save

npm test, like npm start, is a special case that doesn't need run.
