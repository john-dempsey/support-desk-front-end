vite.config.js

Vite's settings: the React plugin, and a fixed port so the front-end and API never collide.

Vite works with no settings at all, but this project needs to change two things. Figure 0.3 is vite.config.js, with its comments and the test settings left out:

// Figure 0.3: Vite's settings (vite.config.js, excerpt)
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vitest/config';

export default defineConfig({
  plugins: [react()],
  server: {
    port: 5173,
    strictPort: true,
  },
  test: {
    // ... settings for the tests
  },
});

The file exports one settings object. defineConfig() doesn't change the object; it just lets your editor know what settings are allowed, so it can autocomplete them and spot typos.

plugins: [react()]

On its own, Vite knows about JavaScript, CSS and HTML, but not JSX. The React plugin teaches it two things:

  • how to translate JSX into plain JavaScript
  • how to update a component that changed without reloading the page, so the rest of the page keeps its state. This is the React version of the hot module replacement from the first slide, called Fast Refresh.

server.port and strictPort

5173 is Vite's default port anyway. It's written out here for two reasons. It makes the port obvious to anyone reading the file. More importantly, strictPort: true changes what happens if 5173 is already in use (for example, if you forgot to stop another project's dev server). Without it, Vite quietly moves to 5174, and you end up looking at the wrong app in the browser. With it, Vite stops with an error that tells you the port is taken.

The API has 3000, so the two never clash.

The test section

The same file also holds the settings for Vitest, the test runner. That's why defineConfig is imported from 'vitest/config' instead of 'vite': Vitest's version understands the test section as well. Vite itself ignores that section. The settings inside it are explained in the testing topic.
