What Vite Does

Why a front-end needs a build tool at all, and the two jobs Vite does: a dev server while you work, and a build when you're done.

In the back-end, Node ran your .js files exactly as you wrote them: node src/server.js, and that was it. A front-end can't work that way, for three reasons:

  1. Browsers don't understand everything you'll write. React components are written in JSX, HTML-like markup inside JavaScript (the next topic introduces it). No browser can run JSX as it is. It has to be turned into plain JavaScript first.
  2. Browsers don't know about node_modules. In Node, import { useState } from 'react' works because Node knows to look in node_modules/react. A browser sees 'react' and has no idea where to find it.
  3. Lots of small files load slowly. Your app will grow to dozens of files, plus the libraries they import. Sending each one to every user separately would make the first page load slow.

Vite (French for "quick", pronounced veet) is the tool that deals with all three. It has two jobs.

Job 1: the dev server (npm run dev)

While you're working, Vite runs a small web server on port 5173. When the browser asks for a file, Vite translates it on the spot (JSX into JavaScript, 'react' into a real path) and sends the result.

When you save a file, Vite tells the browser straight away, and only the part of the page that changed is updated. You don't press refresh, and anything you'd typed into a form is usually still there. This is called hot module replacement (HMR). It's the front-end version of the back-end's node --watch, but it updates the page in place instead of restarting everything.

Job 2: the build (npm run build)

When the app is ready to deploy, npm run build translates every file once and bundles them into a few small, optimised files in a dist/ folder. Those are plain HTML, CSS and JavaScript files that any web server can host, with no Vite and no Node needed. That's covered at the end of this lesson.

Have you seen Vite before?

Possibly. Recent versions of Laravel use Vite to bundle CSS and JavaScript. If your Year 2 project had a vite.config.js and an @vite(...) directive in a Blade layout, you were already running Vite with npm run dev. The difference is what it bundles: there, a little JavaScript added to pages the server built; here, the whole app.
