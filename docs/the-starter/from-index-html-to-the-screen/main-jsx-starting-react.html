main.jsx: Starting React

The file index.html loads: it finds the empty div, and hands it to React.

Back to the <script> tag in index.html, which loads src/main.jsx. Here it is:

// Figure 0.10: the entry point (src/main.jsx)
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import { BrowserRouter } from 'react-router';
import App from './App.jsx';
import './index.css';

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </StrictMode>,
);

It's the front-end's version of the back-end's server.js: a short file whose only job is to start everything. The last statement does the work, in two steps:

  1. createRoot(document.getElementById('root')). You've used document.getElementById in plain JavaScript. It finds the empty <div id="root"> from index.html. createRoot (from react-dom, the package that connects React to web pages) tells React to take charge of that <div>.
  2. .render(...) tells React what to show there. React calls the components, turns what they return into real HTML elements, and puts them inside the <div>.

From now on, React owns everything inside <div id="root">. Your code never adds or removes elements there directly. You change data, and React updates the page to match (more on that in a later topic).

What gets rendered

<App /> is the app's top component, and the rest of the app is inside it. It's wrapped in two components that add features rather than markup:

  • <StrictMode> turns on extra checks that help find mistakes. They only run while you develop, never in the built app. One of them makes React do some work twice on purpose, which you'll come back to later.
  • <BrowserRouter> connects the app to the browser's address bar, so any component inside it can find out the current URL and change it. That's what the routing topic builds on.

Wrapping a component like this is how React adds a feature to everything inside it: all of App gets both.

import './index.css'

This import doesn't give you anything to use: it's there for its side effect, like the back-end's import 'dotenv/config'. Vite sees a CSS file being imported and adds the stylesheet to the page. That's how the app's global styles get loaded without a <link> tag in index.html.
