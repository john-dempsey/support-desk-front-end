Props: Passing Data In

Attributes on a component become an object passed to its function, so one component can show different things in different places.

A component that always shows the same thing isn't very reusable. The starter's ErrorMessage shows whatever error it's given:

// Figure 0.8: a component with a prop (src/components/ErrorMessage.jsx)
function ErrorMessage({ message }) {
  return (
    <p role="alert" className="error-message">
      {message}
    </p>
  );
}

export default ErrorMessage;

And this is how another component uses it:

<ErrorMessage message="Can't reach the API" />

How it works

When React meets <ErrorMessage message="..." />, it collects the attributes into one object and passes it to the function:

ErrorMessage({ message: "Can't reach the API" })

That object is called props (short for properties). The function could take it as one parameter and read props.message:

function ErrorMessage(props) {
  return <p className="error-message">{props.message}</p>;
}

The starter uses destructuring in the parameter list instead: { message } pulls the message property out of the props object straight away. It's the same destructuring you used on req.body in the back-end (const { subject, description } = req.body), just written where the parameter goes. It also lists, right at the top, every prop the component expects.

(role="alert" is for screen readers. It's explained in the accessibility topic.)

Strings and everything else

<ErrorMessage message="Can't reach the API" />   // a fixed string: quotes
<ErrorMessage message={errorMessage} />           // a variable: braces

Quotes pass a plain string. For anything else (a variable, a number, an object) use { }, just like anywhere else in JSX.

Default values

Loading has a prop that's optional:

// Figure 0.9: a prop with a default (src/components/Loading.jsx, excerpt)
function Loading({ message = 'Loading…' }) {
  return (
    <p role="status" className="loading">
      {message}
    </p>
  );
}

= 'Loading…' is a default value, the same as for any JavaScript parameter. <Loading /> shows "Loading…", and <Loading message="Connecting to the API…" /> shows that message instead.

Props are read-only

A component reads its props and never changes them. The component that passes a prop owns that value. If the value needs to change, the owner changes it, and React calls the component again with the new props. That's how data flows in React: down, from parent to child.

Compared with Blade

Props are like the array you passed to a partial, or the attributes on a Blade component:

@include('partials.error', ['message' => $error])
<x-error-message :message="$error" />

Even the default value has a Blade equivalent: @props(['message' => 'Loading…']).
