JSX Is Almost HTML

What JSX really is, how to put JavaScript values into it, and the handful of places it differs from HTML.

JSX looks like HTML, but it's really a shorter way to write JavaScript. Before the browser sees it, Vite translates each tag into a function call. Roughly:

// What you write
<h1 className="title">Hello</h1>

// What Vite turns it into (simplified)
jsx('h1', { className: 'title', children: 'Hello' })

That call creates a small object describing the element. React uses those objects to build the real page. You'll never write the function call version yourself, but knowing it's there explains the rules below.

Putting values in: { }

Curly braces switch from markup back to JavaScript. Whatever is inside is worked out, and the result is shown:

const ticketCount = 3;

return <p>You have {ticketCount} open tickets.</p>;

This is Blade's {{ $ticketCount }} with one pair of braces instead of two. Like Blade's {{ }}, JSX escapes what it shows: if a value contains <script>, it appears as text instead of running. You get protection against XSS without doing anything.

Anything that produces a value works inside { }: a variable, ticket.subject, count + 1, a function call. An if statement or a for loop doesn't, because they don't produce a value. Later topics show how to make decisions and repeat things in JSX.

Where JSX differs from HTML

HTML JSX Why
class="loading" className="loading" class is a reserved word in JavaScript, so JSX uses the browser's own JavaScript name for it
<label for="email"> <label htmlFor="email"> same reason: for is a JavaScript keyword
<br>, <img ...> <br />, <img ... /> every tag must be closed, including components: <Greeting />
<!-- comment --> {/* comment */} a JavaScript comment inside { }
several elements side by side one parent around them a function can only return one thing

One parent: fragments

The last rule needs a fix. A component often needs to return a heading and a paragraph side by side, but a function returns one value. Wrapping them in a <div> works, but adds an extra element to the page for no reason. Instead, use an empty tag, called a fragment:

return (
  <>
    <h1>Page not found</h1>
    <p>Sorry, there's no page at this address.</p>
  </>
);

<> and </> group the elements for JavaScript's sake, and then disappear: only the <h1> and <p> end up on the page. That's what NotFoundPage in Figure 0.7 does.
