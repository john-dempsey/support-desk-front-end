A Tree of Components

Components contain components. Seeing the whole tree makes it clear where every part of the page comes from.

main.jsx renders App. App renders more components, and they render others. The result is a tree. This is the starter's tree on the home page:

<div id="root">                (index.html)
└── StrictMode                 (main.jsx)
    └── BrowserRouter          (main.jsx)
        └── App                (App.jsx)
            ├── NavBar         ← shown on every page
            └── <main>
                └── HomePage   ← changes with the URL
                    ├── Loading        while waiting for the API
                    └── ErrorMessage   if something went wrong

Each component only knows about the ones directly inside it. HomePage uses Loading and ErrorMessage without knowing or caring where HomePage itself sits. That's what makes a component reusable: the same ErrorMessage can go into any page.

Data flows down this tree as props. HomePage decides what the error message is and passes it to ErrorMessage, which just displays it.

Compared with Blade layouts

App does the same job as a Blade layout. In Laravel, a page said @extends('layouts.app'), and the layout had the shared navigation plus a @yield('content') where the page went. Here, App contains NavBar and a <main>, and the page for the current URL goes inside <main> (the routing topic shows how).

The difference is the direction. In Blade, the page picks its layout. In React, the parent decides which children to show.

Try it: see the tree

Install the React Developer Tools browser extension (it's free, for Chrome, Edge and Firefox). Open the app, open the developer tools, and choose the new Components tab.

  1. Find HomePage in the tree. Click on ErrorMessage or Loading (if it's showing) and look at its props in the right-hand panel.
  2. Compare the tree with the Elements tab. Which components appear as HTML elements there, and which leave no trace at all? (Hint: StrictMode, BrowserRouter and the <> fragments.)
