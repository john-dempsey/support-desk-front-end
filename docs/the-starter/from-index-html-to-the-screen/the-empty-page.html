The Empty Page

The only HTML file in the app has almost nothing in it. Everything you see is added by JavaScript.

A single-page application has exactly one HTML page. Figure 0.6 is all of it:

<!-- Figure 0.6: the app's only HTML page (index.html) -->
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <link rel="icon" type="image/svg+xml" href="/favicon.svg" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <!-- TODO (your case study): change the title to your app's name. -->
    <title>My App</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>

Look at the <body>. There's no heading, no navigation, no text. Just:

  • an empty <div> with the id root
  • a <script> that loads src/main.jsx

Compare that with a page from your Laravel app. When the browser asked for /tickets, the server ran Blade and sent back a <body> already full of headings, tables and links. Here the server (Vite, while you develop) sends this nearly-empty page for every URL. The JavaScript in main.jsx then builds the whole page inside <div id="root">, in the browser.

type="module" tells the browser the script uses import/export, the same ES modules you used in the back-end.

Try it

Run the app and open http://localhost:5173. Then compare two views of the same page:

  1. View Page Source (right-click, or Ctrl+U). This is the HTML the server sent. What's inside <div id="root">? (You'll also see one or two extra <script> tags that Vite adds while you develop, for updating the page when you save. They aren't part of your app.)
  2. Inspect (right-click on the heading, or F12, then the Elements tab). This is the page as it is now, after JavaScript has run. What's inside <div id="root"> this time?

The difference between the two is everything React added. The rest of this topic is about how.
