The Route Table

App.jsx maps each URL to a component, the way routes/index.js mapped each URI to a controller.

In the back-end, a route connected a URI to the code that handled it (this is ticket.routes.js, mounted at /tickets, with its validation left out):

router.get('/', ticketController.getAllTickets);

and in Laravel, routes/web.php did the same:

Route::get('/tickets', [TicketController::class, 'index']);

The front-end needs the same idea: which URL shows which page? In React, that's done by React Router, and the whole table lives in App.jsx:

// Figure 0.11: the route table (src/App.jsx, comments removed)
import { Route, Routes } from 'react-router';
import NavBar from './components/NavBar.jsx';
import HomePage from './pages/HomePage.jsx';
import NotFoundPage from './pages/NotFoundPage.jsx';

function App() {
  return (
    <>
      <NavBar />
      <main className="container">
        <Routes>
          <Route path="/" element={<HomePage />} />
          <Route path="*" element={<NotFoundPage />} />
        </Routes>
      </main>
    </>
  );
}

export default App;

Reading it

  • Each <Route> pairs a path with an element: the component to show when the URL matches. element={<HomePage />} is an ordinary prop (topic 03), passed with { } because its value is JSX, not a string.
  • <Routes> looks at the current URL, finds the route that matches it, and shows only that route's element. The others aren't shown at all.
  • Routing is done with components, not a separate config file, so Routes and Route are imported and used like any other component.

Where the routes sit

<NavBar /> is outside <Routes>, so it appears on every page. <Routes> is inside <main>, so whichever page matches is shown there. This is the Blade layout from the last topic, made concrete: App is the layout, and <Routes> is its @yield('content').

No server involved

This is the biggest difference from the back-end. An Express route runs when an HTTP request arrives at the server. React Router runs in the browser: it reads the address bar (that's what <BrowserRouter> in main.jsx makes possible) and picks a component. Moving between pages doesn't send a request to anyone. The next slide shows how.

One place for every page

In your viva you'll be asked to trace a click through your code. The route table is where that trace starts: from a URL, it tells you which page component to open next. Keep every route in this one file, as the back-end kept every router in routes/index.js.
