The Catch-All Route

path="*" shows a not-found page for any URL the app doesn't have, like the back-end's notFound middleware.

The second route in App.jsx (Figure 0.11) is:

<Route path="*" element={<NotFoundPage />} />

* matches any URL. So when no other route fits, the user sees NotFoundPage instead of a blank space. It's the front-end's version of the back-end's middleware/notFound.js:

export default (req, res, next) => {
  res.status(404).json({
    error: { message: `Not found: ${req.method} ${req.originalUrl}` },
  });
};

Order doesn't matter (but keep it last)

In Express, notFound had to be registered after every route. Express tries each one in order and stops at the first match, so a catch-all at the top would have caught everything.

React Router works differently. It compares every route with the URL and picks the most specific match. / is more specific than *, so / wins at the home page wherever the two routes are written. * only wins when nothing else matches at all. The starter still puts it last, because a table that reads from most specific to least is easier to follow.

Who answers a URL that doesn't exist?

Type http://localhost:5173/no-such-page into the address bar and press Enter. This time it's a real request to the server (Vite), because you typed the URL yourself instead of clicking a <Link>. Here's what happens:

  1. Vite has no file called no-such-page. Instead of a 404, it sends back index.html, the same page it sends for every URL.
  2. The browser runs main.jsx, and React starts.
  3. React Router reads /no-such-page from the address bar, finds no route but *, and shows NotFoundPage.

So the "not found" message comes from React, not from the server. The HTTP status of that request was 200 OK: as far as Vite is concerned, it successfully sent index.html. Only the app knows the page doesn't exist.

Sending index.html for every URL is called a fallback, and it's what makes a single-page app work at all. Without it, refreshing on any page except / would show the server's own error. Vite's dev server does it for you. When the app is deployed on a different server, that server must be set up to do it too, which comes up again when the app is built for production.

Try it

With the Network tab open, go to http://localhost:5173/no-such-page. Find the document request. What status does it have? Now compare it with the request the back-end gets: open http://localhost:3000/no-such-page. What status and body does the API send?
