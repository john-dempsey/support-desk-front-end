What Runs Where

Two projects, two terminals, two ports, and a browser that talks to both.

While you develop, three programs work together:

  1. The API, on http://localhost:3000. This is the Support Desk API you built, started with npm run dev in its own folder. It talks to MySQL and sends back JSON.
  2. The Vite dev server, on http://localhost:5173. Vite is the tool that runs the front-end while you work on it. It's also started with npm run dev, but in the front-end's folder. Its job is to send the front-end's files (one HTML page, plus your JavaScript and CSS) to the browser, and to refresh the browser whenever you save a file.
  3. The browser. It loads the page from Vite, then runs your React code. When that code needs data, the browser sends a request straight to the API on port 3000.

Notice what's missing: Vite never talks to the API. Once the browser has the front-end's files, every request for data goes directly from the browser to the API. That's why the API has to be running for the front-end to show any data, and why the front-end needs to know the API's address (you'll see where that's set in the toolchain topic).

Two terminals

So in practice you'll have two terminals open, one for each project:

# Terminal 1: the API (in your back-end folder)
npm run dev        # API on http://localhost:3000

# Terminal 2: the front-end (in your front-end folder)
npm run dev        # front-end on http://localhost:5173

Both commands are called npm run dev, so check which folder you're in. Each project's package.json decides what its own dev script does.

Then open http://localhost:5173 in the browser, not port 3000. Port 3000 is the API, which only ever answers with JSON.

Laravel comparison

In Laravel, php artisan serve did all of this in one process: it served the pages and ran the code that read the database. Here those jobs are split between two programs. The browser is the only thing that connects them.
