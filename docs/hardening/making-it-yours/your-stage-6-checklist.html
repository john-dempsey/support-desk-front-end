Your Stage 6 Checklist

The same hardening for your own case study: one hook for loading data, an error boundary, titles, a skip link and a caption, a coverage report, a build, and optionally nginx.

For every app, whatever stage it reached. Steps 1 to 6 need nothing from your API beyond what your pages already use (topic 01). Step 7 needs Docker, and step 8 your own back-end.

Do the steps in this order. Run npm test and npm run lint, and try the app in the browser after every step, and commit when all three are happy. Stage 6 adds no features, so nothing the user can do should change.

1. useFetch

Copy src/hooks/useFetch.js (Figures 6.2 to 6.5); it has nothing Support Desk in it. Add its tests (Figures 6.6 to 6.8) before you move any page onto it, so you know the hook works on its own.

2. Your pages, one at a time

Use the list of pages you made in topic 01's Try it. For each page: replace its useState and fetch effect with one useFetch call per request (Figures 6.10 and 6.12), renaming data as you unpack it (Figure 6.9). Keep setData for changes after a create or delete, with the function form after an await (Figure 6.14). Run that page's tests before moving on to the next page: they should pass unchanged.

3. An error boundary

ErrorBoundary.jsx (Figures 6.18, 6.19 and 6.21), around your <Routes>, inside <main>, with key={location.pathname} (Figure 6.20). Check it with a deliberate crash, then take the crash out. Tests: Figures 6.22 and 6.23.

4. The accessibility pass

  • PageTitle (Figure 6.24) on every page, including the not-found page and each page's error states (Figure 6.25).
  • A skip link. The template doesn't have one: add the link to App.jsx, id="main-content" to <main> (Figure 6.26), and its styles to index.css (Figure 6.27).
  • A <caption> on every table, with .visually-hidden if it would repeat the heading (Figures 6.28 and 6.29).
  • Tab through every page with the keyboard only.
  • Tests: Figures 6.30 to 6.32.

5. Coverage

npm install --save-dev @vitest/coverage-v8, the coverage script, coverage in .gitignore, and include/exclude in vite.config.js (Figure 6.33). Run npm run coverage. Look for whole files, or whole functions, that no test runs, and test those first. Remember that 100% isn't the goal.

6. The build

npm run build, then npm run preview. Log in (if your app has a login), load every page, refresh on a deep URL, and check the console is empty. Search the built .js file for your API's address.

7. nginx (optional)

Copy Dockerfile, nginx.conf, .dockerignore and compose.yaml (Figures 6.39 to 6.44). Change the stack's name in compose.yaml, and the port if 8080 is taken. Make sure every comment in your .env starts with #. Run docker compose up -d --build, then check a refresh on a deep URL works.

8. CORS (your own back-end)

Pin both CORS settings to your front-end's origins (topic 09's snippets). Check each origin you use still works, and that one you haven't listed gets the console error.
