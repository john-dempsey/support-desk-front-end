Tracing Stage 6

Questions to practise the viva's trace with, now that the fetching lives in a hook, crashes have a boundary, and the app can run from nginx.

The viva's trace is still component → API module → HTTP request → state update → re-render. Stage 6 moved one part of it: the state update now happens inside useFetch, so a trace through a page passes through the hook. And there are two new kinds of question: what happens when something goes wrong, and what happens before React runs at all.

Write one yourself

Write the trace for choosing "Open" in the Status filter on the ticket list, as a numbered list, one line per step, with the file each step is in. Start with the onChange in TicketFilters, and finish with the filtered tickets in the table. You should need about ten steps, and at least four of them are in useFetch.js. Topic 02's diagrams and topic 03's Figures 6.10 and 6.11 cover most of it.

Questions to practise with

Answer these out loud, with the code open. Then try them again with it closed.

  1. Name the five pages that use useFetch. Which two call it twice, and why two calls rather than one?
  2. Two pages call useFetch at the same time. Do they share data? Why not, when a context's value is shared?
  3. What are the three things in the effect's dependency list, and what makes each one change?
  4. Why does the page pass getTicket, id to the hook, and not () => getTicket(id)?
  5. A slow answer for ticket 1 arrives after the answer for ticket 2. Which line stops it from replacing ticket 2?
  6. What does reload() change, and why does that load the data again?
  7. After adding a comment, the page calls setComments with a function. Why a function, and why not reload the comments instead?
  8. Why does TagsPage keep its own reloadTags()?
  9. A page throws while rendering. Which method in ErrorBoundary runs first, and what does render() show? What does the user still see at the top of the page?
  10. The user then clicks Tickets. Why does the list appear, rather than "Something went wrong" again?
  11. Name two errors the boundary doesn't catch. What handles them instead?
  12. Where does the browser tab's title come from on the ticket's page? What does it say while the ticket is loading?
  13. You reload http://localhost:8080/tickets/3. Which program answers first, what does it send, and how does the ticket's page appear?
  14. You change VITE_API_URL in .env. What has to happen before the app on port 8080 uses the new address, and why?

Try it

Pick two questions you couldn't answer with the code closed. Find the answers in the code, then explain each to someone else without looking.
