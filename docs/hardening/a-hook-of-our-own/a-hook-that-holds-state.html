A Hook That Holds State

useAuth() was a custom hook that shares one value. useFetch is a custom hook that calls useState, so every page that calls it gets its own.

You met custom hooks in Stage 4: a function of your own whose name starts with use and which calls other hooks. useAuth() and useNotifications() are both one line, a call to useContext().

useFetch is a custom hook too. It lives in src/hooks/, the folder Stage 0's hooks/README.md kept for it, and it's a named export, like the functions in src/utils/:

import { useFetch } from '../hooks/useFetch.js';

Its state belongs to whoever calls it

The difference is what's inside. useFetch calls useState and useEffect, and a hook called inside a hook belongs to the component that called it. React treats it as if those lines were written in the page itself.

So every page that calls useFetch gets its own data, its own error and its own "still loading?". Calling it twice gives two separate sets. Only the code is shared.

That's the opposite of a context. useAuth() hands every component the same user, which is why logging out updates the navigation bar and the page together. A hook like useFetch shares how to do something, not a value.

If you've used a PHP trait in Laravel (HasFactory, Notifiable), it's a similar idea: every class that uses a trait gets the trait's methods, but each object still has its own properties.

Why the name must start with use

React's rules for hooks (call them at the top of a component, never inside an if, a loop or a handler) apply inside a custom hook too. The linter can only check them if it knows a function is a hook, and the use at the start of the name is how it knows.

Try it

In src/hooks/useFetch.js, rename the function: change export function useFetch( to export function fetchData(. Don't change anything else, and don't open the app. Run:

npm run lint

You get five errors that begin like this one (shortened here):

× react-hooks(rules-of-hooks): React Hook "useState" is called in
function "fetchData" that is neither a React function component nor a
custom React Hook function.

Why five? Count the hooks that useFetch calls. Then change the name back, and run npm run lint again to check it's clean.
