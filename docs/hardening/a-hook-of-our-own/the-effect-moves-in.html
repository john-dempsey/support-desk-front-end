The Effect Moves In

The hook's effect is the pages' effect with general names. Its dependency list is a plain array, so the linter can still check it.

The effect is the one you've written since Stage 2, line for line. Only the names have changed:

// Figure 6.3: the request (src/hooks/useFetch.js, excerpt)
  useEffect(() => {
    let ignore = false;

    async function loadData() {
      try {
        const result = await fetchFunction(argument);
        if (!ignore) {
          setData(result);
        }
      } catch (caughtError) {
        if (!ignore) {
          setError(caughtError);
        }
      } finally {
        if (!ignore) {
          setIsLoading(false);
        }
      }
    }

    loadData();

// Figure 6.4: the cleanup (src/hooks/useFetch.js, excerpt)
    return () => {
      ignore = true;
      setData(null);
      setError(null);
      setIsLoading(true);
    };
  }, [fetchFunction, argument, reloadCount]);

The comments are left out of both figures. Put them next to Figure 6.1:

Stage 5's TicketListPage useFetch
loadTickets() loadData()
await getTickets(queryString) await fetchFunction(argument)
setTickets(result.tickets) and setMeta(result.meta) setData(result): the whole result
catch (error), then setErrorMessage(error.message) catch (caughtError), then setError(caughtError)
the cleanup resets four pieces of state, and hasChanged the cleanup resets three

The catch names its error caughtError because the hook already has a piece of state called error. Giving both the same name would hide the state inside the catch block, and be confusing to read.

hasChanged isn't in the hook's cleanup: it's the list page's own state, for its "this has changed" notice, so it stays in the page.

The dependency list

[fetchFunction, argument, reloadCount] lists every value from outside the effect that it reads. It's a plain array, written out in full, so oxlint's exhaustive-deps rule (Stage 2) can check it, the same as in every page before.

  • A new argument (another ticket, another query) runs the effect again, for the new data. That's [ticketId] and [queryString] from Stages 2 and 3.
  • A new reloadCount runs it again for a Reload, as in Stage 5.
  • A new fetchFunction would run it again too. In practice a page always passes the same one, as a later slide in this topic explains.

Try it

Take argument out of the dependency list, so it reads [fetchFunction, reloadCount], and run npm run lint. The warning says:

⚠ react-hooks(exhaustive-deps): React Hook useEffect has a missing
dependency: 'argument'

(It's one line, split here to fit, and the linter shows the line that uses argument underneath.) What would go wrong on the ticket page if you ignored it, and the URL changed from /tickets/1 to /tickets/2 while the page stayed open? Put argument back.
