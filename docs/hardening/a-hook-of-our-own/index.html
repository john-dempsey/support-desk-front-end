A Hook of Our Own

The loading pattern every page has repeated since Stage 2, written once as a custom hook: useFetch.

  • The Same Effect Five Times

    Five pages each carry their own copy of the loading pattern from Stage 2. Only the request is different.

  • A Hook That Holds State

    useAuth() was a custom hook that shares one value. useFetch is a custom hook that calls useState, so every page that calls it gets its own.

  • The Hook's State

    useFetch takes an API function and the one value it needs, and holds the same state the pages held: the data, an error, and whether it's still loading.

  • The Effect Moves In

    The hook's effect is the pages' effect with general names. Its dependency list is a plain array, so the linter can still check it.

  • What It Hands Back

    useFetch returns an object of five values. A page takes the ones it needs, and can still change the data or ask again.

  • Pass the Function, Not an Arrow

    useFetch(getTicket, ticketId) loads once. useFetch(() => getTicket(ticketId)) loads forever, because an arrow written in a page is a new function on every render.

  • Testing the Hook

    renderHook() runs a hook with no page around it, so the ignore flag finally gets a test of its own.
