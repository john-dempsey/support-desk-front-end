The Hook's State

useFetch takes an API function and the one value it needs, and holds the same state the pages held: the data, an error, and whether it's still loading.

Here's how useFetch starts:

// Figure 6.2: the hook's state (src/hooks/useFetch.js, excerpt)
export function useFetch(fetchFunction, argument) {
  // null means "not loaded yet", which is different from [] ("loaded, and
  // there are none"), so a page doesn't say "There are none" too early.
  const [data, setData] = useState(null);
  const [error, setError] = useState(null);
  const [isLoading, setIsLoading] = useState(true);
  // Its only job is to be in the effect's dependency list: adding 1 makes
  // the effect run again, which is how reload() works.
  const [reloadCount, setReloadCount] = useState(0);

Two parameters

  • fetchFunction is one of the functions in src/api/, such as getTickets. The page passes the function itself, not a call to it: getTickets, not getTickets(). The hook decides when to call it.
  • argument is the one value that function needs: a ticket ID, or the list's query string. Some API functions need nothing (getTags), and then the page leaves it out.

So a page says what to load in one line:

useFetch(getTickets, queryString)   // TicketListPage
useFetch(getTags)                   // TagsPage

Four pieces of state

They're the pieces every page already had, with general names, since the hook doesn't know what it's loading:

Stage 5's TicketListPage useFetch
tickets and meta data: whatever the API function returned
errorMessage, a string error: the whole Error, or null
isLoading isLoading
reloadCount (since Stage 5) reloadCount, now inside the hook

error keeps the whole Error, not just its message. That's because some pages need more than the message. TicketDetailPage reads error.status to tell "not found" (404) apart from "the API is down" (Stage 2's "What a Status Means"). A string would lose the status.

data starts as null for the same reason Stage 2 gave: null means "not loaded yet", and [] means "loaded, and there are none".
