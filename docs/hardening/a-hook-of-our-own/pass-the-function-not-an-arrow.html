Pass the Function, Not an Arrow

useFetch(getTicket, ticketId) loads once. useFetch(() => getTicket(ticketId)) loads forever, because an arrow written in a page is a new function on every render.

There's one rule for calling useFetch, and it matters:

Pass the API function itself, never a new arrow.

This looks like it does the same thing, but don't do it:

useFetch(() => getTicket(ticketId));

Why it never stops

An arrow function written inside a component is created afresh every time the component renders. Two arrows with the same code are still two different functions, just as two {} objects are two different objects.

fetchFunction is in the effect's dependency list. So after each render, React compares the new arrow with the last one, sees a "change", and runs the effect again:

With useFetch(getTicket, ticketId), nothing changes between renders. getTicket is imported once, at the top of the file, so it's the same function every time. ticketId is a string, and '1' equals '1'. So the effect runs once, and again only when the ticket ID really changes.

Why this is dangerous, not just slow

The loop sends a real request each time round. In a test, with a pretend getTicket that answered after 10 ms, the arrow version asked about 180 times a second; the plain version asked once. The API allows 300 requests every 15 minutes from one computer, so the loop would use them all up in under two seconds, and then every page would get a 429 until the 15 minutes were up.

The linter can't catch this one. It checks the dependency lists of React's own hooks, but it doesn't know that useFetch's first argument ends up in one. That's why the rule is written at the top of useFetch.js, and why the hook takes one value, not a whole dependency list: the pages stay simple, and there's only one way to call it.

Try it

This version doesn't touch the API: the "request" is a pretend one that answers after 100 ms. In src/pages/HomePage.jsx, import useFetch and add this as the first line inside HomePage():

useFetch(() => {
  console.count('asked');
  return new Promise((resolve) => setTimeout(() => resolve('hi'), 100));
});

Open the home page with the browser's console showing. asked: climbs by about twenty a second, and never stops. Now move the arrow out of the component, as a named function above function HomePage():

function pretendRequest() {
  console.count('asked');
  return new Promise((resolve) => setTimeout(() => resolve('hi'), 100));
}

and call useFetch(pretendRequest) inside. Reload the page. It stops at asked: 2. Why 2 and not 1? (Stage 0's "Cleanup and the ignore Flag" has the answer.) Then remove both, and the import.
