Open to Every Origin

Two lines in the back-end let any website call the API from a browser. Their comments say to tighten them once the front-end's origins are known. Now they are.

This topic is mostly discussion. It's about a change to the back-end, and this course doesn't make it to the Support Desk API. The one Try it that changes anything is on your own back-end, on the next slide.

What you've seen so far

Stage 0 ("CORS From the Other Side") showed why the API needs app.use(cors()): the front-end's page and the API are on different origins, so the browser only lets the page read an answer that says it may. Stage 2 ("The Preflight") showed the browser asking first, with an OPTIONS request, before it sends a token. Every answer says the same thing:

Access-Control-Allow-Origin: *

* means any origin: any website, opened in anyone's browser, may call the API and read the answer.

Two places, not one

The API has a second, separate CORS setting. Socket.IO's first requests are ordinary HTTP requests (in Stage 5, four of the five requests it made at login were XHR), so the socket server has its own list, in config/socket.js:

cors: { origin: '*' },

Both have the same comment in the back-end: wide open for now, because there was no front-end yet, and to be tightened "once the React app's dev/prod origins are known".

They're known now

By this stage, the app runs on three origins:

Origin What it is
http://localhost:5173 npm run dev
http://localhost:4173 npm run preview (topic 07)
http://localhost:8080 nginx in Docker (topic 08)

A deployed app would add its real address, such as https://support.example.com. Every other origin, every other website, has no reason to call this API from a browser.

Try it

Open the app on port 8080 (or 4173) with the Network tab's filter on All, and log in. Click a preflight row. What does Access-Control-Allow-Origin say? Now open the back-end's app.js and config/socket.js, and find the two "wide open for now" comments.
