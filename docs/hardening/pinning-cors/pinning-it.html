Pinning It

One setting lists the front-end's origins, and both CORS settings read it. Any other origin gets a console error, and the app says it can't reach the API.

"Pinning" CORS means replacing * with the list of origins that are allowed. The list changes from one computer to another (a deployed app has its own address), so it belongs in the environment, like PORT.

This is how you'd do it in your own back-end. It's a back-end change, so it isn't made to the Support Desk API in this course.

One setting

In src/config/env.js, one more line in the schema, with a default that works for npm run dev:

  CORS_ORIGINS: z.string().min(1).default('http://localhost:5173'),

Its value is a list with commas between the origins, in .env:

CORS_ORIGINS=http://localhost:5173,http://localhost:4173,http://localhost:8080

Both places read it

split(',') turns the text into an array, and both cors() and Socket.IO accept an array of origins:

// src/app.js (with import env from './config/env.js'; at the top)
app.use(cors({ origin: env.CORS_ORIGINS.split(',') }));

// src/config/socket.js (with import env from './env.js';)
  io = new Server(httpServer, {
    cors: { origin: env.CORS_ORIGINS.split(',') },
  });

If your API runs in Docker, as in Lesson 6, the api service doesn't read .env by itself: add CORS_ORIGINS to its environment in docker-compose.yml, next to PORT, and rebuild.

What the browser shows

From an origin on the list, nothing changes. From any other origin, the answer to the preflight no longer allows it, so the browser never sends the real request. The console says, for an API pinned to http://localhost:5173 alone (reflowed here):

Access to fetch at 'http://localhost:3000/auth/login' from origin
'http://localhost:4173' has been blocked by CORS policy: Response to
preflight request doesn't pass access control check: The
'Access-Control-Allow-Origin' header has a value
'http://localhost:5173' that is not equal to the supplied origin.

(With a list, the end is different: "No 'Access-Control-Allow-Origin' header is present on the requested resource.") And the page shows the message Stage 0 warned about:

Can't reach the API at http://localhost:3000 — is the back-end running?

The API is running. fetch() was refused by the browser, so to client.js it looks exactly like no API at all. That's why the console is the first place to look.

Try it

On your own back-end, pin CORS to http://localhost:5173 only, and restart it. Check your app still works on port 5173. Then run npm run build and npm run preview, and try to log in on port 4173. Read the console error. Which request appears in your back-end's log, and which never arrives? Then add http://localhost:4173 to the list and try again.
