Lighthouse Says 100

Lighthouse gave the app 100 for accessibility before this topic and after it. Automated checks only see some problems.

Still 100. The only difference is one check that moved from "not applicable" to "passed":

Why it couldn't see the gaps

Each check answers one narrow question a program can answer:

  • "Document has a <title> element." Stage 5 had one: "Support Desk", on every page. Whether each page's title is different, and says what the page is, needs a person.
  • "Skip links are focusable." Stage 5 had no skip link, so there was nothing to check: "not applicable", not a failure. Only once there was one could Lighthouse check it.
  • A table caption: nothing in Lighthouse's report asks for one.

That's what the report means by "automatic detection can only detect a subset of issues". The ten "additional items to manually check" are Lighthouse listing what it can't judge: a logical Tab order, focus going to new content, and so on. They're the keyboard and screen reader checks from the last slide.

So treat 100 as "no problems a program can find", never as "done".

Try it

Run Lighthouse on your own app: DevTools, the Lighthouse tab, tick only Accessibility, and Analyze page load. Note the score. Then open Additional items to manually check and try two of the ten items by hand, using the keyboard list you made on the last slide.
