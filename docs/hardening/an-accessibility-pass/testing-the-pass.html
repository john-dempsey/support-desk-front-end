Testing the Pass

Each fix gets a test: document.title for the titles, the table's name for the caption, and the first link on the page for the skip link.

Each of the three fixes has a test, so it can't quietly disappear.

Titles: document.title

React moves a page's <title> into <head> in the tests too (jsdom, Stage 0's pretend browser, has a <head>). So a test reads the title the same way the browser tab does, from document.title:

// Figure 6.30: a page's title (src/pages/TicketListPage.test.jsx, excerpt)
  it('names the browser tab after the page', () => {
    getTickets.mockReturnValue(new Promise(() => {}));

    renderWithProviders(<TicketListPage />, { route: '/tickets' });

    expect(document.title).toBe('Tickets · Support Desk');
  });

Every page's test file has one of these. The ticket's page checks its title is the ticket's subject, and the error boundary's test checks "Something went wrong · Support Desk".

The caption: the table's name

A caption gives the table an accessible name, and getByRole can search by name, as it has for buttons and links since Stage 0:

// Figure 6.31: the caption (src/components/TicketList.test.jsx, excerpt)
  it('names the table with a caption', () => {
    renderWithProviders(<TicketList tickets={testTickets} />);

    expect(screen.getByRole('table', { name: 'Tickets' }))
      .toBeInTheDocument();
  });

(The expect is split here to fit.) The test finds the table the way a screen reader user would, by its name, which is the whole point of the caption.

The skip link: first, and pointing at main

// Figure 6.32: the skip link (src/App.test.jsx, excerpt)
  it('starts every page with a link that skips to the main content', () => {
    renderAppAt('/no-such-page');

    const skipLink = screen.getByRole('link', {
      name: 'Skip to main content',
    });
    // It's the first link, so it's the first thing Tab reaches.
    expect(screen.getAllByRole('link')[0]).toBe(skipLink);
    expect(skipLink).toHaveAttribute('href', '#main-content');
    expect(screen.getByRole('main')).toHaveAttribute('id', 'main-content');
  });

(The getByRole line is split here to fit.) It checks three things that must all be true for the link to work: it comes first, it points at #main-content, and <main> has that id. What the test can't check is that the link slides into view on focus: jsdom doesn't lay out a page or apply CSS positions. That part needs the keyboard check from the start of this topic.
