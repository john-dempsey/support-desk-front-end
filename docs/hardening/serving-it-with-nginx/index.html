Serving It with nginx (Optional)

The built app in a container: a two-stage Dockerfile, nginx sending the files, try_files for deep URLs, and a year's caching for files whose names change.

  • Why a Web Server

    The built app is just files, so it needs a web server, not Node. The browser fetches the files from nginx and talks to the API itself.

  • Two Stages, One Small Image

    The first stage uses Node to build the app. The second is nginx with dist/ copied in, and nothing else.

  • The API's Address, at Build Time

    .env stays out of the image, so compose.yaml reads it and hands the address to the build as a build argument.

  • Starting It

    One command builds the image and starts nginx on port 8080, next to the API's stack. Logging in, pushes and Reload all work from there.

  • Refreshing a Deep Address

    nginx only sends files that exist. One line, try_files, tells it to send index.html instead, so React Router can show the page.

  • Keeping Files for a Year

    A hashed file's contents never change, so the browser may keep it for a year. index.html is checked every time, so a new build is seen at once.

  • Changing It Later

    Everything in the image is fixed when it's built. A change to the code, .env or nginx.conf needs --build; npm run dev stays how you work.
