The API's Address, at Build Time

.env stays out of the image, so compose.yaml reads it and hands the address to the build as a build argument.

Topic 07 showed that the API's address is written into the JavaScript when it's built. In Docker, the build happens inside the image, so the address has to get in there somehow. But not by copying .env.

What stays out: .dockerignore

As in Lesson 6, .dockerignore lists what Docker never receives, so no COPY can reach it:

# Figure 6.41: what Docker never receives (.dockerignore, excerpt)
node_modules
dist
coverage

# Never put secrets in an image: anyone with the image could read them.
# The API's URL comes in as a build argument instead (see compose.yaml).
.env
.env.*
!.env.example

node_modules and dist are made fresh inside the image. .env stays out as a habit worth keeping. A front-end's .env should have no secrets, but in Stages 2 and 3 ours held a real token (VITE_DEV_TOKEN), and an image can be copied to anyone.

What goes in: a build argument

An ARG line in a Dockerfile declares a build argument: a value given to the build from outside. Figure 6.39 had ARG VITE_API_URL just before RUN npm run build, so the build sees it as an environment variable, and Vite reads VITE_ values from environment variables as well as from .env. compose.yaml supplies the value:

# Figure 6.42: the web service (compose.yaml, excerpt)
name: support-desk-front-end

services:
  web:
    build:
      context: .
      args:
        # Compose reads .env in this folder, so the image is built with the
        # same API URL as `npm run dev` uses. With no .env, it's empty and
        # client.js uses its default. Change it, and run `--build` again:
        # it's baked in when the image is built.
        VITE_API_URL: ${VITE_API_URL:-}
    restart: unless-stopped
    ports:
      - '8080:80' # http://localhost:8080

So .env is read on your computer, by Compose, and only the one value goes into the build. ${VITE_API_URL:-} means "the value, or empty if there isn't one". '8080:80' sends port 8080 on your computer to nginx's port 80, as Lesson 6's '3000:3000' did for the API. The name line names the stack, so the container is called support-desk-front-end-web-1.

Comments in .env start with #

Vite is forgiving about .env: it skips any line it doesn't understand. Docker Compose isn't. A line such as // casey makes every docker compose command in that folder fail, even ps:

unexpected character "/" in variable name

So comments in .env start with #, as in .env.example.

Try it

Run docker compose config in the app's folder. It prints compose.yaml with the values filled in. What does it show for VITE_API_URL? Where did that value come from?
