Refreshing a Deep Address

nginx only sends files that exist. One line, try_files, tells it to send index.html instead, so React Router can show the page.

Topic 07 ended with a plain web server answering a reload of /tickets/3 with a 404. nginx is a plain web server too: with no settings of our own, it does the same.

There's no file called tickets/3 in dist/, so nginx says so. The app never loads, so React Router never gets to read the address. The Dockerfile copies our own settings over nginx's default site to fix that:

# Figure 6.43: send index.html for every address (nginx.conf, excerpt)
server {
    listen 80;
    root /usr/share/nginx/html;

    # Every URL that isn't a real file gets index.html. There is no
    # tickets/3 file in dist/: React Router reads the URL in the browser
    # and shows the right page. Without this line, refreshing /tickets/3
    # would get nginx's own "404 Not Found".
    location / {
        try_files $uri /index.html;
        # Ask the server every time, so a new build is picked up at once.
        add_header Cache-Control "no-cache";
    }
  • listen 80 and root: answer on port 80 inside the container, with files from the folder the Dockerfile copied dist/ into.
  • location / holds the rules for every address (the next slide adds a more specific one).
  • try_files $uri /index.html: try the address as a file ($uri is the address, such as /favicon.svg). If there's no such file, send /index.html instead.

That's the same fallback the dev server and npm run preview always had. In a Laravel app, the web server's settings send every address to public/index.php in the same way, and Laravel's router takes over; here React Router does.

Try it

In nginx.conf, put a # in front of the try_files $uri /index.html; line. Run docker compose up -d --build, open http://localhost:8080/tickets/3 and reload. Now click the address bar, go to http://localhost:8080/ and click your way to a ticket: why does that work? Remove the # and build again.
