Two Requests, Two Hooks

A page that needs two things calls useFetch twice. Both requests still go at the same time.

The ticket's page needs two things: the ticket, and its comments. In Stage 5 it asked for both in one effect, with Promise.all. Now it calls the hook once for each request:

// Figure 6.12: two hooks (src/pages/TicketDetailPage.jsx, excerpt)
  // One useFetch for each request. Both run when the page first renders,
  // so the two requests are sent at the same time. useFetch loads again
  // whenever ticketId changes, e.g. if the URL changes to another ticket.
  const {
    data: ticket,
    error: ticketError,
    isLoading: isTicketLoading,
    reload: reloadTicket,
  } = useFetch(getTicket, ticketId);
  const {
    data: comments,
    setData: setComments,
    error: commentsError,
    isLoading: areCommentsLoading,
    reload: reloadComments,
  } = useFetch(getComments, ticketId);

This is where renaming earns its keep: every value gets a name that says which request it belongs to.

Still at the same time

Each call to the hook has its own effect, and React runs all of a component's effects after the same render. So both requests leave together, as they did with Promise.all:

The page then puts the two back together. It waits for both, and shows whichever error there is:

// Figure 6.13: waiting for both (src/pages/TicketDetailPage.jsx, excerpt)
  if (isTicketLoading || areCommentsLoading) {
    return <Loading message="Loading the ticket…" />;
  }
  // ...
  // Either request may have failed: show whichever error there is.
  const loadError = ticketError || commentsError;

EditTicketPage does the same with the ticket and the list of agents.

Why not one hook for both? It would need a combined object, { ticket, comments }. Then adding a comment would mean copying that object as well as the comments inside it. With two hooks, adding a comment changes comments and nothing else.

Try it

Log in, open a ticket with the Network tab showing (filter: Fetch/XHR), and look at the Waterfall column for the ticket and its comments. Do the two bars start at the same moment? (In development, StrictMode asks for each one twice, as Stage 0 explained, so you'll see four rows.)
