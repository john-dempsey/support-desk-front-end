Renaming While Destructuring

useFetch calls its result data. A page can unpack it under a name of its own: { data: tags }.

useFetch doesn't know what it's loading, so it calls everything data and error. But a page full of data would be hard to read: data of what? So each page renames the values as it unpacks them:

const { data } = useFetch(getTags);        // the tags are called data
const { data: tags } = useFetch(getTags);  // the same value, called tags

data: tags reads "take the one called data, and call it tags". The name on the left of the colon is the hook's; the name on the right is the page's. After that line there's a tags variable, and no data at all.

Here's the tags page:

// Figure 6.9: renaming as it unpacks (src/pages/TagsPage.jsx, excerpt)
  // "data: tags" renames as it unpacks: useFetch calls it data, and this
  // page calls it tags. The same for setData and error.
  const { data: tags, setData: setTags, error: loadError, isLoading } =
    useFetch(getTags);

(The last line is split in two here to fit.) Three values are renamed, and isLoading keeps its name, because it says what it means already.

Why the names matter

  • The rest of the page reads as it did before. It still says tags.map(...) and setTags(...), exactly as in Stage 5, so moving onto the hook changes one line at the top, not every line below it.
  • error was already taken. The tags page has three other errors, for adding, renaming and deleting. Calling this one loadError says which it is.
  • A page can call the hook twice. Two data variables in one page would clash. With renaming, each call's values get names of their own. That's the next slide but one.

PHP can do the same with a keyed array: ['data' => $tags] = $result; takes the data key and calls it $tags.

Try it

In src/pages/TagsPage.jsx, change data: tags to just data, so the page no longer has a tags variable. Run npm run lint: it warns that data is never used, but says nothing about tags. Now run:

npx vitest run src/pages/TagsPage.test.jsx

Every test in the file fails, with ReferenceError: tags is not defined. Which tool found the real mistake? Put data: tags back.
