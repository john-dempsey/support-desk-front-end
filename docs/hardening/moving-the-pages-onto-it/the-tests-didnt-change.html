The Tests Didn't Change

Five pages were rewritten, and every one of their tests passed without being touched. That's what tests are for.

Five pages lost their effects, renamed their state and gained a hook. Their tests were not changed at all. Stage 5's 161 tests, run against the Stage 6 pages, all pass.

That works because the page tests never looked inside the pages. Since Stage 2 they've faked the API module, rendered the page, and checked what a user would see:

  • "Loading tickets…" appears, then the tickets;
  • an error from the API appears as an alert;
  • choosing a filter asks the API for the right query.

None of that mentions useState, useEffect or ignore, so none of it cared how the page got its data. A test that checks behaviour, not code, keeps passing when the code is rewritten, and fails the moment the behaviour breaks. That's the safety net topic 01 promised.

The test files did gain tests in Stage 6, for things later topics add. Of the lines already in them, the only ones changed are two import lines, each importing one more function for a new test.

The hook has its own tests too

The pages' tests check that each page works. useFetch.test.js (topic 02) checks the hook on its own, including the ignore flag. Between them, a mistake in the hook would show up twice: once in its own test, and once in every page that uses it.

Try it

In TicketListPage, drop the query string from the hook call, so it reads useFetch(getTickets). The page still loads tickets. Run npm test:

  • six tests fail: the list page's tests for the query, the filter, "All statuses", Next and Reload, and one App test that logs two users in;
  • npm run lint warns that queryString is declared but never used.

Read the first failure's message: what did the test expect getTickets to be called with? Put queryString back.
