Moving the Pages onto It

Each page that loads data swaps its own effect for useFetch, keeps what's really its own, and passes every test it passed before.

  • Renaming While Destructuring

    useFetch calls its result data. A page can unpack it under a name of its own: { data: tags }.

  • The List Page, After

    TicketListPage's four pieces of state and its whole effect become one line. The rest of the page hardly changes.

  • Two Requests, Two Hooks

    A page that needs two things calls useFetch twice. Both requests still go at the same time.

  • Changing the Data Afterwards

    After a create, a delete or a push, a page changes the loaded data with the setData the hook hands back, using the function form.

  • What Stays in the Page

    The hook only loads. Deciding what an error means, the page's own notices, and the tags page's way of reloading all stay in the pages.

  • Not Every Effect Is a Fetch

    AuthProvider and NotificationsProvider also have an ignore flag, but they aren't pages waiting for data, so they keep their own effects.

  • The Tests Didn't Change

    Five pages were rewritten, and every one of their tests passed without being touched. That's what tests are for.
