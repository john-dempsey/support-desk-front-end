What's in the 329 kB

Most of the built JavaScript is React. Our own code, every page and component from six stages, is less than a tenth of it.

The build's one .js file is 329 kB. How much of that did we write?

The build can make a source map (npx vite build --sourcemap): a file that says which original file each part of the built code came from. Adding up the parts gives this:

  • react-dom, nearly two thirds of it, is the part of React that works out what changed and updates the page. react itself (hooks such as useState, and createElement) is small.
  • Socket.IO is five packages that work together: the client, the connection underneath it (engine.io-client), two message parsers and a small event emitter. Together they're about as big as React Router.
  • Our code, every page, component, hook and API file from Stages 1 to 6, is 29 kB: 9%.

The gzip column from the build is what users actually download: about 102 kB, since the server compresses the file before sending it.

So is it too big?

For an app people log in to and use for a while, 102 kB once is fine. The browser keeps the file afterwards (topic 08 shows how long).

Big apps split their JavaScript, so a page's code is only downloaded when someone visits that page. That's called lazy loading. Here it wouldn't save much: the pages are part of our 9%, and every page needs React.

Try it

Look at your own app's package.json dependencies and run npm run build. If your app has no Socket.IO, how much smaller would you expect its .js file to be than ours? Check the build's output. What's left once React and React Router are taken away?
