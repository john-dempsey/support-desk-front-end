The API's Address Is Built In

The build writes VITE_API_URL's value straight into the JavaScript, twice, and drops the fallback it no longer needs.

Stage 0 said .env is read when the app is built. Here's what that looks like in the finished app. Two files read the API's address, the client and the socket, and both look the same in src/:

const API_URL = import.meta.env.VITE_API_URL || 'http://localhost:3000';

Search the built .js file for localhost:3000 and you find this:

// Figure 6.37: the API's address, built in
// (dist/assets/index-CPcL75JA.js, two excerpts, reflowed)
var br=`http://localhost:3000`;
// ...
var ga=ha(`http://localhost:3000`,{autoConnect:!1});

The first line is client.js's API_URL. The second is socket.js's io(API_URL, { autoConnect: false }). The minifier gave everything short names (br, ga, ha), and wrote false as !1, which is shorter and means the same.

What happened to the ||

The build did two things, one after the other:

  1. It replaced import.meta.env.VITE_API_URL with the value from .env, as text: 'http://localhost:3000' || 'http://localhost:3000'.
  2. The minifier saw that the left side of || is a string that isn't empty, so it's always used. The right side can never run, so it was deleted.

So there's no import.meta.env left in the built app, and nothing that reads .env. The address is now just a string in the code.

What that means

  • Changing .env after a build does nothing to that build. The old address is in the .js file. You have to build again.
  • One build talks to one API. To run the same app against a test API and a live one, you build it twice, once with each address.
  • Vite also reads VITE_ values from environment variables, not only from .env. Topic 08 uses that to pass the address to a build that has no .env.

Try it

  1. Open dist/assets/ and search the .js file for localhost:3000. How many times is it there? Search for VITE_API_URL: is it there at all?
  2. In .env, change the address to http://api.example.test:9999, then run npm run build. Search for the new address. Which of the two file names in dist/assets/ changed, and why didn't the other?
  3. Put .env back and build again.
