Production Isn't Development

The built app sends each request once, has no component names, and leaves out everything marked as development only.

The built app looks the same as the one on port 5173. Underneath, three things are different, and each one comes from a choice made earlier in the course.

1. Each request goes once

In development, StrictMode runs every effect twice (Stage 0, topic 06), so the Network tab showed two GET /tickets for one visit. The build leaves StrictMode's checks out. Log in as Alex on the built app and the Network tab shows one of each: POST /auth/login, then one GET /notifications?unread=true and one GET /tickets.

2. No names

The minifier shortens names to make the file smaller. You saw br for API_URL in this topic. Component names go too: search the built file for TicketDetailPage and it's not there.

3. Nothing for development only

Topic 04's error boundary shows the error's message only in development (Figure 6.21):

{import.meta.env.DEV &&
  <p>Details (development only): {this.state.error.message}</p>}

In a build, import.meta.env.DEV is false, so the build wrote in false && <p>…</p>. That's always false, so the minifier dropped the <p> and kept only the false. Here's the fallback in the built file:

// Figure 6.38: the boundary's fallback, built
// (dist/assets/index-CPcL75JA.js, excerpt, reflowed, one message cut)
(0,A.jsx)(`h1`,{children:`Something went wrong`}),
(0,A.jsx)(ar,{message:`Sorry, this page stopped working. …`}),
!1,
(0,A.jsx)(`p`,{children:(0,A.jsx)(k,{to:`/`,
  children:`Go to the home page`})})

Each (0,A.jsx)(…) is what one JSX tag became: a call to React's function for making an element (ar is ErrorMessage, k is Link). The !1 is the false, and React shows nothing for false, so users never see a details paragraph. The words "development only" aren't in the file at all.

(Since Stage 4, there's no token in the build either: VITE_DEV_TOKEN has gone, and a token only ever lives in the user's localStorage.)

Try it

Run npm run build, then npm run preview, and open http://localhost:4173. Open the Network tab, log in as Alex, and count the requests to tickets. (Login is limited to 10 tries in 15 minutes, so don't log in and out too often.) Then search the built .js file for development only, then for Something went wrong. Which do you find?
