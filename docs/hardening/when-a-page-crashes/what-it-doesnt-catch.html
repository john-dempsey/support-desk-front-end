What It Doesn't Catch

A boundary only catches errors thrown while rendering. Event handlers and requests still need try/catch, and the details are for developers only.

A boundary catches errors thrown while React is rendering the components inside it. It doesn't catch:

  • Errors in event handlers, such as a click. A handler runs after rendering has finished, when the user does something. If it throws, nothing on the screen is half-drawn, so React has nothing to replace.
  • Errors in async code, such as a failed request. The request finishes long after the render that started it.

Neither needs a boundary. Every handler and every request in the app already has its own try/catch, which shows the user a message right where it belongs: next to the form, or in place of the list. The boundary is a safety net for the bugs that slip past those.

The details are for developers

(The last line is split here to fit.) Vite sets import.meta.env.DEV to true under npm run dev and false in the production build, so "Cannot read properties of null (reading 'name')" helps you, and never puzzles a real user.

Who hears about the error

React itself logs every error a boundary catches, with console.error, so the boundary doesn't need to. A real app would also want to know when its users hit a bug. It would send the error to an error-reporting service from a method called componentDidCatch, which React calls after getDerivedStateFromError. This app has no such service, so it doesn't have the method.
