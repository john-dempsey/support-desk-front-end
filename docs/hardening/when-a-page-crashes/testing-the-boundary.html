Testing the Boundary

A component that always throws tests the fallback, a faked environment variable tests the production version, and an App test checks the key.

ErrorBoundary.test.jsx needs something to crash on purpose. A component that does nothing but throw is enough:

// Figure 6.22: BrokenPage (src/components/ErrorBoundary.test.jsx, excerpt)
function BrokenPage() {
  throw new Error('Broken on purpose');
}

function silenceConsoleErrors() {
  vi.spyOn(console, 'error').mockImplementation(() => {});
}

React logs every caught error with console.error, and a test that crashes on purpose would fill the output with red. vi.spyOn() swaps console.error for a fake that prints nothing (and mockReset in vite.config.js puts the real one back after each test). The test can still check it was called:

// Figure 6.23: a crash (src/components/ErrorBoundary.test.jsx, excerpt)
  it('shows "Something went wrong" when the page crashes', () => {
    silenceConsoleErrors();

    renderWithProviders(
      <ErrorBoundary>
        <BrokenPage />
      </ErrorBoundary>,
    );

    expect(screen.getByRole('heading', { name: 'Something went wrong' }))
      .toBeInTheDocument();
    // ...
    // React still reports the error, even though the boundary caught it.
    expect(console.error).toHaveBeenCalled();
  });

(The first expect is split here to fit; three more checks are left out: the title, the alert and the link home.)

Pretending to be production

Tests run under Vitest, where import.meta.env.DEV is true. To test the production version, one test fakes it:

vi.stubEnv('DEV', false);

and then checks that "Broken on purpose" appears nowhere on the page. (unstubEnvs in vite.config.js undoes it after the test.)

The key, tested in App

The boundary's own tests can't check the key: that's in App. So App.test.jsx gives the ticket's page a ticket with no customer, which crashes it, waits for "Something went wrong", then clicks Tickets and expects the ticket list.
