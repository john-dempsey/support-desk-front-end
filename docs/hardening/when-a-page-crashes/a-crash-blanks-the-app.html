A Crash Blanks the App

Every failure so far was expected and handled in state. A bug that throws while rendering is different: React removes the whole app.

Since Stage 2, every page has handled the failures it expects: the API is down, the ticket isn't there, the name is taken. Each one is caught with try/catch and shown as a message.

A bug is different. Suppose the ticket's page read the agent's name without checking there is one:

<dd>{ticket.assignedAgent.name}</dd>

For an unassigned ticket, assignedAgent is null, and reading .name from null throws a TypeError while the page is rendering. There's no try around rendering, so nothing in the page can catch it.

What React does about it

In Stage 5, React's answer is to remove the whole app. Not just the ticket's page: the navigation bar too. The user is left with a blank white page and nothing to click. The console says:

An error occurred in the <TicketDetailPage> component.
Consider adding an error boundary to your tree to customize error
handling behavior.

React does this because a component that crashed halfway through rendering might show something wrong, or half of something. React can't know which parts of the screen are still safe, so it shows none of them.

An error boundary is the "error boundary" that message suggests: a component that catches a crash anywhere inside it and shows something else instead. It's the front-end's version of Laravel's exception handler: an uncaught exception in Laravel gets an error page, never a blank one.

Try it

In src/pages/TicketDetailPage.jsx, find the line that shows the assigned agent, and change it to the buggy version above:

<dd>{ticket.assignedAgent.name}</dd>

Reload the page, log in as Ada, and open an unassigned ticket (in the seed data, ticket 2 or 4). You should see the screenshot above. The console now says the error occurred in <TicketDetailPage>, and that "React will try to recreate this component tree from scratch using the error boundary you provided, ErrorBoundary."

Leave the bug in for now: the next slides use it.
