No New Features

Stage 6 makes the app you already have easier to change, harder to break, and ready to run outside Vite, with the tests checking every step.

Stages 1 to 5 each gave the user something new: a list, a form, a login, a notification. Stage 6 doesn't. A user would only notice a few small things, such as each browser tab having its own title.

Instead, this stage works on the app you already have. It has three aims:

  • Easier to change. Since Stage 2, every page that loads data has had its own copy of the same effect, about 30 lines long. Topics 02 and 03 write it once, as a hook of our own.
  • Harder to break. A bug that crashes one page shouldn't blank the whole app (topic 04). Keyboard and screen reader users should be able to tell pages apart and skip the navigation (topic 05). And a coverage report shows which code no test has ever run (topic 06).
  • Ready to run outside Vite. npm run dev is a tool for developing. Topics 07 to 09 build the real thing, serve it the way a real website is served, and look at the one setting on the API that a real deployment would change.

The tests do the real work here

Changing code that already works is risky: it's easy to break something you weren't looking at. That's what the tests are for.

At the end of Stage 5 the app had 161 tests in 29 files. Every change in this stage is made with those tests running, and all 161 still pass at the end of Stage 6, without a single change to them. When a test does fail along the way, it points at the exact behaviour that broke, before a user ever sees it.

The stage adds tests of its own as well: 199 by the end.

Try it

Before you start, run npm test on your own Stage 5 app (or Stage 3, if your API has no login), and write down the two numbers it prints: test files and tests. That's the safety net you'll be relying on for the rest of this stage.
