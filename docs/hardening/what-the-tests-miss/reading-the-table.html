Reading the Table

Four percentages for each file, and the line numbers no test reached. What each column means, using the Support Desk app's first report.

Here's part of the Support Desk app's first coverage report, run before this topic's new tests:

File               | % Stmts | % Branch | % Funcs | % Lines | Uncovered Line #s
-------------------|---------|----------|---------|---------|-------------------
All files          |   96.25 |    90.58 |   97.45 |   96.22 |
  App.jsx          |      80 |       50 |     100 |      80 | 36
  main.jsx         |       0 |      100 |     100 |       0 | 16
  Pagination.jsx   |      80 |      100 |   66.66 |      80 | 13
  StatusBadge.jsx  |     100 |       75 |     100 |     100 | 13
  ...etFilters.jsx |      60 |      100 |      60 |      60 | 33-47
  AuthProvider.jsx |   91.17 |       70 |    90.9 |   91.17 | 79-81
  TagsPage.jsx     |    87.8 |    77.77 |     100 |    87.5 | 25,75-76,83,93

(Seven of its rows; the dashes are shortened, and one row per folder is left out.) Long names are cut short: ...etFilters.jsx is TicketFilters.jsx.

The four percentages

  • Stmts (statements): how many of the file's statements ran. A statement is roughly one instruction: return null;, a call, an assignment.
  • Branch: every if, ? :, && and || has two ways to go. This counts how many of those ways ran. App.jsx is at 50%: if (isCheckingSession) only ever went one way, so the return inside it, line 36, never ran. No test had a session still being checked.
  • Funcs (functions): how many functions were ever called. TicketFilters.jsx is at 60%: two of its five functions, the onChange arrows on the Sort by and Order dropdowns, never ran.
  • Lines: like statements, counted by line. It's usually close to Stmts.

The last column

Uncovered Line #s says where to look. It lists the lines that never ran: TagsPage.jsx lines 25, 75–76, 83 and 93. When every line has run, it lists the lines with a branch that didn't, instead: StatusBadge.jsx line 13. So a file that has both shows only the lines at first. Fix those, and the branches appear.

The whole table also has a summary row, "All files". It's the number people quote, and the least useful one: 96% sounds fine, and says nothing about which 4%.

Try it

Run npm run coverage on your own app. Find:

  1. the file with the lowest % Funcs: which function never ran?
  2. a file at 100% statements but under 100% branches: open it at the line the last column gives, and say which way that branch never went.
