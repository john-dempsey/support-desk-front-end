The HTML Report

coverage/index.html shows the same numbers as a web page, and every file's code with the lines no test ran marked in red.

The table in the terminal is one of several reports Vitest writes. The most useful is a small website in coverage/. Open coverage/index.html in your browser:

Click a folder, then a file, and you see its code, line by line:

What the marks mean

  • A count, such as 2x or 39x, beside a line: how many times the tests ran it. 39x on line 31, which calls useFetch, is every render of the page in every test.
  • A red line never ran. In TagsPage.jsx that's line 25, return error;. It's the end of describeTagError(), for an error that isn't a 409, and no test sent the tags page any other error.
  • An E in front of an if means its else path never ran (and an I would mean its if path never ran). Line 22 checks for a 409, and every test that reached it had a 409, so the "not a 409" way never happened. That's the same gap as line 25, seen from the if.
  • Yellow in the folder table: a middling score, between red (low) and green (high).

The report can be more useful than the table: you see the gap in its code, so you can see what sort of test would reach it.

Try it

Open your own report, find the file with the most red, and pick one red line. Write one sentence for a test that would run it: "When the API answers … the page should show …". Don't write the test yet: the next slides show how the Support Desk app chose which gaps to fill.
