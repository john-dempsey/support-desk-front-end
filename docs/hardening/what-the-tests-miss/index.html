What the Tests Miss

A coverage report shows which lines of the app no test has ever run. It found real gaps, and 16 new tests fill them, but 100% isn't the goal.

    Vitest can record every line the tests run. One dev dependency and one script give a report of what they never touch.

  • Reading the Table

    Four percentages for each file, and the line numbers no test reached. What each column means, using the Support Desk app's first report.

  • The HTML Report

    coverage/index.html shows the same numbers as a web page, and every file's code with the lines no test ran marked in red.

  • What It Found

    The first report pointed at real behaviour that no test checked. Sixteen new tests fill those gaps.

  • Two of the New Tests

    A component test for TicketFilters' dropdowns, and an App test that uses the real AuthProvider to catch the session check in progress.

  • 100% Isn't the Goal

    After the new tests, a few red lines are left on purpose. And a line coverage calls 'covered' can still be checked by nothing.
