A Coverage Report

Vitest can record every line the tests run. One dev dependency and one script give a report of what they never touch.

By Stage 5 the app had 161 tests. They tell you what's checked. They don't tell you what isn't: a page, a button or an error message that no test has ever run. Guessing where those gaps are is slow, and you'll miss some.

A coverage report answers it for you. While the tests run, Vitest records which lines of the app were run, and then lists every file with how much of it the tests reached.

Setting it up

Vitest needs one extra package to record coverage. It's a dev dependency, a tool for the tests that never reaches the browser, and its version must match Vitest's:

npm install --save-dev @vitest/coverage-v8

(v8 is the JavaScript engine inside Node and Chrome: it does the recording.) Then a script in package.json, next to test:

"coverage": "vitest run --coverage"

The report is written to a coverage/ folder, which is made fresh each time, so it's added to .gitignore, like dist.

Counting every file

By default, a file that no test imports doesn't appear in the report at all, which hides the biggest gap of all. So vite.config.js says which files to count:

// Figure 6.33: what to count (vite.config.js, excerpt)
    // For `npm run coverage`: which lines of the app the tests ran.
    // include lists every source file, so a file no test loads shows up
    // at 0% instead of being left out. The test helpers in src/test are
    // part of the tests, not the app, so they're not counted.
    coverage: {
      include: ['src/**/*.{js,jsx}'],
      exclude: ['src/test/**'],
    },

It goes inside the test section, next to mockReset. Test files themselves are never counted.

Try it

Add coverage to your own app: install the package, add the script and the coverage section, and add coverage to .gitignore. Then run:

npm run coverage

The tests run as usual, and a table follows them. Does every file in your src/ appear in it? Check git status doesn't list coverage/.
