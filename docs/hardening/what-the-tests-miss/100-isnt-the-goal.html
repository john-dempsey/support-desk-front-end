100% Isn't the Goal

After the new tests, a few red lines are left on purpose. And a line coverage calls 'covered' can still be checked by nothing.

After the 16 new tests, these are the only files under 100%:

File               | % Stmts | % Branch | % Funcs | % Lines | Uncovered Line #s
-------------------|---------|----------|---------|---------|-------------------
All files          |   99.41 |    93.33 |     100 |    99.4 |
  main.jsx         |       0 |      100 |     100 |       0 | 16
  client.js        |   96.87 |     90.9 |     100 |   96.87 | 65
  StatusBadge.jsx  |     100 |       75 |     100 |     100 | 13
  AuthProvider.jsx |     100 |       70 |     100 |     100 | 31-43
  useFetch.js      |     100 |    83.33 |     100 |     100 | 47
  TagsPage.jsx     |   97.61 |    88.88 |     100 |    97.5 | 25
  socket.js        |     100 |       50 |     100 |     100 | 17

(Seven of the 13 files under 100%. Most of the others, such as LoginPage and TicketForm, are a field whose error no test shows.) Every function has run. The app could be pushed to 100%. It isn't, on purpose.

Some lines aren't worth a test

  • main.jsx starts the app in the browser. Tests render components directly, so they never run it, and a test of it would test React.
  • socket.js line 17, VITE_API_URL || 'http://localhost:3000': the tests load your .env, so the fallback never runs.
  • AuthProvider lines 31–43 and useFetch line 47: the ignore flag's other side, for an answer that arrives after it's no longer wanted. In useFetch it's a late error. Its late answer already has a test; a late error is a good challenge.
  • client.js line 65: a response with no JSON body at all. It's in the Stage 0 template, so it's a challenge too.

Covered isn't the same as tested

Coverage only says a line ran. It can't say whether any test would notice if the line did the wrong thing:

  • maxLength={200} on the ticket's subject ran in every test that showed the form: covered. No test types 201 characters, so deleting it would break nothing.
  • StatusBadge line 13, styles[status] || styles.unknown, picks grey for a status it doesn't know. In tests, a CSS Module hands back a made-up class name for any name, even one that isn't in the file, so styles.on_hold is never empty and the || styles.unknown side never runs. The test for an unknown status still passes, because it only checks the text.

So use coverage to find gaps, never as the score to aim for. A team that must reach 100% writes tests that run lines without checking them, which raises the number and catches nothing.

Try it

In src/components/TicketForm.jsx, delete maxLength={200} and run npm run coverage. Does any test fail? Does the coverage for TicketForm.jsx change? Put it back. What test would notice?
