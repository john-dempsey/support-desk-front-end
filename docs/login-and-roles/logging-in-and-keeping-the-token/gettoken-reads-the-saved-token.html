getToken() Reads the Saved Token

Stage 2 said getToken() would change in Stage 4. It now returns the token saved at login, and apiRequest() reads it once per request.

Stage 2 gave client.js one small function for finding the token (Figure 2.3), so that this stage would only have to change one line. Here it is in Stage 3, and in Stage 4:

// Figure 4.5: getToken() in Stage 3 (src/api/client.js, excerpt)
export function getToken() {
  return import.meta.env.VITE_DEV_TOKEN || null;
}

// Figure 4.6: getToken() in Stage 4 (src/api/client.js, excerpt)
import { getSavedToken } from './tokenStorage.js';

export function getToken() {
  return getSavedToken();
}

Both return a token, or null when there isn't one. getSavedToken() already gives null when nothing is saved (localStorage.getItem() does that for a missing key), so the || null isn't needed.

When there's no token

buildHeaders() still adds the Authorization header only when there's a token (Figure 2.4). That matters even more now:

  • Logging in: there's no token yet, so none is sent.
  • Logged out: logout() clears the saved token, so the next request has none.

One token per request

There's one more small change. In Stage 3, buildHeaders() called getToken() itself. Now apiRequest() reads the token once, at the start, and hands it to buildHeaders():

// Figure 4.7: reading the token once (src/api/client.js, excerpt)
export async function apiRequest(path, options = {}) {
  const method = options.method || 'GET';
  const hasBody = options.body !== undefined;
  const token = getToken();

  let response;
  try {
    response = await fetch(`${API_URL}${path}`, {
      method,
      headers: buildHeaders(hasBody, token),
      body: hasBody ? JSON.stringify(options.body) : undefined,
    });

(The rest of the function is left out here.)

apiRequest() needs to know whether this request carried a token again once the answer arrives. Topic 09 shows why.

Stage 2 also said nothing else in client.js would change. That's nearly true: apart from these lines, there's one addition, also in topic 09.
