Logging In, and Keeping the Token

The three requests about who the user is, where the token is kept between visits, what's inside it, and how it reaches every request.

  • Three Requests About Who You Are

    auth.api.js has one function per auth route: log in, register, and ask who a token belongs to. They follow the same three steps as every other API function.

  • Keeping Only the Token

    The token is saved in the browser's localStorage, so a reload doesn't log the user out. Three small functions in tokenStorage.js are the only code that touches it.

  • What's Inside a Token

    Anyone can read a token's payload: it holds the user's id, their role, and when it expires. The app could decode it, but doesn't need to, and shouldn't trust what it finds.

  • Any Script on the Page Can Read It

    The Console just read the token, and so could any other JavaScript on the page. That's the trade-off of localStorage, and why React showing text as text matters.

  • getToken() Reads the Saved Token

    Stage 2 said getToken() would change in Stage 4. It now returns the token saved at login, and apiRequest() reads it once per request.

  • The Token's Journey

    The token is written once, at login, and read on every request after that. Only two files ever touch it.
