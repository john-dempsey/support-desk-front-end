Keeping Only the Token

The token is saved in the browser's localStorage, so a reload doesn't log the user out. Three small functions in tokenStorage.js are the only code that touches it.

React state disappears when the page reloads: the whole app starts again from nothing. If the token were only kept in state, pressing F5 would log you out. So the token is also saved somewhere that lasts.

localStorage

Every browser gives each site a small store of its own, called localStorage:

  • it holds text, saved under a name (a key), like a tiny dictionary
  • it lasts through a reload, closing the tab, and restarting the browser
  • each site has its own. http://localhost:5173 can't see another site's store, and doesn't even share one with http://localhost:4173, because the port is part of what counts as "the site"

One file touches it

// Figure 4.3: saving the token (src/api/tokenStorage.js, excerpt)
const TOKEN_KEY = 'supportDeskToken';

// Returns the saved token, or null if there isn't one.
export function getSavedToken() {
  return localStorage.getItem(TOKEN_KEY);
}

export function saveToken(token) {
  localStorage.setItem(TOKEN_KEY, token);
}

export function clearSavedToken() {
  localStorage.removeItem(TOKEN_KEY);
}

Three one-line functions might seem like too little for a file. They're there so that the key 'supportDeskToken' is written once, and no other file uses localStorage directly. If the token ever moved somewhere else, this would be the only file to change.

Only the token

The user's details (name, role, ...) are not saved, only the token. A saved copy of the user could go out of date: their name could change, or their account could be deleted. Instead, when the app starts, it asks the API who the token belongs to, with GET /auth/me. That's later in this lesson.

In Laravel, the browser kept a session cookie, and sent it with every request by itself. Here, nothing happens by itself: the app saves the token, and client.js adds it to each request.

Try it

Log in to the app as Casey. In DevTools, open the Application tab, then Storage › Local storage › http://localhost:5173. What keys are there?

Then:

  1. Reload the page. Are you still logged in?
  2. Open the app in a second tab. Are you logged in there?
  3. Click Log out, and look at Local storage again. (Click the refresh button above the list if it hasn't changed.)
