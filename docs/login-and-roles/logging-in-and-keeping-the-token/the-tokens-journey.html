The Token's Journey

The token is written once, at login, and read on every request after that. Only two files ever touch it.

Here's the whole journey, from the login form to the API checking the token on a later request:

Written once, read many times

  • Left, once per login. The token arrives in the answer to POST /auth/login, and saveToken() writes it to localStorage. Registering does the same, with POST /auth/register.
  • Right, on every request. getToken() reads it back, and buildHeaders() puts it in the Authorization header. The back-end's authenticate.js checks it, as it did for the stand-in token.

The right-hand column is the same as Stage 2's trace of a ticket request (topic 06). Only the box where getToken() finds the token has changed.

Who touches the token

File What it does with the token
tokenStorage.js the only file that reads or writes localStorage
client.js reads it on every request, and puts it in the header
AuthProvider.jsx saves it after login and register, and clears it on logout
every page and *.api.js file (except auth.api.js) nothing: they don't know it exists

auth.api.js only passes the token back from the login answer to AuthProvider. Pages never see it.
