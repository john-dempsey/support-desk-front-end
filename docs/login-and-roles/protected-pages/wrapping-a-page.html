Wrapping a Page

In App.jsx, each page that needs a login is written between <ProtectedRoute> tags. The route table now says who can open each page, as the back-end's route files do.

In Stage 3, every route in App.jsx gave its page straight to element. Now most pages are wrapped first:

// Figure 4.22: two protected routes (src/App.jsx, excerpt)
{/* Any logged-in user. */}
<Route
  path="/tickets"
  element={
    <ProtectedRoute>
      <TicketListPage />
    </ProtectedRoute>
  }
/>

<Route
  path="/tags"
  element={
    <ProtectedRoute allowedRoles={['agent', 'admin']}>
      <TagsPage />
    </ProtectedRoute>
  }
/>

(Less indented here than in the file, where other routes come between these two.)

<TicketListPage /> is written between ProtectedRoute's tags, so it arrives in ProtectedRoute as children, the same prop AuthProvider uses (topic 04). ProtectedRoute decides whether to show it.

Every route, and who can open it

Route Wrapped in Who
/, /login, /register, * nothing anyone
/tickets, /tickets/:ticketId <ProtectedRoute> anyone logged in
/tickets/new <ProtectedRoute allowedRoles={['customer']}> customers
/tickets/:ticketId/edit, /tags <ProtectedRoute allowedRoles={['agent', 'admin']}> agents and admins

The same table as the back-end's

The back-end does the same in its route files. ticket.routes.js starts with router.use(authenticate), so every ticket route needs a token, and adds authorize(...) to the routes only some roles may use.

Back-end Front-end
authenticate <ProtectedRoute>
authorize('agent', 'admin') <ProtectedRoute allowedRoles={['agent', 'admin']}>
/auth/login and /auth/register have no authenticate /login and /register have no ProtectedRoute
