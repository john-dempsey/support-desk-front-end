Not Available

For the wrong role, ProtectedRoute shows a plain message instead of the page. The page never loads, so it never sends requests that can only fail.

When a customer opens /tags, ProtectedRoute shows:

Not available

Your account can't use this page.

Go to the tickets (a link)

It's short on purpose. It says what's wrong, and offers a way on.

Why not just show the page?

The API would refuse what the page tries to do anyway. On /tags, a customer could see the list (GET /tags is open to everyone), but every add, rename and delete would get a 403. The page wouldn't know that until it tried, and what it showed could be confusing. Take /tickets/1/edit, as Casey:

  1. EditTicketPage loads, and asks for the ticket and the list of agents, with Promise.all() (Stage 3, topic 05).
  2. GET /users?role=agent is for agents and admins only. The API answers 403.
  3. Promise.all() fails if either request fails, so the page shows "Couldn't load the ticket", with "You do not have permission to perform this action".

But the ticket loaded fine! The message blames the wrong thing. ProtectedRoute stops all of that before it starts: the page is never rendered, so it never sends a request.

Why not send them somewhere else?

ProtectedRoute could send the customer to /tickets, as it sends a visitor to /login. But then nothing would explain why the page they asked for didn't appear. A visitor who isn't logged in can do something about it (log in), so sending them to the login page helps. A customer can't become an agent, so a message is more honest than a jump to another page.

Not the only check

ProtectedRoute is for the user's sake: it saves them from a page that can only fail. It doesn't stop anyone sending the requests some other way. The API checks every request itself, whatever the front-end shows. Topic 08 shows what that means in practice.

Try it

In App.jsx, remove allowedRoles={['agent', 'admin']} from the /tickets/:ticketId/edit route, and save. Log in as Casey, and open /tickets/1/edit. What do you see? In the Network tab, which request failed, and with what status?

Put allowedRoles back when you're done.
