Wrapping the App

main.jsx puts AuthProvider around App, inside BrowserRouter. When the user changes, every component that called useAuth() re-renders with the new value.

main.jsx has had one wrapper since Stage 0. It now has two:

// Figure 4.10: two providers around the app (src/main.jsx, excerpt)
createRoot(document.getElementById('root')).render(
  <StrictMode>
    <BrowserRouter>
      <AuthProvider>
        <App />
      </AuthProvider>
    </BrowserRouter>
  </StrictMode>,
);

App is inside both, so every component it renders can use both the router's hooks and useAuth().

AuthProvider itself uses nothing from the router, so the two could go the other way round. The order only matters for a provider that uses another one: it has to be inside it.

When the user changes

Logging in calls setUser() inside AuthProvider. Then:

  1. AuthProvider re-renders, as any component does when its state changes, and makes a new authValue with the new user.
  2. The provider now holds a different value, so React re-renders every component that called useAuth(), wherever it is.
  3. Each one shows what's right for the new user: NavBar shows their name and Log out, HomePage swaps "Log in" for "View the tickets", and so on.

Logging out is the same, with setUser(null). Nothing has to tell NavBar that someone logged in. It reads user, so it re-renders when user changes.

Try it

In main.jsx, swap <BrowserRouter> and <AuthProvider>, so AuthProvider is on the outside (and the closing tags match). Does the app still work? Now explain why it would break if AuthProvider ever called useNavigate().
