A Component That Holds the User

AuthProvider is a component with no HTML of its own. It holds the user in state, and puts it, with the functions that change it, into the context for everything inside it.

AuthProvider.jsx is the longest new file in Stage 4. Here's its outline, with the details left for later:

// Figure 4.9: the outline of AuthProvider
// (src/context/AuthProvider.jsx, excerpt)
function AuthProvider({ children }) {
  const [user, setUser] = useState(null);

  // … isCheckingSession, and two effects (topics 05 and 09)
  // … login(), register(), logout() and hasRole() (next slides)

  const authValue = {
    user, isCheckingSession, login, register, logout, hasRole,
  };

  // Every component inside the provider can now read authValue.
  return <AuthContext value={authValue}>{children}</AuthContext>;
}

(The two // … lines stand for code that's left out here; they aren't in the file. authValue is on one line in the file.)

State, like any component

user is ordinary state: null when nobody is logged in, and the user's details ({ id, name, email, role, ... }) when someone is. It's the same useState as the ticket list's tickets. The difference is where it's shared.

authValue, into the context

authValue gathers everything other components need into one object: the user, and the functions that log in and out.

AuthContext is the context from authContext.js, written as if it were a component. <AuthContext value={authValue}> fills the context with that object, for everything between its tags. Any component inside can now get it with useAuth().

You'll often see <AuthContext.Provider value={...}> in examples online. That's the older way, from before React 19, and does the same thing.

children

AuthProvider shows nothing of its own: no heading, no <div>. It wraps whatever is written between its tags. In main.jsx that's <App />:

<AuthProvider>
  <App />
</AuthProvider>

React passes what's between the tags as a prop called children. AuthProvider takes it from its props, { children }, and renders it inside the provider. So App, and everything App renders, ends up inside the context.

It's the same idea as a Blade component's {{ $slot }}: the component decides where the content goes, and the page using it decides what the content is.

Find every component in src/ that takes children:
