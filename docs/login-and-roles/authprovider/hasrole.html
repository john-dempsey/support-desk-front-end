hasRole(...roles)

hasRole('agent', 'admin') is true for an agent or an admin, and false for anyone else, including nobody. It's the front-end's version of the back-end's authorize(...).

Several components need to ask "is this user one of these roles?". AuthProvider answers that question once, for all of them:

// Figure 4.12: checking the role (src/context/AuthProvider.jsx, excerpt)
// The front-end's version of the back-end's authorize('agent', 'admin'):
// hasRole('agent', 'admin') is true for an agent or an admin.
function hasRole(...roles) {
  return user !== null && roles.includes(user.role);
}

(It sits inside AuthProvider, so it's indented one step further in the file.)

Put it next to the back-end's authorize.js:

export default (...allowedRoles) =>
  (req, res, next) => {
    if (!allowedRoles.includes(req.user.role)) {
      return next(new ApiError(403, 'You do not ...'));
    }
    next();
  };

(The message is shortened, and a blank line left out.)

...roles

The ... in a parameter list gathers all the arguments into one array, however many there are. It's called a rest parameter:

Call roles is
hasRole('admin') ['admin']
hasRole('agent', 'admin') ['agent', 'admin']

Then roles.includes(user.role) asks: is the user's role in that array? It's the same check as authorize(), with user in place of req.user.

user !== null first

When nobody is logged in, user is null, and null.role would crash. && stops at the first false, so with no user, hasRole() returns false without ever reading user.role.

User hasRole('customer') hasRole('agent', 'admin')
nobody false false
Casey (customer) true false
Alex (agent) false true
Ada (admin) false true

Why a function

Each component could write user && user.role === 'admin' itself. But hasRole('agent', 'admin') reads like the back-end's route, can't forget the null check, and means the same thing everywhere it's used.
