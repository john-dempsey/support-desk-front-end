Logging In and Out

login() and register() ask the API, save the token, and set the user. logout() sends no request at all: it forgets the token and the user.

// Figure 4.11: logging in and out (src/context/AuthProvider.jsx,
// excerpt)
// login() and register() use the user in the API's response directly:
// there's no need to ask GET /auth/me again. Errors aren't caught here,
// so the page that called them can show the message.
async function login(email, password) {
  const result = await authApi.login(email, password);
  saveToken(result.token);
  setUser(result.user);
}

async function register(name, email, password) {
  const result = await authApi.register(name, email, password);
  saveToken(result.token);
  setUser(result.user);
}

function logout() {
  clearSavedToken();
  setUser(null);
}

(These functions sit inside AuthProvider, so they're indented one step further in the file.)

login(), in three steps

  1. Ask the API. authApi.login() sends POST /auth/login, and returns { user, token } (topic 02).
  2. Save the token, so it lasts through a reload and goes with every later request.
  3. Set the user. Every component that uses useAuth() re-renders with the new user (the last slide).

register() is the same, through authApi.register(). The API logs a new customer in straight away, so registering ends in the same place as logging in.

Errors go back to the page

There's no try/catch here. If the password is wrong, authApi.login() throws, and so does login(), before saving or setting anything. The error reaches the page that called login(), and the page shows it. That's the same split as Stage 3: the page decides what the user sees.

Logging out sends nothing

logout() makes no request. The back-end keeps no record of who's logged in (a JWT is stateless, Lesson 4), so there's nothing on the server to end. Logging out means this browser forgets the token and the user.

That has a consequence: the token itself still works until it expires. Anyone who had copied it could still use it. That's one more reason to keep tokens short-lived.
