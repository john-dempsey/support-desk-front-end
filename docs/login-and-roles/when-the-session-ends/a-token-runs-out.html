Calling It on a 401 →

A Token Runs Out

Tokens last a day. When one runs out mid-session, every request gets a 401. Rather than each page handling that, client.js tells AuthProvider, once, for all of them.

Topic 05 handled a token that had run out before the app started: GET /auth/me answers 401, and the user starts logged out.

But a token can also run out while the app is open. Leave a tab open overnight, click a ticket in the morning, and the request is sent with yesterday's token. The API answers:

401 "Invalid or expired token"

In Stage 3, with a token pasted into .env, that's what every page said until you pasted in a new one. Now the app can do better: log the user out, and send them to the login page.

Where should that happen?

Every page that loads data could check for it:

} catch (error) {
  if (error.status === 401) {
    logout();
  }
  // ...
}

That's the same lines in five pages, in a dozen catch blocks, and in every page anyone adds later. Forget it once, and that page shows an error instead.

Every request already goes through one function: apiRequest() in client.js. It sees every 401. So that's where to notice it.

But client.js can't log anyone out

Logging out means setUser(null), which belongs to AuthProvider. client.js is plain JavaScript, not a component. It can't call useAuth(), and it shouldn't know about React at all.

So client.js offers a place to put a function, and AuthProvider puts one there:

// Figure 4.30: a place for a function (src/api/client.js, excerpt)
// What to do when the API says a token is no longer any good (401): it has
// expired, or its user has gone. AuthProvider gives this file a function
// that logs the user out, so every page gets that behaviour from one
// place, instead of each page checking for 401 itself.
let sessionExpiredHandler = null;

export function setSessionExpiredHandler(handler) {
  sessionExpiredHandler = handler;
}

sessionExpiredHandler starts as null: nothing to call. Calling setSessionExpiredHandler(someFunction) stores a function in it for later. It's the same idea as passing onDelete to CommentList: "when this happens, call this", except that client.js isn't a component, so it can't take props.

Try it

Count the catch blocks in src/pages/, leaving out LoginPage and RegisterPage:

grep -c "catch" src/pages/*Page.jsx
