AuthProvider Logs Them Out

AuthProvider puts a function in client.js that clears the token and the user. ProtectedRoute does the rest: with no user, every protected page goes to /login.

// Figure 4.32: registering the handler (src/context/AuthProvider.jsx,
// excerpt)
// A 401 from any later request means the session is over, so client.js
// calls this function, and the user is logged out wherever they are.
// ProtectedRoute then sends them to the login page.
useEffect(() => {
  setSessionExpiredHandler(() => {
    clearSavedToken();
    setUser(null);
  });
  return () => {
    setSessionExpiredHandler(null);
  };
}, []);

(Indented one step further in the file.)

When AuthProvider first appears, this effect gives client.js a function. Its body is the same as logout(): forget the token, forget the user. The cleanup takes it away again if AuthProvider is ever removed, so client.js never calls a function belonging to a component that's gone.

From a 401 to the login page

Nothing in the handler mentions /login. It doesn't need to:

setUser(null) re-renders everything that uses useAuth() (topic 04). That includes the ProtectedRoute around the open page, which now finds no user, and sends the browser to /login (topic 07). Each piece does one job, and together they log the user out from anywhere.
