Tracing a Login

Questions to practise the viva's trace with, now that the app knows who's using it: the token, the context, protected routes, and the 401.

The viva's trace is the same shape as before: component → API module → HTTP request → state update → re-render. Stage 4 adds two new places for a step to happen: the context, whose state change re-renders every component that uses it, and localStorage, which outlives a reload.

Write one yourself

Write the trace for logging in, as a numbered list, one line per step, with the file each step is in. Start with the user clicking Log in, and finish with the ticket list on the screen and Casey's name in the navigation bar. You should need about twelve steps. The left-hand column of topic 02's diagram, "The Token's Journey", covers the first half. Check the rest against topics 04 and 06.

Questions to practise with

Answer these out loud, with the code open. Then try them again with it closed.

  1. After a successful login, handleSubmit doesn't call navigate(). So what takes the user to the ticket list?
  2. Where is the token kept, and why does it survive a reload when user doesn't?
  3. Which file reads the token before every request? Which pages know the token exists?
  4. Why does the app save only the token, not the user? What does it do instead when it starts?
  5. You reload on /tickets/1. What does the app show first, which request goes out, and why doesn't the user end up on the login page?
  6. NavBar, HomePage and TicketDetailPage all change when someone logs in. Nobody tells them. How do they find out?
  7. Why are AuthContext and AuthProvider in two files?
  8. Casey types /tags into the address bar. Which component decides what appears, and what does it check, in what order?
  9. What does hasRole('agent', 'admin') do with its arguments? What does it return when nobody is logged in?
  10. How does CommentList know which comments get a Delete button, without calling useAuth()?
  11. A token expires while Alex has the app open. Alex clicks a ticket. Name every file involved, from the 401 to the login page.
  12. A wrong password also gets a 401. Why doesn't that call the session-expired handler?
  13. The front-end hides Edit and Delete from Casey. What stops Casey deleting a ticket anyway?

Try it

Pick two questions you couldn't answer with the code closed. Find the answers in the code, then explain each to someone else without looking.
