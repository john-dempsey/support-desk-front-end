Which Comments Can Be Deleted

The rule for deleting a comment depends on each comment, not just the user's role. The page passes CommentList a function, canDelete(comment), that answers the question for each one.

The other controls depend only on the user's role. A comment's Delete depends on the comment too: the API lets its author delete it, and an admin delete any comment. Anyone else gets 403 "You can only modify your own comments".

So the question "can this user delete this comment?" has a different answer for each comment in the list.

The page answers the question

// Figure 4.28: the rule (src/pages/TicketDetailPage.jsx, excerpt)
// The API's rule for comments: only the author, or an admin, may delete
// one. CommentList calls this for each comment, to decide whether to
// show its Delete button.
function canDeleteComment(comment) {
  return comment.author.id === user.id || hasRole('admin');
}

(Indented one step further in the file.)

It's passed to CommentList as a prop, next to Stage 3's onDelete:

<CommentList
  comments={comments}
  canDelete={canDeleteComment}
  onDelete={handleDeleteComment}
/>

The list asks it, comment by comment

// Figure 4.29: asking (src/components/CommentList.jsx, excerpt)
{canDelete(comment) && (
  <button
    type="button"
    className="danger-button"
    aria-label={`Delete comment by ${comment.author.name}`}
    onClick={() => onDelete(comment)}
  >
    Delete
  </button>
)}

(Inside the comments.map(), so indented further in the file.)

Two kinds of function prop

Prop Called when Returns Does
onDelete(comment) the user clicks Delete nothing deletes, in the page
canDelete(comment) the list renders each comment true or false nothing: it only answers

CommentList still knows nothing about users or roles, and doesn't call useAuth(). It displays what it's given, and asks the page when it needs to know something. The rule stays in the page, next to the user.
