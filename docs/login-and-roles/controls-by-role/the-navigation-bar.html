The Navigation Bar

NavBar shows Tickets to anyone logged in, Tags to agents and admins, and the user's name and a Log out button, or Log in and Register for a visitor.

The navigation bar is on every page, so it's the first place the user sees who the app thinks they are.

// Figure 4.24: links by role (src/components/NavBar.jsx, excerpt)
{user && (
  <li>
    <NavLink to="/tickets">Tickets</NavLink>
  </li>
)}
{hasRole('agent', 'admin') && (
  <li>
    <NavLink to="/tags">Tags</NavLink>
  </li>
)}

(Less indented here than in the file, and a comment is left out.)

{condition && (...)} is the same pattern as Stage 3's {deleteErrorMessage && <ErrorMessage ... />}: if the condition is false (or null), React shows nothing there.

  • Tickets: anyone logged in. user is null for a visitor, so the link isn't shown.
  • Tags: hasRole('agent', 'admin'), the same roles as the /tags route's allowedRoles (topic 07). A link should never lead to "Not available".

Who's logged in, and Log out

// Figure 4.25: the user menu (src/components/NavBar.jsx, excerpt)
function handleLogout() {
  logout();
  navigate('/login');
}
// ...
{user ? (
  <>
    <p className="user-name">
      {/* ... the user's name and role */}
    </p>
    <button type="button" className="secondary-button"
      onClick={handleLogout}>
      Log out
    </button>
  </>
) : (
  <ul className="nav-links">
    {/* ... NavLinks to /login and /register */}
  </ul>
)}

(Shortened: the ... comments stand for code left out. The <button> tag is one line in the file.)

The left-out line shows the name, then the role in brackets: {user.name}, then ({ROLE_LABELS[user.role]}) in a <span> styled in a quieter colour. ROLE_LABELS turns the API's 'customer' into "Customer" for display, like Stage 3's STATUS_LABELS for statuses. The role is shown so the user always knows which account they're in: useful in class, when you switch between Casey, Alex and Ada.

Log out calls logout() from useAuth() (topic 04), then goes to the login page. Logging out on the home page would otherwise leave the user where they were, so navigate('/login') makes every logout end in the same place.
