Buttons by Role

The ticket list shows New ticket only to customers. The ticket page shows Edit and Delete only to agents and admins. Each is one hasRole() check around JSX that was already there.

Stage 3 showed every button to everyone. Stage 4 wraps the ones only some roles can use in a hasRole() check. Nothing else about them changes.

New ticket: customers only

// Figure 4.26: the New ticket link (src/pages/TicketListPage.jsx,
// excerpt)
{/* Only customers can report a problem (the API's
    authorize('customer')), so only they get the link. */}
{hasRole('customer') && (
  <p>
    <Link to="/tickets/new" className="button-link">
      New ticket
    </Link>
  </p>
)}

The same roles as the API

Each check uses the roles from the matching back-end route:

Control Front-end Back-end route
New ticket hasRole('customer') POST /tickets: authorize('customer')
Edit ticket hasRole('agent', 'admin') PATCH /tickets/:id: authorize('agent', 'admin')
Delete ticket hasRole('agent', 'admin') DELETE /tickets/:id: authorize('agent', 'admin')
Tags (in NavBar) hasRole('agent', 'admin') POST, PATCH, DELETE /tags: authorize('agent', 'admin')

Get one wrong, and the user sees a button that can only end in a 403. Get it right, and every button they see works.

The pages themselves (NewTicketPage, EditTicketPage, TagsPage) needed no changes at all: ProtectedRoute keeps the wrong roles out (topic 07).
