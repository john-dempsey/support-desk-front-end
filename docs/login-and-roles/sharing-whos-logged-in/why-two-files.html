Why Two Files?

The context and its hook are in authContext.js, and the provider component is in AuthProvider.jsx. Keeping them apart lets Vite update components in place while you edit.

The logged-in user's context is split over two files:

File Exports Kind
authContext.js AuthContext, useAuth() a context and a function
AuthProvider.jsx AuthProvider (the default export) a component

One file would seem simpler. The reason for two is Fast Refresh.

Fast Refresh

When you save a component file, Vite swaps in the new version of the component without reloading the page, and keeps its state (Stage 0, topic 02, "What Vite Does"). Change some text in a page, save, and the browser shows it straight away.

Fast Refresh can only do that for a file that exports nothing but components. If a file also exports something else, such as a context or a function, Vite has to replace more of the app, and state is lost.

oxlint knows this rule. With all three in one file, npm run lint says:

warning react(only-export-components): Fast refresh only works when a
file only exports components. Move your React context(s) to a separate
file.

(It's one line in the terminal, split here to fit.) oxlint also gives a second warning, for useAuth(): "Use a new file to share constants or functions between components." So the context and the hook have their own file, and AuthProvider.jsx exports only the component.

(A plain constant, such as a string, is allowed. The project's .oxlintrc.json turns that on, with allowConstantExport.)

Where to look

When you need to know how the logged-in user is kept, read AuthProvider.jsx. When you only need to use it, all you need is useAuth() from authContext.js. Every component imports that. No component imports AuthProvider: only main.jsx does (and two test files).

Try it

Add this function to the bottom of AuthProvider.jsx:

export function isLoggedIn(user) {
  return user !== null;
}

Run npm run lint. What does it say, and which line does it point to? Then delete the function again, and run npm run lint once more. What does oxlint print when there's nothing wrong?
