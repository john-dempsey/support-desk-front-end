Sharing Who's Logged In

Eight components need to know who is logged in. A React context lets each one ask, instead of having the user passed down to it as a prop.

  • Who Needs the User?

    The navigation bar, the protected routes, the login page and three other pages all need the logged-in user. Passing it to each one as a prop would work, but every component in the way would have to carry it.

  • You've Used a Context Already

    BrowserRouter is a context provider, and useParams() and useNavigate() read it. That's why a component with a <Link> fails in a test without a router.

  • Creating a Context

    createContext() makes the context, and useAuth() is a two-line hook that reads it. Every component asks for the logged-in user the same way.

  • Why Two Files?

    The context and its hook are in authContext.js, and the provider component is in AuthProvider.jsx. Keeping them apart lets Vite update components in place while you edit.
