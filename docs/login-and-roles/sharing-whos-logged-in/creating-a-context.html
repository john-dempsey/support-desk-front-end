Creating a Context

createContext() makes the context, and useAuth() is a two-line hook that reads it. Every component asks for the logged-in user the same way.

The first file is short:

// Figure 4.8: the context and its hook (src/context/authContext.js,
// excerpt)
import { createContext, useContext } from 'react';

export const AuthContext = createContext(null);

// The one way components get the auth value:
//   const { user, hasRole } = useAuth();
export function useAuth() {
  return useContext(AuthContext);
}

createContext(null)

createContext() makes a new, empty context: a named slot that a provider can later fill. The argument, null, is what a component gets if it reads the context with no provider above it. Here that only happens by mistake, as the Try it shows.

AuthContext is exported so that two files can fill it: AuthProvider in the app, and renderWithProviders in the tests.

useContext() and useAuth()

useContext(AuthContext) is a React hook. It returns the value from the nearest AuthContext provider above the component. When that value changes, every component that read it re-renders, as if its own state had changed.

useAuth() just calls it. It's a custom hook: a function of your own whose name starts with use and which calls other hooks. Writing useAuth() everywhere, instead of useContext(AuthContext), means components don't need to import the context at all, and reads better.

Custom hooks follow the same rule as useState: call them at the top of a component, never inside an if, a loop or an event handler.

Taking out what you need

useAuth() returns an object, and each component takes out only the parts it uses, by destructuring:

const { user, hasRole } = useAuth();   // TicketDetailPage
const { user, login } = useAuth();     // LoginPage
const { isCheckingSession } = useAuth(); // App

It's the same { } as props in a component's parameter list.
