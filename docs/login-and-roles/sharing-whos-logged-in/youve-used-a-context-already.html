You've Used a Context Already

BrowserRouter is a context provider, and useParams() and useNavigate() read it. That's why a component with a <Link> fails in a test without a router.

Contexts aren't new to this app. One has been there since Stage 0.

main.jsx wraps the whole app in <BrowserRouter>. Nothing passes the URL down to TicketDetailPage as a prop, yet useParams() can read :ticketId from it. And useNavigate() works in any page. How?

BrowserRouter is a provider: it puts the router's information (the current URL, a way to change it) into a context. useParams(), useNavigate(), <Link> and <NavLink> all read that context, wherever they are inside it.

The error you've seen

Stage 1, topic 07 showed this error from a test that rendered a <Link> with no router around it:

Cannot destructure property 'basename' of 'React$1.useContext(...)' as it is null.

Now it makes sense. <Link> calls useContext(...) to read the router's context. With no BrowserRouter (or MemoryRouter) above it, there's nothing to read, so it gets null, and taking basename out of null fails.

Two halves

Every context has the same two halves:

The router The logged-in user
Provider: puts a value in place, for everything inside it <BrowserRouter> <AuthProvider>
Hook: reads that value, from anywhere inside useParams(), useNavigate(), ... useAuth()

React Router wrote its half for you. Stage 4 writes the second column itself, in two short files. The next slide shows the first of them.

Blade and Laravel

The nearest thing in Laravel is auth()->user(), or @auth in a Blade view. Any controller or view can ask "who's logged in?" without being handed the user. useAuth() gives React components the same thing.
