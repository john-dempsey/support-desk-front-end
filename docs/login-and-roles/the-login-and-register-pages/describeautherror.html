describeAuthError

Two of the API's auth errors need saying in the user's own words: too many attempts, and an email that's already registered. A small function in utils/ rewords them for both pages.

Most of the API's error messages are fine to show as they are. Two aren't:

Status The API says Why that's not enough
429 "Too many requests — please try again later." It doesn't say how long, or that it's only logging in that's blocked
409 on register "A record with that User_email_key already exists" User_email_key is the name of a database index. It means nothing to a user

So both pages pass every error through one small function first:

// Figure 4.20: rewording two errors (src/utils/describeAuthError.js,
// excerpt)
export function describeAuthError(error) {
  if (error.status === 429) {
    return new Error(
      'Too many attempts. Wait a few minutes, then try again.'
    );
  }
  if (error.status === 409) {
    return new Error(
      'An account with that email already exists. Try logging in.'
    );
  }
  return error;
}

(Each return new Error(...) is one line in the file. They're split here to fit.)

Any other error comes back unchanged, details and all, so a 400 still reaches the form's fields.

Why a function, and why in utils/

Both LoginPage and RegisterPage need it, so it's written once. It has nothing to do with React: it takes an error and returns an error. Like getFieldError() and formatDate(), that makes it a plain function in utils/, and easy to test on its own (topic 10).

Stage 3's tags page did the same thing for its own 409 (Stage 3, topic 08). The API's message names the index there too.

The rate limit

The back-end allows 10 requests to /auth/login and /auth/register every 15 minutes from one address, successful or not (Lesson 6). It's there to stop someone guessing passwords. The 429 is what makes the first message necessary.

The API also tells the browser how many attempts are left, in a response header.

Try it

Log in once, then click the login request in the Network tab. Under Response Headers, find RateLimit-Remaining. How many attempts do you have left? What does RateLimit-Reset count?
