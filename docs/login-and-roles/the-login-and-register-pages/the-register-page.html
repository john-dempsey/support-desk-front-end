The Register Page

RegisterPage is LoginPage with a name field, a password rule, and register() instead of login(). A new account is always a customer, and is logged in straight away.

RegisterPage works exactly like LoginPage: controlled inputs, isSubmitting, describeAuthError(), and if (user) to leave once it's done. What's different:

LoginPage RegisterPage
Fields email, password name, email, password
Calls login(email, password) register(name, email, password)
Browser checks required, type="email" also maxLength={100} on the name, minLength={8} on the password
Field errors shown email name, email and password

The browser's limits match the back-end's registerSchema: a name of at most 100 characters, a password of at least 8.

Telling the user the rule first

A password rule is easier to follow if you know it before you type:

// Figure 4.21: the password field (src/pages/RegisterPage.jsx, excerpt)
<input
  id="register-password"
  type="password"
  autoComplete="new-password"
  required
  minLength={8}
  value={password}
  onChange={(event) => setPassword(event.target.value)}
  aria-invalid={Boolean(passwordError)}
  aria-describedby={
    passwordError
      ? 'register-password-hint register-password-error'
      : 'register-password-hint'
  }
/>
<p id="register-password-hint" className="field-hint">
  At least 8 characters.
</p>
<FieldError id="register-password-error" message={passwordError} />

(Less indented here than in the file.)

aria-describedby can name more than one id, separated by spaces. The hint is always linked, so a screen reader reads "At least 8 characters" when the field is reached. If the API sends an error for the password, its id is added too, and both are read.

Always a customer

The API's register always creates a customer (Lesson 4, "Register: Always a Customer"). There's no role field, and sending one would be ignored. Staff accounts are made another way, never through a public form.

The answer includes a token, so register() saves it and sets the user, just like login(). The new customer lands on the ticket list, already logged in, with an empty list and a New ticket link.

Try it

  1. Register with a name of only spaces. Which check lets it through, and which one stops it? Where does the message appear?
  2. Register with casey@example.com. What does the page say, and what did the API actually send? (Look at the Network tab.)
  3. Register yourself, with a real-looking name and a new email. What's in the navigation bar? Then reload the page. Are you still logged in?

Every registration creates a real user in the database, and counts towards the 10-attempt limit.
