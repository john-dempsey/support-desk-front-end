Login and Roles

Users log in instead of pasting a token into .env. The app knows who they are, shows each role only what it can use, and logs them out when their session ends.

  • What Stage 4 Adds

    Who this stage is for, what each kind of user sees, and which files change, before any of the code.

  • Logging In, and Keeping the Token

    The three requests about who the user is, where the token is kept between visits, what's inside it, and how it reaches every request.

  • Sharing Who's Logged In

    Eight components need to know who is logged in. A React context lets each one ask, instead of having the user passed down to it as a prop.

  • AuthProvider

    The component that holds the logged-in user, logs them in and out, and answers hasRole(). Everything inside it can read it with useAuth().

  • Checking the Session on Load

    After a reload, the token is still saved but the user is gone. The app asks the API who the token belongs to, and waits for the answer before showing any page.

  • The Login and Register Pages

    Two forms written inside their pages: what they send, how they leave once someone is logged in, and how they show the API's errors.

  • Protected Pages

    ProtectedRoute wraps a page in App.jsx's route table. It sends a visitor to the login page, and tells a user whose role can't use the page, before the page ever loads.

  • Controls by Role

    The navigation bar, the ticket list and the ticket page show each user only the links and buttons their role can use. That's for the user's sake: the API still checks every request.

  • When the Session Ends

    A token stops working after a day. When any request gets a 401, client.js tells AuthProvider, and the user is logged out from one place, whatever page they're on.

  • Testing Stage 4

    A fake logged-in user for page tests, the real AuthProvider tested on its own, the 401 handler, and a whole visit from login to logout.

  • Making It Yours

    Tracing a login through Stage 4, then adding login, register and roles to your own case study's front-end.
