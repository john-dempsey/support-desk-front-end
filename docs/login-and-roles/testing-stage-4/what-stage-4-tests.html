What Stage 4 Tests

Most page tests fake who is logged in. AuthProvider is tested on its own, with only its API calls faked. And one test follows a whole visit through the real app.

Stage 4's code is about who is using the app. So its tests have to decide who that is, the same way Stage 2's tests decided what "the API" sent back.

There are two ways to do that, and Stage 4 uses both:

  • Most tests fake the logged-in user. A page test isn't testing login. It needs a user so the page knows what to show, and a fake user is quicker and clearer than logging in.
  • AuthProvider is tested for real, with only auth.api.js faked. Its tests check what it does with the API's answers: save the token, set the user, clear both.

Try it

Open src/utils/describeAuthError.test.js next to describeAuthError.js. The last test passes a 401, and checks the result with toBe(error), not toEqual. Why does toBe prove the error came back unchanged? Add a fourth test: a 400 with details, checking that result.details is still there.
