A Fake Logged-In User

renderWithProviders now fills the auth context with a fake value. A test says who is logged in with `user`, and Ada is the default, so Stage 3's tests didn't change.

Stage 1's renderWithProviders put a router around the component. It now puts the auth context around it too:

// Figure 4.33: two providers for a test
// (src/test/renderWithProviders.jsx, excerpt)
export function renderWithProviders(
  componentToTest,
  { route = '/', path, user = adminUser } = {},
) {
  // ... the Routes for `path`, as in Stage 1

  const auth = createFakeAuth(user);
  const result = render(
    <AuthContext value={auth}>
      <MemoryRouter initialEntries={[route]}>{content}</MemoryRouter>
    </AuthContext>,
  );
  return { ...result, auth };
}

(The // ... line stands for code left out here.)

createFakeAuth(user) is Figure 4.13 from topic 04: the same six names AuthProvider provides, with login, register and logout as vi.fn() fakes, and a real hasRole().

Choosing who's logged in

The new option, user, says who it is:

renderWithProviders(<NavBar />, { user: customerUser }); // Casey
renderWithProviders(<NavBar />, { user: agentUser });    // Alex
renderWithProviders(<NavBar />, { user: null });         // nobody
renderWithProviders(<NavBar />);                          // Ada

The three users are in src/test/testUsers.js, in the shape the API sends. Their ids match the customer and the comment authors in testTickets.js and testComments.js, so a test can check, for example, that Casey may delete Casey's own comment.

Why Ada by default

Stage 3's page tests were written when every control was shown. With Ada, an admin, as the default user, they still see every control, and didn't need to change. Only tests that are about a role pass user.

It returns the fake

renderWithProviders now returns auth too, so a test can check what the component asked for: expect(auth.logout).toHaveBeenCalled().

Try it

In renderWithProviders.jsx, change the default to user = customerUser (and import customerUser). Run npm test. How many tests fail, and in which files? What do they have in common? Put it back when you're done.
