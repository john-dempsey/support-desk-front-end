Checking What the Page Asked For

In a page test, login() is a vi.fn(). The test checks it was called with what was typed, and makes it fail to see how the page shows the error.

LoginPage doesn't call the API itself: it calls login() from useAuth(). In a test, that's the fake from renderWithProviders, so the test can check what the page asked for:

// Figure 4.35: testing the login form
// (src/pages/LoginPage.test.jsx, excerpt)
// Nobody is logged in, so the login form shows.
function renderLoginPage() {
  return renderWithProviders(<LoginPage />, {
    route: '/login', user: null,
  });
}

it('sends the email and password to login()', async () => {
  const { auth } = renderLoginPage();

  await fillInAndSubmit();

  expect(auth.login)
    .toHaveBeenCalledWith('casey@example.com', 'password123');
});

it("shows the API's message for a wrong email or password", async () => {
  const { auth } = renderLoginPage();
  auth.login.mockRejectedValue(
    createApiError(401, 'Invalid email or password'),
  );

  await fillInAndSubmit();

  expect(await screen.findByRole('alert'))
    .toHaveTextContent('Invalid email or password');
  expect(screen.getByRole('button', { name: 'Log in' })).toBeEnabled();
});

(Less indented, and split to fit. fillInAndSubmit() types the email and password and clicks Log in, as Stage 3's form tests did.)

Two things to check

  • What went out. auth.login is a vi.fn(), so toHaveBeenCalledWith checks the page passed exactly what was typed. It's Stage 3's "check what was sent", one step earlier: at the context, not the API module.
  • What came back. mockRejectedValue() makes the fake login() throw, as the real one does on a 401. The test then checks the message appears, and the button can be clicked again.

The user: null matters: with anyone logged in, the page would leave straight away (topic 06), and there'd be no form to fill in.

A test that doesn't test AuthProvider

None of these tests check that the token was saved, or that the user was set. That's AuthProvider's job, and its own tests check it (slide 06). Each test file tests one thing, and fakes the rest.
