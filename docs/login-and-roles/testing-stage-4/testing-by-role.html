Testing by Role

A role test renders the same page as different users, and checks what's there and what isn't. queryBy... finds nothing without failing, so it can prove a button is missing.

The ticket page's role tests render the same page twice, as two different users:

// Figure 4.34: as a customer, then as an agent
// (src/pages/TicketDetailPage.test.jsx, excerpt)
it("doesn't show a customer Edit or Delete", async () => {
  getTicket.mockResolvedValue(ticketAssignedToAlex);

  renderWithProviders(<TicketDetailPage />, {
    route: '/tickets/1',
    path: DETAIL_PATH,
    user: customerUser,
  });
  await screen.findByRole('heading', { level: 1, name: 'Cannot log in' });

  expect(screen.queryByRole('link', { name: 'Edit ticket' }))
    .not.toBeInTheDocument();
  expect(screen.queryByRole('button', { name: 'Delete ticket' }))
    .not.toBeInTheDocument();
});

it('shows an agent Edit and Delete', async () => {
  // ... the same, with user: agentUser
  expect(await screen.findByRole('link', { name: 'Edit ticket' }))
    .toBeInTheDocument();
});

(Less indented, and split to fit. The second test is shortened.)

queryBy... to prove something is missing

getByRole() throws if it finds nothing, so the test would fail before it reached expect. queryByRole() returns null instead, and .not.toBeInTheDocument() checks for exactly that.

Query Finds it Finds nothing
getBy... returns it throws: the test fails
queryBy... returns it returns null
findBy... returns it, once it appears waits, then throws

Wait first, then check what's missing

The first await screen.findByRole('heading', ...) matters. Before the fake API answers, the page shows "Loading the ticket…", and there's no Edit link on a loading page either. Checking then would pass for the wrong reason. Waiting for the heading makes sure the page has loaded, so a missing button is really missing.

One test per answer

There's a test for "no" (the customer) and for "yes" (the agent). A test that only checked the customer would also pass if the buttons were never shown to anyone.
