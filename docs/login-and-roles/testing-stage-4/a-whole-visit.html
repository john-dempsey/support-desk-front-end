A Whole Visit

One App test uses the real AuthProvider with only the API modules faked, and follows a visit from start to finish: log in, move around, log out, and log in as someone else.

Most tests check one piece. One test in App.test.jsx checks how the pieces work together, over a whole visit. It uses the real AuthProvider, the real routes and the real pages. Only the API modules are faked.

// Figure 4.40: log in, move, log out, log in again
// (src/App.test.jsx, excerpt)
login.mockResolvedValueOnce({ user: adminUser, token: 'ada-token' });
login.mockResolvedValueOnce({ user: customerUser, token: 'casey-token' });
getTickets.mockResolvedValue({
  tickets: testTickets, meta: { page: 1, totalPages: 3 },
});
render(
  <MemoryRouter initialEntries={['/login']}>
    <AuthProvider>
      <App />
    </AuthProvider>
  </MemoryRouter>,
);

// Ada logs in, moves to page 2, and logs out.
await logInAs('ada@example.com');
await userEvent.click(await screen.findByRole('button', { name: 'Next' }));
expect(getTickets).toHaveBeenLastCalledWith('page=2');
await userEvent.click(screen.getByRole('button', { name: 'Log out' }));

// Casey logs in, and the list is asked for with no query at all.
await logInAs('casey@example.com');
expect(getTickets).toHaveBeenLastCalledWith('');

(Less indented, and split to fit. logInAs() fills in the login form, clicks Log in, and waits for the ticket list.)

mockResolvedValueOnce, twice

mockResolvedValueOnce() sets the answer for one call. Called twice, it queues two answers: the first login() gets Ada, the second gets Casey. It's how one test can log in as two different people.

What it proves

Each step relies on the pieces from this lesson:

  1. Logging in goes through LoginPage, login() and the if (user) redirect, and lands on the ticket list.
  2. Next changes the URL to ?page=2 (Stage 3), and the list asks for page 2.
  3. Log out clears the user, and NavBar goes to the login page.
  4. Casey logs in and lands on the plain ticket list, /tickets, so the list is asked for with an empty query: nothing from Ada's visit carries over.

It's the only test that does all four, so it's the one that would catch the pieces not fitting together.

Try it

In LoginPage.jsx, delete the if (user) { ... } block. Run the tests. Two fail: which, and why does each one need that block? Put it back when you're done.
