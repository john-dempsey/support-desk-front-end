Testing the Real AuthProvider

AuthProvider has no screen of its own, so its tests put a tiny component inside it that shows what useAuth() gives. Only auth.api.js is faked; localStorage is real.

AuthProvider renders nothing but its children. To see what it's doing, the test gives it a child made for the purpose:

// Figure 4.37: a component that shows the context
// (src/context/AuthProvider.test.jsx, excerpt)
function ShowAuth() {
  const auth = useAuth();

  if (auth.isCheckingSession) {
    return <p>Checking…</p>;
  }

  return (
    <>
      <p>{auth.user ? `Logged in as ${auth.user.name}` : 'Logged out'}</p>
      <button type="button"
        onClick={() => auth.login('casey@example.com', 'password123')}>
        Log in
      </button>
      <button type="button" onClick={auth.logout}>
        Log out
      </button>
    </>
  );
}

(The first <button> tag is one line in the file.)

ShowAuth uses useAuth() exactly as a real component does. So the test checks AuthProvider the way the app sees it: by what's on the screen.

A saved token, checked

// Figure 4.38: the session check (src/context/AuthProvider.test.jsx,
// excerpt)
it('checks a saved token with GET /auth/me, and logs that user in',
  async () => {
    saveToken('saved-token');
    getCurrentUser.mockResolvedValue(customerUser);

    renderAuthProvider();

    expect(screen.getByText('Checking…')).toBeInTheDocument();
    expect(await screen.findByText('Logged in as Casey Customer'))
      .toBeInTheDocument();
  });

(Split to fit.)

saveToken() is the real one, so the token really is in localStorage before AuthProvider starts, just as after a reload. getCurrentUser is faked (vi.mock('../api/auth.api.js')), and the test checks both states: "Checking…" first, then the user.

Cleaning up localStorage

localStorage lasts between tests, just as it lasts between visits. A token one test saved would still be there for the next. So setup.js now clears it after every test, next to cleanup():

afterEach(() => {
  cleanup();
  localStorage.clear();
});

Try it

In src/test/setup.js, delete the localStorage.clear(); line and run npm test. How many tests fail, and in which files? Pick one and explain where its extra token came from. Then put the line back.
