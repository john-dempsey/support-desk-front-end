Only If Your API Has a Login

Stage 4 needs an API with authentication. If yours has none, your Stage 3 app is already complete.

This stage needs an API with authentication: Step 4 of the back-end assignment. If your own API has no login, stop at Stage 3. Your app is complete and working without this stage: nothing in Stages 1 to 3 depends on a login, a role or a token. You can go on to the parts of Stage 6 that don't need a login.

The Support Desk API has had authentication since Lesson 4, "Auth & Authorization":

  • POST /auth/register and POST /auth/login answer with a token
  • authenticate.js refuses a request without a valid token (401)
  • authorize(...) refuses a role that isn't allowed (403)

Lesson 7 added GET /auth/me for this stage: "who does this token belong to?"

The stand-in token goes

In Stages 2 and 3, you logged in with a REST client as Ada, and pasted Ada's token into .env as VITE_DEV_TOKEN. Every request used it, so the app always acted as Ada, an admin, whoever was using it.

Stage 4 replaces that with a real login:

  • A login page and a register page. The user's token comes from the API when they log in, not from .env.
  • The app knows who's using it. The navigation bar shows their name and role, and a Log out button.
  • Each role sees what it can use. A customer gets New ticket; an agent or admin gets Edit, Delete and Tags.
  • A session can end. Tokens last one day. When one runs out, the user is logged out and sent to the login page, instead of every page showing an error.

Try it

Before you start, check your own API is ready. In your REST client:

  1. Send a request to one of your protected routes without a token. Do you get a 401?
  2. Log in. Does the answer include a token?
  3. Send the first request again with that token, as Authorization: Bearer <token>. Does it work now?

If all three do, your API is ready for Stage 4. If not, your app is finished at Stage 3.
