What Changes, and What Doesn't

Stage 4 adds a context folder, two pages and a ProtectedRoute, and changes the pages that show buttons by role. None of the ticket, comment or tag API modules change.

Here's every file in src/ that Stage 4 touches, leaving out the tests (topic 10):

Folder New Changed
api/ auth.api.js, tokenStorage.js client.js: getToken() (topic 02), and one addition (topic 09)
context/ authContext.js, AuthProvider.jsx README.md
pages/ LoginPage, RegisterPage TicketListPage, TicketDetailPage, HomePage: what shows depends on the user
components/ ProtectedRoute NavBar: links by role, the user's name, Log out. CommentList: Delete only where allowed
utils/ describeAuthError.js
main.jsx: wraps the app in AuthProvider. App.jsx: two routes, and ProtectedRoute around the others. index.css: the user's name in the header

NewTicketPage, EditTicketPage and TagsPage change only in their top comments.

The context/ folder has been in the project since Stage 0, holding only a README.md that said this stage would fill it.

What doesn't change

  • tickets.api.js, comments.api.js, tags.api.js, users.api.js. Not one line. None of them has ever handled the token: client.js adds it to every request (Stage 2, topic 02). So when the token starts coming from a login instead of .env, only client.js needs to know.
  • The Stage 3 forms: TicketForm, CommentForm and TagForm.

VITE_DEV_TOKEN is gone

Nothing reads VITE_DEV_TOKEN any more, and .env.example now lists only VITE_API_URL. Delete the VITE_DEV_TOKEN line from your own .env. A token you don't need is just one more secret lying around.

Once you've got the stage-04 code, list every file in src/ that changed since the end of Stage 3:
