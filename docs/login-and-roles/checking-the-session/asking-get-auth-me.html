Asking GET /auth/me

An effect runs once when the app starts. With a saved token, it asks who the token belongs to, and either sets the user or clears the token.

// Figure 4.15: checking the session (src/context/AuthProvider.jsx,
// excerpt)
// When the app first loads, ask the API who the saved token belongs to.
useEffect(() => {
  if (getSavedToken() === null) {
    return;
  }

  let ignore = false;

  async function checkSession() {
    try {
      const currentUser = await authApi.getCurrentUser();
      if (!ignore) {
        setUser(currentUser);
      }
    } catch {
      // Usually a 401: the token has expired, or its user is gone. ...
      if (!ignore) {
        clearSavedToken();
      }
    } finally {
      if (!ignore) {
        setIsCheckingSession(false);
      }
    }
  }

  checkSession();

  return () => {
    ignore = true;
  };
}, []); // [] = only once, when the app starts

(Indented one step further in the file. The comment in catch is longer there.)

It's the same shape as every page that loads data since Stage 2: an effect, an async function inside it, try/catch/finally, and the ignore flag. The differences:

  • []: it runs once, when the app starts, not when something changes.
  • No token, no request. It returns straight away. isCheckingSession already started as false.
  • The answer sets the user, instead of a list of tickets.

Every failure means "logged out"

Whatever goes wrong, the catch does the same thing: forget the token. Usually it's a 401: the token has expired, or the user it names no longer exists. If the API isn't running at all, the user is logged out too. That keeps the code short, and costs little: they can log in again, and the login page will say if the API can't be reached.

finally runs either way, so the app always stops waiting.
