A Token, but No User

A reload wipes React's state but not localStorage. So the app starts with a saved token and no user, and has to find out who the token belongs to.

Log in, then press F5. React starts again from nothing, so every piece of state is back to its first value, including user, which is null.

But the token is still in localStorage (topic 02). So the app starts in an odd position: it has proof that someone logged in, but doesn't know who.

Three ways to find out

Option Why not, or why
Decode the token, and read the role from it It can't be checked in the browser (topic 02, "What's Inside a Token")
Save the user in localStorage as well The copy could be out of date, and an expired token would look fine until the first request failed
Ask the API: GET /auth/me The API checks the token and answers with the user as they are now

The back-end added GET /auth/me in Lesson 7 for exactly this.

Starting in the right state

AuthProvider has a second piece of state for the time it takes to ask:

// Figure 4.14: two pieces of state (src/context/AuthProvider.jsx,
// excerpt)
const [user, setUser] = useState(null);
// Only a saved token needs checking. With none, there's nothing to wait
// for: the user is logged out.
const [isCheckingSession, setIsCheckingSession] =
  useState(getSavedToken() !== null);

(Indented one step further in the file, where the second useState is on one line.)

isCheckingSession starts as true only if there's a token to check. With no saved token, there's nothing to ask, and nothing to wait for.

useState() only uses its starting value on the first render. So getSavedToken() !== null decides how the app starts, and after that, only setIsCheckingSession() changes it.
