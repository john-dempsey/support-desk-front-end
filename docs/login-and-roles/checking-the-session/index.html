Checking the Session on Load

After a reload, the token is still saved but the user is gone. The app asks the API who the token belongs to, and waits for the answer before showing any page.

  • A Token, but No User

    A reload wipes React's state but not localStorage. So the app starts with a saved token and no user, and has to find out who the token belongs to.

  • Asking GET /auth/me

    An effect runs once when the app starts. With a saved token, it asks who the token belongs to, and either sets the user or clears the token.

  • Why App Waits

    While the session is being checked, App shows a message instead of the routes. Without it, a logged-in user who reloads a ticket's page would end up on the ticket list.
