Why App Waits

While the session is being checked, App shows a message instead of the routes. Without it, a logged-in user who reloads a ticket's page would end up on the ticket list.

// Figure 4.16: waiting for the answer (src/App.jsx, excerpt)
function App() {
  const { isCheckingSession } = useAuth();

  // While a saved token is being checked, nobody knows yet whether the
  // user is logged in. Showing the routes now would make ProtectedRoute
  // send a logged-in user to /login for a moment, so wait.
  if (isCheckingSession) {
    return (
      <main className="container">
        <Loading message="Checking your session…" />
      </main>
    );
  }

  return (
    <>
      <NavBar />
      <main className="container">
        {/* … the routes, as before */}
      </main>
    </>
  );
}

(The routes are left out here.)

While the check runs, App shows Stage 0's Loading component and nothing else: no navigation bar, no page. When finally sets isCheckingSession to false, App re-renders and shows the routes, with user already set (or not).

What would go wrong without it

Say Casey is on /tickets/1, and reloads. Without the wait:

  1. The routes show straight away, while user is still null.
  2. /tickets/1 is a protected page (topic 07), so with no user, the app goes to /login.
  3. The check finishes, and user is set. The login page sees a user, and sends Casey to /tickets.

Casey is logged in, but on the ticket list instead of ticket 1. Nothing crashed, but the reload lost Casey's place.

The wait is short, usually a fraction of a second. The answer to GET /auth/me decides what every page shows, so nothing is shown until it arrives.

Try it

  1. Log in as Casey, and open /tickets/1. In the Network tab, set the throttling to Slow 4G, and reload. Watch for "Checking your session…".
  2. In App.jsx, put // in front of each line of the if (isCheckingSession) { ... } block. Save, then reload on /tickets/1, still on Slow 4G. Where do you end up?

Remove the //s, and set the throttling back to No throttling.
