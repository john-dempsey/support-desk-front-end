act(): Let React Finish

A state update doesn't redraw the page straight away. act() runs some code, then makes React finish every redraw and effect it caused. Testing Library already does this for render, clicks and findBy.

When a component calls a state setter, React doesn't redraw the page there and then. It notes the change, and redraws a moment later, once the code that's running has finished. That's usually what you want: several changes in a row cause one redraw, not several.

In a test it's a problem. The test is the code that's running, so if it causes a change and then checks the page at once, React hasn't redrawn yet.

What act() does

act(callback) runs the callback, then makes React finish all the work it caused, redraws and effects, before act itself finishes. When the line after act runs, the page is up to date.

You've used it all along without seeing it. Testing Library wraps these in act() for you:

  • render() and rerender()
  • every userEvent call
  • each try inside findBy... and waitFor

So act() only appears in a test when the change comes from somewhere Testing Library doesn't know about. In Stage 5, that's a push from the "server":

// Figure A.25: a push from outside (src/test/fakeSocket.js, excerpt)
async push(notification) {
  if (savedHandler === null) {
    throw new Error('Nothing is listening: render the component first.');
  }
  await act(async () => {
    savedHandler(notification);
  });
},

(Stage 5's version, without its comment. It's a method of the object captureNotificationHandler() returns, so it's indented two levels further in the file.) Calling savedHandler is ordinary code calling a function. The page's state changes, and act waits for the redraw.
