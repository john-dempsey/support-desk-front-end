rerender(): the Same Component, Updated

rerender() draws new JSX in the same place, so React updates the components already there and runs their cleanups. Calling render() again adds a second, separate copy.

NotificationsProvider.test.jsx "logs out" by drawing the provider again with no user:

// Figure A.27: logging out (src/context/NotificationsProvider.test.jsx,
// excerpt)
const { rerender } = render(providersFor(agentUser));
await screen.findByText('1 unread');

rerender(providersFor(null));

expect(stopListening).toHaveBeenCalled();
expect(disconnectSocket).toHaveBeenCalled();
expect(screen.getByText('0 unread')).toBeInTheDocument();

(Stage 5's version, the end of a test. It's indented one level further in the file.)

Same place or new place?

rerender(jsx) render(jsx) again
Where it draws into the same <div> into a new <div>
What React does compares old and new, and updates the components already there starts a second, separate copy
State kept the new copy starts fresh
Effects cleanups run, then effects re-run, for any whose dependencies changed the first copy's effects are untouched

rerender is how a test plays "the props changed": here, the user the provider reads went from Alex to null. That's exactly what happens in the app on logout, so the provider's effect cleanup runs: it stops listening and disconnects.

render() also returns unmount(), which removes what it drew and runs every cleanup, as when the user leaves the page.
