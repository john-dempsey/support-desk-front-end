A Mock Factory, Step by Step

With a factory, Vitest runs your function to build the fake module, at the moment something first imports it. That happens before the file's own lines, which is why the fake socket needs vi.hoisted().

socket.test.js replaces the socket.io-client library with a factory: a function that builds the fake module by hand.

// Figure A.26: a factory (src/realtime/socket.test.js, excerpt)
const fakeSocket = vi.hoisted(() => {
  // ... on, off, fire, and vi.fn()s for emit, connect, disconnect
});

vi.mock('socket.io-client', () => ({
  io: () => fakeSocket,
}));

(Stage 5's version, with fakeSocket's body left out.)

vi.mock(path) vi.mock(path, factory)
The fake module is built by Vitest from the real one's exports whatever the factory returns
Each function is a vi.fn() returning undefined whatever you write
An export the factory leaves out (can't happen) is missing

The order things really run in

Vitest moves vi.mock and vi.hoisted above the imports (topic 04). So the file runs in this order:

  1. vi.hoisted(...): fakeSocket is built
  2. vi.mock(...): Vitest notes the factory, but doesn't run it yet
  3. the imports: socket.js is imported, and it imports socket.io-client. That's when the factory runs, and socket.js calls io() and gets fakeSocket.
  4. the rest of the file, from top to bottom

Step 3 happens before any ordinary line of the test file. If fakeSocket were a plain const, it wouldn't exist yet when io() asks for it. vi.hoisted moves its code up to step 1.
