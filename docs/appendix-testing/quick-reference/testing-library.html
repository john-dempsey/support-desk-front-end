Testing Library, user-event and jest-dom at a Glance

Rendering, finding, waiting, acting like a user, and the checks for elements: every part of the three Testing Library packages the app's tests use.

React Testing Library ('@testing-library/react')

Function Does Topic
render(jsx) adds a <div> to the page and draws jsx in it, effects and all 05
rerender(jsx) draws new jsx in the same place, updating what's there 10
renderHook(fn) runs a hook inside a test component; its latest return value is result.current 11
screen the queries, searching the whole page 05
within(element) the same queries, searching inside element 06
waitFor(check) runs check until it stops throwing, for up to 1 s 11
act(fn) runs fn, then lets React finish every redraw it caused 10
cleanup() removes everything render added (in setup.js) 03

Queries: kind + what they search by

Kind One match None Topic
getBy... returns it throws 05
queryBy... returns it returns null 05
findBy... resolves with it keeps trying, then rejects 05, 07
getAllBy..., findAllBy... return an array of all matches as above 06

The app searches ByRole (with name and level), ByLabelText and ByText. A string must match the whole text; a regular expression can match part (topic 06).

user-event ('@testing-library/user-event')

Every call is async, so it's always awaited (topic 08).

Function Does
userEvent.click(element) moves the pointer, presses and releases, and clicks
userEvent.type(element, 'text') clicks, then presses each key; {enter} and friends press special keys
userEvent.selectOptions(select, 'Option text') chooses an option in a <select>
userEvent.clear(element) empties an input

Try it

Choose one page test you haven't read closely, such as NotificationsPage.test.jsx. For each test in it, write one line: what it fakes, what it does like a user, and what it checks, naming each function from these tables. Then break the page so that exactly one of its tests fails, and predict the message before you run it.
