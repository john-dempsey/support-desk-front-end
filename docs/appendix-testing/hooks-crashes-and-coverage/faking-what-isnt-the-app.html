Faking What Isn't the App's

ErrorBoundary's tests fake two things the app doesn't own: console.error, to keep the output quiet while still counting calls, and import.meta.env.DEV, to pretend to be the production build.

// Figure A.29: two fakes (src/components/ErrorBoundary.test.jsx,
// excerpt)
function silenceConsoleErrors() {
  vi.spyOn(console, 'error').mockImplementation(() => {});
}

// ... and, in the last test:
    // Pretend this is the production build, where DEV is false.
    vi.stubEnv('DEV', false);

(Stage 6's version, two excerpts.)

A spy that says nothing

React logs every error a boundary catches with console.error (Stage 6, topic 04). That's useful in a browser and just noise in a test that crashes on purpose. The spy (topic 08) replaces error on the console object, and mockImplementation(() => {}) makes it do nothing. But it's still a fake, so it still records each call, and the test can check React did report the crash: expect(console.error).toHaveBeenCalled().

A different build, in one line

import.meta.env.DEV is true in tests and npm run dev, and false in the production build. ErrorBoundary reads it while it renders, to decide whether to show the error's message:

// Figure A.30: development only (src/components/ErrorBoundary.jsx,
// excerpt)
{import.meta.env.DEV && (
  <p>Details (development only): {this.state.error.message}</p>
)}

(One line in the file, reflowed here to fit, with brackets added.)

Because it reads the value late, at render time, vi.stubEnv('DEV', false) before rendering is enough: the same reason it worked for getToken() in topic 07.

Try it

  1. Make silenceConsoleErrors do nothing: add return; as its first line. Run npx vitest run src/components/ErrorBoundary.test.jsx. The output fills with Error: Broken on purpose and a long stack trace, and one test fails: TypeError: [Function error] is not a spy or a call to a spy!. Which line asked, and why can't it ask the real console.error?
  2. Put it back, then put // in front of the vi.stubEnv line. Which test fails, and what did it find? Remove the //.
