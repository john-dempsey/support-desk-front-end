How Coverage Is Counted

Node's JavaScript engine counts how often each piece of code runs. The coverage report is those counts after the tests finish, mapped back to your source lines.

Stage 6's npm run coverage (Stage 6, topic 06) reports which lines no test ran. It doesn't guess from reading the tests. It counts.

  1. Node runs JavaScript with an engine called V8 (the same one as Chrome). V8 can keep a count of how many times each function and each branch actually runs.
  2. With --coverage, Vitest switches that counting on in every test file's process, through @vitest/coverage-v8.
  3. The tests run as usual.
  4. Afterwards, the counts are collected and mapped back to your source files. That step matters, because V8 ran the code Vite produced from your JSX, not the .jsx file itself.
  5. Anything with a count of 0 is "uncovered".

So coverage only knows what ran, not what was checked. A line that runs during a test is covered even if no expect looks at what it did (Stage 6, topic 06, "100% isn't the goal").

One test file, one covered file

Run coverage for a single test file:

npx vitest run --coverage src/utils/formatDate.test.js

The table still lists every file (because of include in vite.config.js), but nearly all of it is 0%:

File               | % Stmts | % Branch | % Funcs | % Lines |
All files          |    0.98 |     0.78 |    0.63 |    0.99 |
  client.js        |       0 |        0 |       0 |       0 |
  useFetch.js      |       0 |        0 |       0 |       0 |
  formatDate.js    |     100 |      100 |     100 |     100 |

(Three rows of the table, with the last column left out.) Only the code this test file ran was counted.

Try it

Run the command above, then the same with src/api/client.test.js instead. Is client.js at 100% now? Which other file gets some coverage too, and why? (Look at what client.js imports.) Then open coverage/index.html and find a line marked red in client.js. Delete the coverage folder afterwards (it's in .gitignore).
