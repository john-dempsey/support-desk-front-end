A Helper That Hands Back Its Fakes

renderWithProviders makes new vi.fn() fakes on every call, puts them where the page will find them, and returns them so the test can program and check them.

Stage 4's renderWithProviders wraps the component in a fake auth value as well as a router (Stage 4, topic 10). The fake is made by a function, so every call gets new fakes:

// Figure A.22: fresh fakes on every call
// (src/test/renderWithProviders.jsx, excerpt)
function createFakeAuth(user) {
  return {
    user,
    isCheckingSession: false,
    login: vi.fn(),
    register: vi.fn(),
    logout: vi.fn(),
    hasRole: (...roles) => user !== null && roles.includes(user.role),
  };
}

(Stage 4's version, without its comment.)

The helper then returns them, next to what render() returned: return { ...result, auth };. A test takes what it needs with destructuring:

// Figure A.23: programming the page's login()
// (src/pages/LoginPage.test.jsx, excerpt)
const { auth } = renderLoginPage();
auth.login.mockRejectedValue(
  createApiError(401, 'Invalid email or password'),
);

await fillInAndSubmit();

(Stage 4's version, the start of a test. The second statement is one line in the file, split here to fit.)

Told what to answer after render?

The fake is programmed after the page is on screen. That's fine, because a fake only looks at its answer when it's called, and LoginPage only calls login() when the form is submitted. Topic 07's rule again: what matters is that the fake is ready before the code uses it.

A fake only where a fake helps

login, register and logout are fakes, because tests check that they were called. hasRole is a small real function. Pages use its answer to decide which buttons to show. A bare vi.fn() would always answer undefined, so every role-only control would vanish, in every test.

Try it

In createFakeAuth, replace the hasRole line with hasRole: vi.fn(), and run npm test. 13 tests fail, in 5 files. Pick one failure: which button or field couldn't the test find, and why? Put the line back.
