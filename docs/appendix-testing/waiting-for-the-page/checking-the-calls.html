Checking the Calls

toHaveBeenCalledWith reads the fake's mock.calls for you, and passes if any one call had exactly these arguments. Its failure message lists every call it saw.

tickets.api.js's tests fake the layer under it, client.js, and check what getTicket() asked it for:

// Figure A.17: what was asked for (src/api/tickets.api.test.js, excerpt)
vi.mock('./client.js');

describe('tickets.api', () => {
  // ...
  it('getTicket(id) calls GET /tickets/:id and returns the ticket',
    async () => {
      const ticket = { id: 2, subject: 'Invoice discrepancy' };
      apiRequest.mockResolvedValue({ data: ticket });

      const result = await getTicket('2');

      expect(apiRequest).toHaveBeenCalledWith('/tickets/2');
      expect(result).toEqual(ticket);
    });
});

(Stage 2's version, with the first test left out and the second test's first line split to fit.)

What toHaveBeenCalledWith compares

Topic 04 read fakeFetch.mock.calls[0][0] by hand. toHaveBeenCalledWith(...) does that for you:

  • it looks through every call in mock.calls
  • it passes if any one of them had exactly these arguments, the same number of them, each compared like toEqual (so objects are compared by contents)

So toHaveBeenCalledWith('/tickets/2') fails if apiRequest was called with '/tickets/2' and a second argument.

Reading the failure

When it fails, the message shows each call it did see, marked up against what you expected. With '/tickets/3' in the test:

AssertionError: expected "vi.fn()" to be called with arguments:
[ '/tickets/3' ]

Received:

  1st vi.fn() call:

  [
-   "/tickets/3",
+   "/tickets/2",
  ]

Number of calls: 1

(The first line is one line in the terminal.) - is what you expected, + is what happened.

Try it

  1. Change the test to expect '/tickets/3' and read the message. Put it back.
  2. Add expect(apiRequest).toHaveBeenCalledTimes(1); to the test. Does it pass? Then call getTicket('2') a second time before the checks. Which of the three checks fail now? Remove what you added.
