Reading .env Late

vi.stubEnv changes import.meta.env while the test runs. It only works because getToken() reads the value each time it's called, not once when the file loads.

Stage 2's client.test.js uses vi.stubEnv('VITE_DEV_TOKEN', '') so a test doesn't see your real token (Figure 2.24, Stage 2, topic 07). It works because of when client.js reads the value:

// Figure A.18: reading the token (src/api/client.js, excerpt)
export function getToken() {
  return import.meta.env.VITE_DEV_TOKEN || null;
}

(Stage 2's version.)

In a test, import.meta.env is an ordinary object, filled from .env when the file starts. vi.stubEnv(name, value) changes one property on it, and unstubEnvs (Figure 2.25) puts it back. getToken() reads the property every time it's called, so it sees whatever the test set.

Too early to change

Now picture client.js reading the token once, when the file loads:

const DEV_TOKEN = import.meta.env.VITE_DEV_TOKEN || null;

export function getToken() {
  return DEV_TOKEN;
}

The file is loaded when the test file imports it, before any test runs. By the time a test calls vi.stubEnv, DEV_TOKEN already holds the token from .env, and changing import.meta.env afterwards changes nothing.

The same goes for vi.stubGlobal and vi.mock: a fake only helps if the code looks for the real thing after the fake is in place. That's why vi.mock has to be moved above the imports (topic 04).

Try it

Make sure your .env has a VITE_DEV_TOKEN. In client.js, change getToken() to the version above and run npx vitest run src/api/client.test.js. Two tests fail:

AssertionError: expected 'Bearer my-real-token' to be undefined
AssertionError: expected 'Bearer my-real-token' to be 'Bearer test-token'

(with your token in place of my-real-token). Put getToken() back. client.js reads API_URL the early way: why would vi.stubEnv('VITE_API_URL', ...) in a test have no effect on it?
