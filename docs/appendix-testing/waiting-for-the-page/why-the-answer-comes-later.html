Why the Answer Comes Later

A fake that resolves at once still answers after render() returns, because an await always waits for the running code to finish. findBy gives the page that chance.

// Figure A.15: waiting for the ticket
// (src/pages/TicketDetailPage.test.jsx, excerpt)
it('shows the ticket from the API', async () => {
  getTicket.mockResolvedValue(unassignedTicket);

  renderPageAt('/tickets/2');

  expect(
    await screen.findByRole('heading', {
      level: 1, name: 'Invoice discrepancy',
    }),
  ).toBeInTheDocument();

(Stage 2's version, with the first expect reflowed to fit and the test's other three checks left out. It's indented one level further in the file.)

The fake's promise has already resolved before the page even asks for it. So why can't the test use getByRole straight after renderPageAt? A throwaway test checked: straight after render, the heading wasn't there, and the loading message was.

await always waits its turn

JavaScript runs one piece of code at a time. When code reaches await, it stops there, and the rest of it is put in a queue to run later. That happens even when the promise has already resolved: the rest only runs once the code that's running now has finished.

The code running at step 2 is the test. So the page's await can't finish until the test itself stops and waits, which it does at step 4, on await screen.findByRole(...). That's the page's chance: its code runs, the ticket is saved in state, and React draws it. findByRole notices the page changed, tries again, and finds the heading.

So findBy isn't only "wait a bit". By waiting, the test lets the page finish.
