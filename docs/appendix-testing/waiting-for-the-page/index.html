Waiting for the Page

Needs Stage 2. Why a fake's answer arrives after render() returns, what every mock...Value method is short for, how toHaveBeenCalledWith compares, and why vi.stubEnv only works on code that reads the value late.

  • Why the Answer Comes Later

    A fake that resolves at once still answers after render() returns, because an await always waits for the running code to finish. findBy gives the page that chance.

  • Every Fake Is a Function Underneath

    mockResolvedValue and the rest are shortcuts for mockImplementation, which gives the fake a whole function to run. That function sees the arguments, so it can answer differently for each.

  • Checking the Calls

    toHaveBeenCalledWith reads the fake's mock.calls for you, and passes if any one call had exactly these arguments. Its failure message lists every call it saw.

  • Reading .env Late

    vi.stubEnv changes import.meta.env while the test runs. It only works because getToken() reads the value each time it's called, not once when the file loads.
