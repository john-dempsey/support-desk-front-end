Tests That Wait

An async test returns a promise, and Vitest waits for it, just as the homemade runner's await did. .rejects checks a promise that should fail, and must be awaited.

apiRequest() is async: it returns a promise, which settles later. So its tests are async functions too, and they return a promise. Vitest waits for that promise before it decides whether the test passed, just as run()'s await test.testFunction() did in your homemade runner. If the promise rejects, the test fails.

Checking for a failure

Some tests want apiRequest() to fail:

// Figure A.3: a request that should fail (src/api/client.test.js, excerpt)
it('throws a helpful message when the API cannot be reached', async () => {
  // A rejected fetch() is what happens when nothing answers at all.
  vi.stubGlobal(
    'fetch',
    vi.fn().mockRejectedValue(new TypeError('Failed to fetch')),
  );

  await expect(apiRequest('/welcome')).rejects.toMatchObject({
    status: 0,
    message: expect.stringContaining("Can't reach the API"),
  });
});

(It sits inside the file's describe, so it's indented one level further there, and the vi.stubGlobal call is one line, split here to fit. Topic 04 explains it.)

expect(promise).rejects waits for the promise to settle, then:

  • if it rejected, runs toMatchObject on the error it rejected with
  • if it resolved, fails the test: promise resolved "{ data: {} }" instead of rejecting

The await in front is essential. Waiting takes time, so .rejects itself returns a promise, and the test has to wait for it.

Try it

  1. Delete the await in front of expect(...) in Figure A.3 and run npm test. Vitest fails the test, and says why:
    Error: Promise returned by `expect(actual).rejects.toMatchObject(expected)`
was not awaited.
    (one line in the terminal). Put the await back.
  2. Replace the vi.stubGlobal(...) statement with fakeFetchResponding(200, { data: {} }); so that fetch succeeds. Run the test and find the "instead of rejecting" message. Put it back.
  3. Your homemade runner's run() has await test.testFunction(). What would go wrong for an async test if that await were removed?
