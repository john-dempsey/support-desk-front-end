The Real Thing

Swap the homemade runner for one import line and the same tests run in Vitest. A test file is a list of it() calls, grouped by describe(), and names join with >.

Delete parts 1 to 3 of mini-runner.js, add one import line, and the same tests run in Vitest. (They'd go in a file named *.test.js, so Vitest can find it.)

import { describe, expect, it } from 'vitest';

describe('statusLabel', () => {
  it('turns in_progress into in progress', () => {
    expect(statusLabel('in_progress')).toBe('in progress');
  });
  // ... the second test, exactly as before
});

Vitest's report of the failing test (shortened):

 FAIL  src/statusLabel.test.js > statusLabel > replaces every underscore
AssertionError: expected 'waiting on_customer' to be 'waiting on customer'

Expected: "waiting on customer"
Received: "waiting on_customer"

 ❯ src/statusLabel.test.js:13:48

The same idea, with more help: which file and line, and the two values one above the other. describe(), it() and expect() do the same jobs as your homemade ones. Vitest even waits until the whole file has been read before it calls the describe() functions, then runs the saved tests. That's why -t "loading" (topic 01) still has to read every file: it can't know the names until it has collected them.

A real test file

Every test file in the app has the same shape:

// Figure A.1: the shape of a test file (src/api/client.test.js, excerpt)
import { describe, expect, it, vi } from 'vitest';
import { apiRequest } from './client.js';

function fakeFetchResponding(status, body) {
  // ...
}

describe('apiRequest', () => {
  it('returns the response body on success', async () => {
    // ...
  });

  it('calls the API base URL with the given path', async () => {
    // ...
  });

  // ... five more it() calls
});

(Stage 0's version, with every function body left out.)

  • One describe() per file, named after what's being tested.
  • Inside it, one it() per behaviour, named so it reads as a sentence: "apiRequest ... returns the response body on success".
  • Vitest joins the names with > in its report: src/api/client.test.js > apiRequest > returns the response body on success.
  • test() is the same function as it(), under another name. The app always uses it().

Try it

  1. In client.test.js, change one it( to it.only( and run npx vitest run src/api: 1 passed | 6 skipped. .only is handy while you work on one test; remove it before you commit.
  2. Change it to it.skip(: 6 passed | 1 skipped. Change it back.
  3. Your homemade runner saved { name, testFunction } for each test. How might it.skip() work in it? (One extra property is enough.)
