describe, it and expect From Nothing

Needs Stage 0. A homemade test runner in plain JavaScript shows that it() only saves a test and expect() only throws. Then the real ones: names, checks, and tests that wait.

  • Saving Tests: describe() and it()

    it() doesn't run a test: it saves the function to run later, with its name. describe() runs its function at once, to save a group of tests under one name. expect() is an if and a throw.

  • Running Them

    The runner calls each saved test inside try/catch. A test passes if its function finishes without throwing. That's the whole rule, in Vitest too.

  • The Real Thing

    Swap the homemade runner for one import line and the same tests run in Vitest. A test file is a list of it() calls, grouped by describe(), and names join with >.

  • expect() and Its Checks

    toBe asks "the same value?", toEqual asks "the same contents?", and toMatchObject asks "at least these?". Choosing the wrong one gives a confusing failure.

  • Tests That Wait

    An async test returns a promise, and Vitest waits for it, just as the homemade runner's await did. .rejects checks a promise that should fail, and must be awaited.
