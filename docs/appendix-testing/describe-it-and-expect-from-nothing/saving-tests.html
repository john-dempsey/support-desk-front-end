Saving Tests: describe() and it()

it() doesn't run a test: it saves the function to run later, with its name. describe() runs its function at once, to save a group of tests under one name. expect() is an if and a throw.

The quickest way to see what describe(), it() and expect() do is to write them yourself. Over this slide and the next, you'll build a working test runner in about 40 lines of plain JavaScript, with no packages. It's a simplified copy of what Vitest does, not Vitest's own code.

Part 1: saving the tests

// mini-runner.js, part 1: saving the tests
const tests = [];
let currentGroup = '';

function describe(groupName, defineTests) {
  currentGroup = groupName;
  defineTests(); // runs the it() calls inside, which only save each test
  currentGroup = '';
}

function it(testName, testFunction) {
  tests.push({ name: `${currentGroup} > ${testName}`, testFunction });
}
  • it() runs nothing. It puts the test's name and its function in an array, to be run later. It's the same idea as an Express route: app.get('/tickets', listTickets) doesn't call listTickets, it saves it until a request arrives.
  • describe() calls its function straight away. That function's only job is to call it() a few times. So describe() means "save these tests, and put this group name in front of each one".

Part 2: checking a value

// mini-runner.js, part 2: checking a value
function expect(actual) {
  return {
    toBe(expected) {
      if (actual !== expected) {
        throw new Error(`expected '${actual}' to be '${expected}'`);
      }
    },
  };
}

expect(actual) returns an object, and toBe is a method on it. That's why the two read as one sentence: expect(statusLabel('open')).toBe('open'). The method remembers actual (it's a closure) and compares it with expected.

A check is just an if and a throw. When the values match, toBe does nothing at all. When they don't, it throws an error that says what was wrong.
