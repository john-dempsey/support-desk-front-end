expect() and Its Checks

toBe asks "the same value?", toEqual asks "the same contents?", and toMatchObject asks "at least these?". Choosing the wrong one gives a confusing failure.

Vitest's expect(actual) works like yours: it returns an object full of checks, and each one throws if it fails. They're called matchers. Stage 0's client.test.js uses five of them:

Matcher Passes when actual ... Example in Stage 0
toBe(x) is x: the same value, or the same object the URL fetch was called with
toEqual(x) has the same contents as x, all the way down the response body
toMatchObject(x) has at least the properties in x an error's status and message
toBeNull() is null apiRequest() for a 204
toBeUndefined() is undefined the missing Authorization header
.not.toBe(x), ... .not in front turns any matcher round (not used in Stage 0)

toBe or toEqual?

// Figure A.2: checking an object (src/api/client.test.js, excerpt)
it('returns the response body on success', async () => {
  fakeFetchResponding(200, { data: { message: 'Hello world!' } });

  const responseBody = await apiRequest('/welcome');

  expect(responseBody).toEqual({ data: { message: 'Hello world!' } });
});

(It sits inside the file's describe, so it's indented one level further there.)

For strings, numbers and booleans, toBe is right. For objects and arrays, it's almost always wrong: toBe asks whether they're the same object, and responseBody is a different object from the one written in the test, even though its contents match. toEqual compares the contents.

toMatchObject is looser still: it ignores any extra properties. A thrown error has a stack trace and more, but the test only cares about status, message and details.

Checks inside checks

    message: expect.stringContaining("Can't reach the API"),

Inside toMatchObject, expect.stringContaining(...) stands for "any string containing this". The test doesn't need to repeat the whole message, which includes the API's address.

Try it

  1. In Figure A.2, change toEqual to toBe and run npm test. Read the failure:
    AssertionError: expected { data: { message: 'Hello world!' } } to be
{ data: { message: 'Hello world!' } } // Object.is equality
    (one line in the terminal). The two values print the same, but they're different objects. Vitest even suggests the fix underneath. Change it back.
  2. Change it to toMatchObject({ data: {} }). Does it pass? Why? Change it back.
