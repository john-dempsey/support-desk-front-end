Running Them

The runner calls each saved test inside try/catch. A test passes if its function finishes without throwing. That's the whole rule, in Vitest too.

Part 3: running the saved tests

// mini-runner.js, part 3: running the saved tests
async function run() {
  let failed = 0;
  for (const test of tests) {
    try {
      await test.testFunction();
      console.log(`✓ ${test.name}`);
    } catch (error) {
      failed = failed + 1;
      console.log(`✗ ${test.name}\n    ${error.message}`);
    }
  }
  console.log(`${tests.length - failed} passed, ${failed} failed`);
}

This is the whole idea of a test runner: a test passes if its function finishes without throwing. A failed expect() throws, so the catch reports it, and the loop goes on to the next test. One failing test never stops the others.

The await is there for tests that have to wait for something, such as a request. Slide 05 comes back to it.

Part 4: the tests

// mini-runner.js, part 4: the tests
function statusLabel(status) {
  return status.replace('_', ' ');
}

describe('statusLabel', () => {
  it('turns in_progress into in progress', () => {
    expect(statusLabel('in_progress')).toBe('in progress');
  });

  it('replaces every underscore', () => {
    expect(statusLabel('waiting_on_customer')).toBe('waiting on customer');
  });
});

console.log(`${tests.length} tests saved, none run yet`);
run();

Running it with node mini-runner.js prints:

2 tests saved, none run yet
✓ statusLabel > turns in_progress into in progress
✗ statusLabel > replaces every underscore
    expected 'waiting on_customer' to be 'waiting on customer'
1 passed, 1 failed

The first line proves the order: both tests were saved before either ran. And the second test has found a real bug. Given a string, replace() changes only the first match.
