Four Hooks

beforeEach, afterEach, beforeAll and afterAll save a function to run around the tests. They wrap a test like layers: the outermost runs first before it, and last after it.

Tests in the same file share one page and one copy of every module (topic 01). So something has to tidy up between them. That's what hooks are for:

Hook Runs its function
beforeEach(fn) before every test
afterEach(fn) after every test, even one that failed
beforeAll(fn) once, before the first test
afterAll(fn) once, after the last test

Like it(), a hook only saves its function. The runner calls it at the right moment. A hook written inside a describe() applies only to that group's tests. One written at the top of a file applies to every test in the file.

The order

When there are hooks at several levels, they wrap the test like layers:

beforeEach hooks run from the outside in, and afterEach hooks from the inside out, so whatever was set up first is tidied up last. (This was checked by a throwaway test with a console.log in a hook at each level.) The settings on the left of the diagram are slide 03's.

Stage 0 has exactly one hook, in setup.js. Later stages add a few more, but most of the app's test files need none.
