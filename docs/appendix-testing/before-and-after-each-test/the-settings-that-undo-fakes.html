The Settings That Undo Fakes

mockReset and unstubGlobals are hooks you don't write. Vitest runs them before every test, so a fake from one test is gone before the next one starts.

Topic 04 shows the fakes Stage 0's tests make. Every fake must be gone before the next test, or that test would start with the last one's fake. You could undo each one in an afterEach, but two settings do it for every test file:

// Figure A.5: the test settings (vite.config.js, excerpt)
  test: {
    // jsdom gives the tests a pretend browser (document, window, ...) so
    // React components can render without a real browser window.
    environment: 'jsdom',
    setupFiles: './src/test/setup.js',
    // ...
    unstubGlobals: true,
    mockReset: true,
  },

(Stage 0's version, with the comment on the last two settings left out.)

  • unstubGlobals puts back anything a test replaced with vi.stubGlobal(), such as fetch.
  • mockReset makes every fake function forget what it was told to return, and what it was called with.

They're hooks you don't have to write. One detail: Vitest runs them before each test, not after it. A throwaway test checked this: in an afterEach, and even in an afterAll after the last test, the faked fetch was still in place. The next test then started with the real one. Either way, no test ever sees another test's fake.

Order shouldn't matter

Tests run in the order they're written. But if every test starts clean, any order should pass. Vitest can prove it:

npx vitest run --sequence.shuffle

runs the tests in a random order. All 13 pass.

Try it

  1. Run the shuffle command twice, with --reporter=verbose. Is the order different each time?
  2. In vite.config.js, set mockReset: false and run npm test. All 13 still pass. Read the first line of each HomePage test: why does none of them depend on the reset? Set it back to true. (It's a safety net: one forgotten line in a later test, and the reset is all that stops a leftover answer.)
