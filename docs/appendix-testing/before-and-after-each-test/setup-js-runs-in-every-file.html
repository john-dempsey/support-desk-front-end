setup.js Runs in Every File

setupFiles runs setup.js at the start of every test file, so its afterEach wraps every test in the project. It clears the page each test leaves behind.

// Figure A.4: before every test file (src/test/setup.js)
import { afterEach } from 'vitest';
import { cleanup } from '@testing-library/react';
// Adds browser-specific checks to expect(), e.g.
// expect(element).toBeInTheDocument() and .toHaveTextContent('...').
import '@testing-library/jest-dom/vitest';

// Removes whatever the last test rendered, so every test starts with an
// empty page.
afterEach(() => {
  cleanup();
});

(Stage 0's version.)

vite.config.js says setupFiles: './src/test/setup.js'. So in every test file's process, setup.js runs first: step 2 in topic 01's diagram. Its afterEach() is saved at the top level of every test file, before the file's own hooks. That's why it's the outermost layer. Writing the hook once in setup.js saves writing it in every file.

What cleanup() clears

A page test calls render(<HomePage />), which puts the component on jsdom's page. (Topic 05 shows exactly where.) The next test in the same file uses the same page. Without cleanup(), the last test's component would still be there, and the next test would find two of everything.

Try it

In setup.js, put // in front of cleanup(); and run npm test. Exactly one test fails:

 FAIL  src/App.test.jsx > App routes > shows the navigation on every page
TestingLibraryElementError: Found multiple elements with the role
"navigation" and name "Main"

(The error is one line in the terminal.) The previous test's page is still there, navigation and all. Why do the other page tests still pass? Look at what each one searches for. Remove the //.
