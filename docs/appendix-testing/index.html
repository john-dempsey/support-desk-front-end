Appendix A: How the Testing Tools Work

What describe(), it(), expect(), vi.fn(), render() and the rest actually do, explained from the ground up with the app's own tests, in the order the stages first use them.

  • The Pieces, and What npm test Does

    Needs Stage 0. Five packages, each with one job, and what happens between typing npm test and seeing "13 passed".

  • describe, it and expect From Nothing

    Needs Stage 0. A homemade test runner in plain JavaScript shows that it() only saves a test and expect() only throws. Then the real ones: names, checks, and tests that wait.

  • Before and After Each Test

    Needs Stage 0. Hooks run code around every test. setup.js uses one to clear the page, and two settings in vite.config.js undo every fake, so each test starts clean.

  • Fakes: vi.fn, vi.stubGlobal and vi.mock

    Needs Stage 0. A fake function that records its calls and answers as it's told, a global swapped for one, and a whole module replaced by fakes.

  • A Browser With No Window: jsdom and Testing Library

    Needs Stage 0. jsdom gives Node a pretend page, render() puts a component on it, queries find elements the way a screen reader does, and jest-dom adds checks for them.

  • Lists and Wrappers

    Needs Stage 1. How a query decides that text matches, what within() really is, and why a test has to rebuild whatever main.jsx wraps around the app.

  • Waiting for the Page

    Needs Stage 2. Why a fake's answer arrives after render() returns, what every mock...Value method is short for, how toHaveBeenCalledWith compares, and why vi.stubEnv only works on code that reads the value late.

  • Acting Like a User

    Needs Stage 3. What userEvent fires for one keypress, how a fake's queue of one-off answers works, matchers that match part of a value, vi.spyOn, and jest-dom's checks for form controls.

  • Helpers That Build the World

    Needs Stage 4. Stage 4 adds few new tools. Instead, its tests lean on a helper that makes fresh fakes and hands them back, and on jsdom's real localStorage, which a file's tests share.

  • Changes From Outside React

    Needs Stage 5. What act() does and why you rarely see it, the order Vitest runs a file with a mock factory in, and why rerender() is not the same as rendering again.

  • Hooks, Crashes and Coverage

    Needs Stage 6. renderHook() built by hand, what waitFor() needs from its check, two fakes for things that aren't the app's (console.error and DEV), and how a coverage report is counted.

  • Quick Reference

    Every testing function the finished app's tests use, what it does in a line, and the topic of this appendix that explains it.
