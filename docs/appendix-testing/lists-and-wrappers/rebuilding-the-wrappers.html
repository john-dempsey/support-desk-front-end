Rebuilding the Wrappers

A <Link> reads its settings from the router wrapped around it. A test renders one component on its own, so it has to rebuild whatever main.jsx wraps around the app.

In the app, main.jsx wraps everything in a <BrowserRouter>. Every <Link> and useParams() inside it reads from that router: where the app is, and how to build an address. A component wrapped around others to hand them something they need is called a provider.

A test renders one component on its own. Nothing is wrapped around it unless the test does the wrapping. Without a router, a <Link> has nothing to read, and React stops with:

Cannot destructure property 'basename' of 'React$1.useContext(...)'
as it is null.

(one line in the terminal). basename is one of the router's settings, and null is what the <Link> got instead of a router.

MemoryRouter: the same job, without an address bar

// Figure A.14: the wrapper (src/test/renderWithProviders.jsx, excerpt)
  return render(
    <MemoryRouter initialEntries={[route]}>{content}</MemoryRouter>,
  );

(Stage 1's version, split to fit.)

MemoryRouter provides exactly what BrowserRouter does. The only difference is where it keeps the address: in an array in memory, not in the browser's address bar, which jsdom doesn't have. initialEntries is that array's starting contents, like the browser's history. One entry means "start here".

The rule for any provider

Look at what main.jsx wraps around <App />. Anything a component under test reads from those wrappers must be rebuilt in the test. That's the job renderWithProviders was written for, so it's the one place to add to when main.jsx gains another provider.

Try it

To see a <Link> read from its router, render TicketList inside a router with a basename (a prefix for every address in the app):

render(
  <MemoryRouter basename="/app" initialEntries={['/app']}>
    <TicketList tickets={testTickets} />
  </MemoryRouter>,
);
const link = screen.getByRole('link', { name: 'Printer on fire' });
console.log(link.getAttribute('href'));

(You'll need to import render and MemoryRouter.) It prints /app/tickets/7, though TicketList only says to={`/tickets/${ticket.id}`}. Where did /app come from? Remove the test.
