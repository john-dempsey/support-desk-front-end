How Text Is Matched

A string must match the whole text, capitals and all. A regular expression can match part of it. The All queries return arrays, and Vitest's toHaveLength and toContain check arrays and strings.

Stage 1's tests find things by text and by name, and they don't always pass the whole text. The rules decide when that works.

A string matches the whole text

On a TicketList showing one unassigned ticket, a throwaway test tried these queries:

Query Result
getByText('Unassigned') finds the <td>
getByText('Unassign') throws: a string must match the whole text
getByText('unassigned') throws: capitals count
getByText(/unassigned/i) finds it: a regular expression matches part of the text, and i ignores capitals
getByText('unassign', { exact: false }) finds it: exact: false means "contains, ignoring capitals"
getByRole('link', { name: 'Printer' }) throws: the name is "Printer on fire"
getByRole('link', { name: /Printer/ }) finds the <a>

Before comparing, Testing Library trims the text and turns every run of spaces and line breaks into a single space. So the way the JSX is laid out never matters.

A row's name is all its cells

Figure 1.36 (Stage 1, topic 07) finds a row with { name: /Mouse missing/ }. The accessible name of a table row is the text of all its cells, joined with spaces. For the throwaway test's ticket it was:

Printer on fire Open Casey Customer Unassigned 8 Oct 2026, 13:00

That's why the test uses a regular expression: matching the whole name would tie it to the date, and the date's hour depends on the time zone the tests run in.

The All queries

Query Finds none Finds several
getAllBy... throws returns an array of them
queryAllBy... returns [] returns an array
findAllBy... tries again, then rejects resolves with an array

An array is checked with Vitest's own matchers:

// Figure A.12: counting rows (src/components/TicketList.test.jsx, excerpt)
expect(screen.getAllByRole('row')).toHaveLength(3);

toHaveLength(n) works on anything with a length, so strings too. Its partner toContain(x) checks that an array has x in it, or that a string contains x. formatDate's test uses it: expect(readableDate).toContain('8 Oct 2026').

Try it

In TicketList.test.jsx, change { name: /Mouse missing/ } to { name: 'Mouse missing' } and run the tests. Read the error's list of rows: what is the row's full name? Now try /mouse missing/ (no i), then /mouse missing/i. Change it back.
