getBy, queryBy or findBy

getBy throws when it finds nothing, queryBy returns null, and findBy keeps trying for up to a second. Forgetting to await findBy hands expect() a promise instead of an element.

Every query comes in three kinds. They search the same way; they differ in what happens when there's nothing to find yet:

Query Finds one Finds none Finds several
getBy... returns it throws at once throws
queryBy... returns it returns null throws
findBy... resolves with it tries again until it finds one, or a second has passed, then rejects rejects
  • getBy suits anything that's there as soon as render returns, such as the loading message in Figure A.9.
  • queryBy suits checking something is not there: expect(screen.queryByRole('alert')).not.toBeInTheDocument(). (getBy would throw before expect could check anything.)
  • findBy suits anything that appears later, such as text that arrives when a fake request resolves.

How findBy waits

findBy... is getBy... run over and over. It tries straight away, then again every 50 milliseconds, and also whenever the page changes. As soon as one try finds the element, the promise resolves with it. After 1000 milliseconds of failing, it rejects with the last error. (Those numbers are Testing Library's defaults, in @testing-library/dom.)

// Figure A.11: waiting for the error (src/pages/HomePage.test.jsx, excerpt)
it('shows an error message when the API cannot be reached', async () => {
  getWelcome.mockRejectedValue(new Error("Can't reach the API"));

  render(<HomePage />);

  expect(await screen.findByRole('alert')).toHaveTextContent(
    "Can't reach the API",
  );
});

(Stage 0's version, indented one level further in the file, with the last statement on one line.)

When render returns, the fake's promise hasn't rejected yet, so there is no alert. A few milliseconds later the page catches the error and shows it, and findByRole finds it on its next try.
