A Browser With No Window: jsdom and Testing Library

Needs Stage 0. jsdom gives Node a pretend page, render() puts a component on it, queries find elements the way a screen reader does, and jest-dom adds checks for them.

  • A Pretend Page

    Node has no document or window. jsdom builds them in JavaScript, so React can create real elements in a test, though nothing is ever drawn.

  • render() and screen

    render() adds a <div> to jsdom's page and has React draw the component into it, effects and all. screen searches the whole page, and screen.debug() prints it.

  • How a Query Finds an Element

    getByRole works out every element's role and accessible name, as a screen reader does, and picks the one that matches. When none does, it lists what it found.

  • getBy, queryBy or findBy

    getBy throws when it finds nothing, queryBy returns null, and findBy keeps trying for up to a second. Forgetting to await findBy hands expect() a promise instead of an element.

  • jest-dom: Checks for Elements

    One import adds element checks such as toBeInTheDocument to expect. It uses expect.extend, which you can use too.
