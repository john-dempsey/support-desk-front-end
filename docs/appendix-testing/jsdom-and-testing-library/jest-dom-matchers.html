jest-dom: Checks for Elements

One import adds element checks such as toBeInTheDocument to expect. It uses expect.extend, which you can use too.

Vitest's own matchers (topic 02) check values: strings, numbers, objects. jest-dom adds matchers that check elements. Stage 0's tests use two:

Matcher Passes when the element ...
toBeInTheDocument() is on the page
toHaveTextContent('...') has text that contains this, with the same capitals

They're added by one line in setup.js (Figure A.4):

import '@testing-library/jest-dom/vitest';

That file does little more than call expect.extend(...) with jest-dom's matchers. expect.extend adds new methods to every expect(...) in the process, in the same way your homemade expect() in topic 02 had a toBe method.

A matcher of your own

expect.extend is open to you too. A matcher returns pass (did it pass?) and a message for when it fails:

expect.extend({
  toBeAnOpenTicket(ticket) {
    return {
      pass: ticket.status === 'open',
      message: () => `expected ticket ${ticket.id} to be open`,
    };
  },
});

expect({ id: 2, status: 'closed' }).toBeAnOpenTicket();
// fails with: Error: expected ticket 2 to be open

The app doesn't need one, but it shows there's no magic: jest-dom is a collection of functions like this one.
