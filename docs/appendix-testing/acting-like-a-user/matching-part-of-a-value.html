Matching Part of a Value

expect.objectContaining and its relatives are stand-ins that toEqual and toHaveBeenCalledWith ask "do you match this?". toHaveBeenLastCalledWith only looks at the latest call.

EditTicketPage sends the whole form to updateTicket, but one test only cares about one field:

// Figure A.19: just one field (src/pages/EditTicketPage.test.jsx,
// excerpt)
expect(updateTicket).toHaveBeenCalledWith(
  '1',
  expect.objectContaining({ assignedAgentId: null }),
);

How a stand-in matches

expect.objectContaining(...) doesn't check anything by itself. It returns a small object with a method, asymmetricMatch(value), that answers true or false. When toEqual or toHaveBeenCalledWith compares values and finds one of these objects in the expected side, it doesn't compare them as objects: it asks the stand-in "does this value match you?". A throwaway test called it directly:

const matcher = expect.objectContaining({ assignedAgentId: null });
matcher.asymmetricMatch({ status: 'open', assignedAgentId: null }); // true
matcher.asymmetricMatch({ status: 'open' });                        // false

So a stand-in can go anywhere inside an expected value. Vitest has several:

Stand-in Matches
expect.objectContaining({...}) an object with at least these properties
expect.stringContaining('...') a string containing this (topic 02)
expect.any(String) any string; expect.any(Number) any number, ...
expect.arrayContaining([...]) an array with at least these items

Only the last call

TicketListPage calls getTickets when it opens, and again after the status filter changes. toHaveBeenCalledWith('status=open') would pass if any call had that query. toHaveBeenLastCalledWith('status=open') (Figure 3.66, Stage 3, topic 10) only looks at the latest call, which is the one the filter caused.
