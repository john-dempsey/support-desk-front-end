Acting Like a User

Needs Stage 3. What userEvent fires for one keypress, how a fake's queue of one-off answers works, matchers that match part of a value, vi.spyOn, and jest-dom's checks for form controls.

  • What userEvent Fires

    userEvent.type() doesn't set the input's value. It clicks the input, then presses each key, firing the same events a browser would, and waits for React after each one.

  • A Queue of Answers

    Each ...Once answer is used for one call, in the order they were given. When the queue is empty, the fake falls back to its everyday answer, or undefined.

  • Matching Part of a Value

    expect.objectContaining and its relatives are stand-ins that toEqual and toHaveBeenCalledWith ask "do you match this?". toHaveBeenLastCalledWith only looks at the latest call.

  • vi.spyOn(): One Method on a Real Object

    jsdom has no confirmation box: its window.confirm() complains and returns undefined. vi.spyOn swaps that one method for a fake, and mockReset makes it call the real one again.

  • Checks for Form Controls

    jest-dom has checks for what a form control holds and how a screen reader describes it. toHaveAccessibleDescription follows aria-describedby to the error message.
