vi.spyOn(): One Method on a Real Object

jsdom has no confirmation box: its window.confirm() complains and returns undefined. vi.spyOn swaps that one method for a fake, and mockReset makes it call the real one again.

The detail page asks window.confirm('Delete this ticket?') before it deletes anything (Stage 3, topic 06). In a browser that opens a box with OK and Cancel. jsdom draws nothing, so it can't. A throwaway test called it to see what happens:

Not implemented: Window's confirm() method

is printed, and confirm() returns undefined. The page treats that like Cancel.

So the tests answer for the user:

// Figure A.20: answering the box (src/pages/TicketDetailPage.test.jsx,
// excerpt)
function answerConfirmWith(answer) {
  vi.spyOn(window, 'confirm').mockReturnValue(answer);
}

(Stage 3's version, without its comment.)

spyOn, stubGlobal or vi.fn?

All three make fakes. They differ in where the fake goes:

Tool Replaces Used for
vi.fn() nothing: it's a new function you pass in or give to vi.mock API functions, handlers
vi.stubGlobal(name, fake) a global variable fetch (topic 04)
vi.spyOn(object, 'method') one method of an object that already exists window.confirm

vi.spyOn keeps the original method. Until it's told otherwise, the spy simply calls it, while recording every call like any vi.fn(). That's where the name comes from: it watches a real method. Here, mockReturnValue(answer) then tells it to answer instead.

Before the next test, mockReset makes the spy call the real method again. (A throwaway test checked this in Vitest 5: the method is still a spy, but it gives the real answer.)

Try it

In answerConfirmWith, put // in front of the vi.spyOn line and run npx vitest run src/pages/TicketDetailPage.test.jsx. "Not implemented" is printed several times, and three tests fail. But "does nothing when the user cancels" still passes. Why? Is that test still checking what it says it checks? Remove the //.
