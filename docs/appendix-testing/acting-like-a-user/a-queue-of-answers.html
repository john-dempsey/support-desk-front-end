A Queue of Answers

Each ...Once answer is used for one call, in the order they were given. When the queue is empty, the fake falls back to its everyday answer, or undefined.

A vi.fn() fake keeps two kinds of answer:

  • an everyday answer, from mockReturnValue, mockResolvedValue, mockImplementation, ...
  • a queue of one-off answers, from mockReturnValueOnce, mockResolvedValueOnce, ...

On each call it takes the next answer from the queue, if there is one. Only when the queue is empty does it use the everyday answer. A throwaway test showed the rules:

const fake = vi.fn()
  .mockReturnValue('default')
  .mockReturnValueOnce('first')
  .mockReturnValueOnce('second');
fake(); fake(); fake(); fake();
// 'first', 'second', 'default', 'default'

const bare = vi.fn().mockReturnValueOnce('only');
bare(); bare();
// 'only', undefined

The order you write them in doesn't matter: 'default' was given first, but the queue was still used first. (Each method returns the fake itself, which is why they can be chained with dots.)

An everyday answer for every test

Stage 3's TicketDetailPage loads a ticket and its comments. Most of its tests don't care about comments, so a beforeEach gives getComments an everyday answer, getComments.mockResolvedValue([]) (Figure 3.64, Stage 3, topic 10).

mockReset (topic 03) wipes it before each test, and this beforeEach then sets it again. A test about comments sets its own answer afterwards, which replaces it.

Try it

TagsPage's "adds a tag" test queues two answers for getTags: one for when the page loads, one for after the new tag is added (Figure 3.63, Stage 3, topic 10).
