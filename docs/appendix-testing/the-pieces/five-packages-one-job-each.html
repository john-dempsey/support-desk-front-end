Five Packages, One Job Each

Vitest runs the tests, jsdom pretends to be a browser, Testing Library puts components on the page and finds things there, jest-dom adds checks, and user-event clicks and types.

You've used a testing framework before, so you know the idea. You write small functions that call your code and check what comes back, and a tool runs them all and tells you which passed. This appendix is about the particular tools this app uses, and how each one works underneath. Every example comes from the app's own tests.

Each topic belongs to a stage. It explains the tools that stage's tests first used, and needs nothing from later stages. Topics 01 to 05 need only Stage 0, so they quote Stage 0's tests: the same files you have in your own project, from the template. Some of those files changed in later stages, so do these topics' Try its in a copy of the starter as it was before you changed it.

The packages

No single package does everything a front-end test needs. The starter's package.json (Figure 0.2, Stage 0, topic 02) installs five for testing:

Package Its one job
vitest The test runner. It finds the test files, runs them and reports. It also gives you describe, it, expect, and vi for fakes.
jsdom A pretend browser, written in JavaScript: document, window and HTML elements, inside Node. No window opens and nothing is drawn.
@testing-library/react Puts a React component on jsdom's page (render), and finds things there the way a user would (screen.getByRole(...)).
@testing-library/jest-dom Extra checks for elements, such as toBeInTheDocument() and toHaveTextContent().
@testing-library/user-event Acts like a user: clicking, typing, choosing from a list. It's installed in Stage 0. Stage 2's tests click once with it, and Stage 3's type and choose (topic 08, later in this appendix).

All five are devDependencies: needed while you build and test the app, and never sent to the browser.

Vitest copies the names of Jest's functions, Jest being the most widely used JavaScript test runner. So most of this appendix holds for Jest too. The difference that matters here: Vitest is built on Vite, so it already understands JSX, ES modules and import.meta.env, using the same vite.config.js as npm run dev.

Try it

In your project folder, run npx vitest --version. Then open node_modules/jsdom/package.json and find its "description". jsdom calls itself "A JavaScript implementation of many web standards". Which web standards have the app's components used so far? (Think of what document and HTML elements give you.)
