A Fresh World for Every File

Each test file runs in a process of its own, with a new pretend page and its own copy of every module, so nothing one file does can reach another.

Once Vitest has its list of files, it doesn't run them one after another in a single program. It starts a separate process for each file (a separate running copy of Node) and runs them side by side:

Each process goes through the same five steps:

  1. Build a new jsdom page, because vite.config.js says environment: 'jsdom'. This gives the file its own document and window.
  2. Run setup.js, because of setupFiles. (Topic 03 shows what it does.)
  3. Read the test file. This doesn't run any tests yet: it collects them, as the next topic shows.
  4. Run the collected tests, one at a time, in the order they appear in the file.
  5. Send the results back to the first Vitest process, which waits for every file and prints the summary.

Why a fresh world?

Because nothing one file does can reach another. client.test.js replaces fetch with a fake. HomePage.test.jsx replaces a whole API module. Each runs with its own copy of every module and its own page, so the order the files run in never matters.

Tests in the same file are different: they share one page and one copy of every module. Topic 03 shows how the starter stops one test leaving a mess for the next.

Where the time goes

The last line of a run says where the time went (shortened here):

   Duration  1.99s (environment 65%, tests 12%, setup 12%, ...)

environment is step 1: building jsdom pages. The tests themselves take a few milliseconds each. So a run takes about two seconds however fast your code is, and adding a test to an existing file costs far less than adding a new file.

Try it

Run npx vitest run --reporter=verbose. Each test is now listed on its own line with its full name, e.g.

 ✓ src/api/client.test.js > apiRequest > returns null for 204 No Content 0ms

Run it twice more. Do the three files finish in the same order each time? Why doesn't it matter if they don't?
