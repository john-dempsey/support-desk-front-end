vi.mock(): Replacing a Whole Module

vi.mock swaps a file for a stand-in whose exported functions are all vi.fn() fakes. Every import of it, the page's included, gets the stand-in, and Vitest moves the call to the top of the file.

HomePage doesn't call fetch. It calls getWelcome(), which it imports. To control what the page receives, Stage 0's test replaces the whole module welcome.api.js:

// Figure A.8: faking an API module (src/pages/HomePage.test.jsx, excerpt)
import { describe, expect, it, vi } from 'vitest';
import { render, screen } from '@testing-library/react';
import HomePage from './HomePage.jsx';
import { getWelcome } from '../api/welcome.api.js';

vi.mock('../api/welcome.api.js');

describe('HomePage', () => {
  it("shows the API's welcome message", async () => {
    getWelcome.mockResolvedValue({ message: 'Hello world!' });

    render(<HomePage />);

    expect(await screen.findByText('Hello world!')).toBeInTheDocument();
  });

(Stage 0's version, without its comments.)

How it works

A module is loaded once per process, and every file that imports it shares that one copy. vi.mock(path) tells Vitest: "in this test file's process, whoever imports this path gets a stand-in instead".

  • The stand-in. Vitest loads the real file once, to see what it exports, and builds a stand-in where every exported function is a vi.fn() that returns undefined.
  • The same fake everywhere. The test's getWelcome and the page's getWelcome are the same fake. So when the test calls getWelcome.mockResolvedValue(...), it's setting what the page gets.
  • Moved to the top. import lines run before any other code in a file. If vi.mock ran where it's written, HomePage.jsx would already have the real module. So Vitest moves every vi.mock() call above the imports before the file runs. Where you write it doesn't matter.

Try it

  1. Delete the vi.mock(...) line and run npx vitest run src/pages. Every test fails with something like TypeError: getWelcome.mockResolvedValue is not a function: the real getWelcome has no fake methods. Put it back.
  2. Move the vi.mock(...) line to the very bottom of the file. Do the tests still pass? Put it back.
  3. In the first test, delete the getWelcome.mockResolvedValue(...) line. The test fails after about a second, and prints the page: just the Welcome heading. The fake returned undefined, so there was nothing to show. Why is there no loading message, and no error either? (Read HomePage.jsx.) Put the line back.
