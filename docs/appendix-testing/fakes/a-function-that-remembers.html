vi.fn(): a Function That Remembers

vi.fn() makes a fake function. It records every call, and returns whatever the test tells it to. A homemade one takes ten lines.

A fake stands in for something the test doesn't want to run for real, such as a request to the API. Vitest's fakes all start from vi.fn(). (Vitest calls them "mocks", hence names like vi.mock and mockReset.)

A homemade one first

function makeFake() {
  const fake = (...args) => {
    fake.calls.push(args);
    return fake.answer;
  };
  fake.calls = [];
  fake.answer = undefined;
  return fake;
}

A JavaScript function is an object, so it can carry properties. Each time this fake is called, it saves its arguments in fake.calls, then returns fake.answer. A test sets the answer first, calls the code being tested, and then reads calls to check how the fake was used.

The real one

vi.fn() is the same idea, with more built in:

You write The fake then
vi.fn() returns undefined
.mockReturnValue(x) returns x
.mockResolvedValue(x) returns a promise that resolves with x, as a successful request does
.mockRejectedValue(error) returns a promise that rejects with error, as a failed request does
.mock.calls is every call's arguments: mock.calls[0][0] is the first call's first argument

Stage 0's client.test.js uses it to fake fetch():

// Figure A.6: a fake fetch() (src/api/client.test.js, excerpt)
function fakeFetchResponding(status, body) {
  const fakeFetch = vi.fn().mockResolvedValue({
    ok: status >= 200 && status < 300,
    status,
    json: async () => body,
  });
  vi.stubGlobal('fetch', fakeFetch);
  return fakeFetch;
}

The fake answers every call with a pretend response: only the three things apiRequest() reads (ok, status, json()). The helper returns the fake so a test can look at fakeFetch.mock.calls afterwards. (The next slide explains vi.stubGlobal.)
