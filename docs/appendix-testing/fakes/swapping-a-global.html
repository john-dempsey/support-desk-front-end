vi.stubGlobal(): Swapping a Global

fetch is a global, looked up by name each time it's called. vi.stubGlobal replaces it, so client.js calls the fake without being changed at all.

client.js never imports fetch. It's a global: a property of the global object (window in a browser, globalThis anywhere), available everywhere by name. And JavaScript looks a global up when the line runs, not when the file is loaded.

So if a test replaces the global before calling apiRequest(), this line in client.js calls the fake:

// Figure A.7: the call to fetch (src/api/client.js, excerpt)
    response = await fetch(`${API_URL}${path}`, {

vi.stubGlobal('fetch', fakeFetch) does two things:

  1. it remembers the real fetch
  2. it sets globalThis.fetch to the fake

The remembering is what lets unstubGlobals (topic 03) put the real one back before the next test.

Why fake fetch at all?

Without the fake, the tests would send real requests. They'd pass or fail depending on whether the API happened to be running, and they couldn't easily cause a 400 with details, or a 204, whenever they wanted. With the fake, each test decides exactly what "the API" answers.

Try it

With your API stopped, delete the line vi.stubGlobal('fetch', fakeFetch); from fakeFetchResponding and run npx vitest run src/api. Six tests fail with:

Error: Can't reach the API at http://localhost:3000 — is the back-end
running?

(one line in the terminal). They're calling the real fetch now. Which test still passes, and why? (Look at its first line.) Put the line back.
