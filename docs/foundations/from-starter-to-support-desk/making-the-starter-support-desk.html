Making the Starter Support Desk

The starter's TODOs are done, and the home page's connection check is replaced by a plain welcome now that it has done its job.

The starter marked every place you were expected to change with TODO (your case study). Stage 1 does each one for Support Desk, and then deletes the TODO comment, because there's nothing left to do there.

The name

The app's name appears in two places, and both change from My App:

<!-- Figure 1.3: the browser tab's title (index.html, excerpt) -->
<title>Support Desk</title>

// Figure 1.4: the app's name (src/components/NavBar.jsx, excerpt)
const APP_NAME = 'Support Desk';

The TODOs in App.jsx and NavBar.jsx also asked for a <Route> and a NavLink for each new page. Those are added in topic 06, along with the pages they point to.

A plain home page

In the starter, HomePage called GET /welcome to prove that the front-end and the API could talk to each other. That check has done its job. From Stage 2, the ticket pages talk to the API themselves, and if they can't reach it, they'll say so.

So the home page is now just a welcome and a way in:

// Figure 1.5: the new home page (src/pages/HomePage.jsx)
import { Link } from 'react-router';

function HomePage() {
  return (
    <>
      <h1>Welcome to Support Desk</h1>
      <p>
        Report a problem, follow its progress, and see every ticket in
        one place.
      </p>
      <p>
        <Link to="/tickets">View the tickets</Link>
      </p>
    </>
  );
}

export default HomePage;

(The paragraph is one line in the file. It's split here to fit.)

It has no state and no useEffect: there's nothing to load, so there's nothing to wait for and nothing that can fail.

What else went

With nothing calling GET /welcome, src/api/welcome.api.js has been deleted. Code that nothing uses is just something else to read and keep up to date. client.js stays exactly as it was: every request in Stage 2 goes through it.

The tests changed to match. HomePage.test.jsx no longer mocks welcome.api.js, because there's nothing to mock, and the tests now look for the new heading. A test that looks for text that's gone fails, which is a useful reminder: when you change what a page shows, its tests have to change too.

Try it

Change the heading in HomePage.jsx to Welcome! and run npm test. How many tests fail, and in which files? Why does a test in App.test.jsx fail too, when you only changed HomePage? Change the heading back and check that every test passes again.
