Hard-Coded Tickets

sampleTickets.js stands in for the API, so it gives every ticket the same shape the API will send.

Stage 1's tickets live in one file, src/data/sampleTickets.js. Its top comment starts with the word TEMPORARY: Stage 2 deletes the file and loads the tickets from GET /tickets instead.

Here's the start of it (only two of the three people are shown, and each person is spread over three lines to fit, where the file has one line each):

// Figure 1.1: the sample data (src/data/sampleTickets.js, excerpt)
const casey = {
  id: 1, name: 'Casey Customer', email: 'casey@example.com',
};
const alex = {
  id: 3, name: 'Alex Agent', email: 'alex@example.com',
};

const sampleTickets = [
  {
    id: 1,
    subject: 'Cannot log in',
    description: 'Password reset email never arrives',
    status: 'open',
    customer: casey,
    assignedAgent: alex,
    createdAt: '2026-10-08T09:15:00.000Z',
    updatedAt: '2026-10-08T09:15:00.000Z',
  },
  // ... three more tickets
];

export default sampleTickets;

The same shape as the API

The pages will display whatever the API sends, so every field they use has the same name and shape here as in the API's tickets:

  • the same names: subject, status, assignedAgent, createdAt
  • customer and assignedAgent are objects with an id, name and email, the same as the back-end's include adds to each ticket
  • status uses the API's values: open, in_progress, resolved or closed
  • dates are strings, because JSON has no date type. The API sends every date as an ISO string like this one. Topic 05 turns them into something a person can read.

The API also sends a few fields that no page shows, such as customerId. Those are simply left out here.

An unassigned ticket has null as its agent, exactly as the API sends it:

// Figure 1.2: a ticket with no agent (src/data/sampleTickets.js, excerpt)
customer: priya,
// null means "not assigned to an agent yet". The API sends null, not an
// empty object, so the pages must check for it before reading `.name`.
assignedAgent: null,

null.name is an error in JavaScript, so any page that shows the agent's name has to check for null first. You'll see that check in topic 03.

If the sample data used different names (say title instead of subject), every page would have to change when the real data arrived. With the same shape, Stage 2 changes where the tickets come from and nothing else.

The people and subjects are the ones in the back-end's seed data, so Stage 2 will show the same tickets. Only the statuses differ: in the seed, every ticket is open, but here there's one of each status, so you can see every kind of badge.

Each person written once

casey and alex are written once, as constants, and then used by more than one ticket. Casey is the customer on two tickets, and Alex is assigned to both of them. It saves repeating the same details, and it mirrors the API, which puts the same customer object into each of their tickets.

Try it

Add a fifth ticket to the array, with id: 5 and priya as the customer. Which fields does it need? Save, and check that it shows on the Tickets page. Then delete its customer line, save again, and open the browser's Console. What went wrong, and why? Put the line back before you go on.
