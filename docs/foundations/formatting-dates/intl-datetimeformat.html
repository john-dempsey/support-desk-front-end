Intl.DateTimeFormat

The browser has date formatting built in. formatDate makes one formatter, set up once, and uses it for every date.

Browsers have a built-in way to format dates for people: Intl.DateTimeFormat (Intl is short for internationalisation). So the app doesn't need a date library. src/utils/formatDate.js sets one up:

// Figure 1.21: the formatter (src/utils/formatDate.js, excerpt)
// Created once and reused, rather than on every call. 'en-IE' gives Irish
// formatting, e.g. "8 Oct 2026, 10:15", in the user's own time zone.
const dateFormatter = new Intl.DateTimeFormat('en-IE', {
  dateStyle: 'medium',
  timeStyle: 'short',
});

The two arguments

  • 'en-IE' is the locale: English, as written in Ireland. It decides the order and the words. 'en-US' would give Oct 8, 2026, 10:15 AM instead.
  • The options say how much to show. dateStyle: 'medium' gives 8 Oct 2026 ('long' would give 8 October 2026), and timeStyle: 'short' gives hours and minutes, 10:15, with no seconds.

The formatter turns a Date into text in the user's own time zone, which the browser knows from the computer's settings. That's how 09:15 UTC becomes 10:15 on a computer in Ireland in October.

Using it

// Figure 1.22: using the formatter (src/utils/formatDate.js, excerpt)
export function formatDate(isoString) {
  const date = new Date(isoString);
  // ... a check for bad dates (next slide)
  return dateFormatter.format(date);
}

new Date(isoString) turns the ISO string into a JavaScript Date object, and dateFormatter.format(date) turns that into the text the page shows.

Why create it once?

Setting up a formatter takes some work: the browser has to load the rules for that locale. dateFormatter is created outside the function, once, when the file loads. Every call to formatDate reuses it. Creating a new formatter inside the function would repeat that work for every date on every page, for exactly the same result. It's the same reason STATUS_LABELS sits outside StatusBadge.
