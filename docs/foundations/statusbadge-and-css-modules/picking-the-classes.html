Picking the Classes

The badge looks up its colour class by the status value, the same way it looks up its label, and combines it with the shared badge class.

Here's the rest of the component. The return line is split over three lines to fit here; in the file it's one line:

// Figure 1.19: the badge (src/components/StatusBadge.jsx, excerpt)
function StatusBadge({ status }) {
  // If the API ever sends a status this file doesn't know about, show it
  // as it is, in grey, rather than showing nothing.
  const label = STATUS_LABELS[status] || status;
  const colourClass = styles[status] || styles.unknown;

  return (
    <span className={`${styles.badge} ${colourClass}`}>{label}</span>
  );
}

The colour class

styles is an object, so it's looked up the same way as STATUS_LABELS. That's why the CSS file names its classes exactly like the API's status values: .open, .in_progress, .resolved, .closed. For a ticket that's in_progress, styles[status] is styles.in_progress, the class with the yellow colours. An underscore is allowed in a CSS class name, so the API's value works as it is.

For a status the file doesn't know, styles[status] is undefined, and || falls back to styles.unknown. In the CSS, .unknown shares its grey rule with .closed:

/* Figure 1.20: the grey badge (src/components/StatusBadge.module.css,
   excerpt) */
.closed,
.unknown {
  color: #59636e;
  background-color: #f6f8fa;
}

Two classes on one element

In HTML, an element can have several classes, separated by spaces: class="badge open". The badge needs two: badge for the shape, and one colour class. The template literal builds that string from the two generated names:

`${styles.badge} ${colourClass}`   // '_badge_85lrl_6 _open_85lrl_18'

A template literal (a string in backticks, with ${ } around each value) is the same thing you used to build strings in the back-end. className (not class) is the JSX name for the attribute, as the starter explained.
