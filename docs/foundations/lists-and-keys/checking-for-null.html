Checking for null

An unassigned ticket's agent is null, so the cell checks before reading the name, and shows "Unassigned" instead.

Topic 01 showed that an unassigned ticket has assignedAgent: null. The "Assigned to" cell has to cope with that:

// Figure 1.12: the agent cell (src/components/TicketList.jsx, excerpt)
<td>{ticket.assignedAgent ? ticket.assignedAgent.name : 'Unassigned'}</td>

This is the conditional operator, ? :, from the starter: Blade's @if ... @else ... @endif as an expression. Read it as "if the ticket has an agent, show the agent's name, otherwise show Unassigned". null counts as false, so an unassigned ticket gets the second value.

Why the check matters

Without it, the cell would be {ticket.assignedAgent.name}. For an unassigned ticket that's null.name, and JavaScript stops with an error:

TypeError: Cannot read properties of null (reading 'name')

One error while drawing a component stops React drawing the whole app, not just that cell, so the page goes blank.

Why not &&?

{ticket.assignedAgent && ticket.assignedAgent.name} would avoid the error too, but it shows nothing for an unassigned ticket. An empty cell is ambiguous: is the ticket unassigned, or did something fail to load? A screen reader would just say "blank". Showing the word Unassigned says what's true.

Why only the agent?

The customer cell has no check: {ticket.customer.name}. Every ticket has a customer (the back-end won't create one without), so customer is never null. Check for null where the API can send it, and nowhere else, or the code fills up with checks that can never matter.

Try it

  1. In sampleTickets.js, change the first ticket's assignedAgent to null. What does its row show now?
  2. In TicketList.jsx, replace the whole ? : expression with ticket.assignedAgent.name and save. What happens to the page, and what does the Console say?
