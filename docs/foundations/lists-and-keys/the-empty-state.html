The Empty State

When there are no tickets, TicketList returns a message instead of the table, using an early return.

A list should always say something sensible when it has nothing in it. TicketList checks for that before it builds the table:

// Figure 1.13: nothing to show (src/components/TicketList.jsx, excerpt)
function TicketList({ tickets }) {
  // The "empty" state. Not possible with the hard-coded tickets, but it
  // will be once the list comes from the API (e.g. a brand-new customer).
  if (tickets.length === 0) {
    return <p>There are no tickets to show.</p>;
  }

  return (
    // ... the table

An early return

A component is a function, so it can return more than once. When there are no tickets, the first return gives back the message, and nothing after it runs. The table code is only reached when there's at least one ticket.

This is a normal JavaScript if statement. It's allowed here because it's outside the JSX, in the body of the function. Inside { } it wouldn't be.

Why not &&?

The starter's HomePage used && to show or hide one piece of the page, such as the error message. Here, the whole result is different: either a table, or a sentence. Building an empty table, with headings and no rows, would look broken. An early return keeps the two cases apart, and the main return doesn't have to worry about the empty case at all.

When it happens

Never, with the sample data, which always has four tickets. But from Stage 2 the tickets come from the API, and a customer who has only just registered has no tickets yet. Handling it now means TicketList is ready for that before it happens.

Try it

Change the message to No tickets yet. and run npm test. Which test fails, and what is it checking? Change the message back. (The previous topic's Try it showed you how to see the message in the browser.)
