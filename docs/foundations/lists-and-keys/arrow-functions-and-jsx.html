Arrow Functions and JSX

A short reminder of arrow functions from the back-end, plus the one new shorthand JSX needs: parentheses around a multi-line result.

The next slide passes an arrow function to .map(). You met arrow functions in the back-end's Lesson 1, including the implicit return: with no { }, the expression after => is returned automatically.

// These two do the same thing:
const double = (number) => { return number * 2; };
const doubleAgain = (number) => number * 2;

You also passed an arrow function to another function, in the in-memory ticket.service.js:

tickets.find((ticket) => ticket.id === id);

find() calls the arrow function once for each ticket, and stops at the first one where it returns true. You write what to do with one ticket; find() does the looping.

Returning JSX

An arrow function can return JSX, because JSX is an expression:

const toListItem = (name) => <li>{name}</li>;

When the JSX is more than one line, wrap it in parentheses:

const toRow = (ticket) => (
  <tr>
    <td>{ticket.subject}</td>
  </tr>
);

The parentheses only group the lines, the same as the return ( ... ) in every component you've seen. It's still an implicit return.

The trap: braces instead of parentheses

const toRow = (ticket) => {
  <tr>
    <td>{ticket.subject}</td>
  </tr>
};

With braces, the arrow function has a body, so nothing is returned unless you write return. This version returns undefined, React shows nothing for undefined, and there's no error message to tell you why. If a list comes out empty and you can't see why, check this first.
