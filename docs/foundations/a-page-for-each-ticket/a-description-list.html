A Description List

The ticket's details are label-and-value pairs, so they go in a <dl>, with a little CSS grid to line them up.

When the ticket is found, the page shows it. The details are pairs: a label and a value. HTML has an element for exactly that (the comment above the <dl> is left out here):

// Figure 1.29: the details (src/pages/TicketDetailPage.jsx, excerpt)
<dl className="details-list">
  <dt>Ticket ID</dt>
  <dd>{ticket.id}</dd>
  <dt>Customer</dt>
  <dd>{ticket.customer.name}</dd>
  <dt>Assigned to</dt>
  <dd>{ticket.assignedAgent ? ticket.assignedAgent.name : 'Unassigned'}</dd>
  <dt>Created</dt>
  <dd>{formatDate(ticket.createdAt)}</dd>
  <dt>Last updated</dt>
  <dd>{formatDate(ticket.updatedAt)}</dd>
</dl>

<dl>, <dt> and <dd>

A description list (<dl>) holds pairs of a term (<dt>, the label) and its description (<dd>, the value). Screen readers announce it as a list and read each label with its value, so "Assigned to: Unassigned" stays together. With plain <p>s or <div>s, that link between label and value would only exist in how it looks.

It's the same thinking as the ticket table's <th>s in topic 03: choose the element that says what the content is, and screen readers can do the rest.

Notice the agent's value: it's the same ? : check as in TicketList, for the same reason.

Lining them up

/* Figure 1.30: two columns (src/index.css, excerpt) */
.details-list {
  display: grid;
  grid-template-columns: max-content 1fr;
  gap: 0.25rem 1.5rem;
}

display: grid puts the <dt>s and <dd>s into a grid with two columns: the first is as wide as the longest label (max-content), and the second takes the rest of the space (1fr). Because the elements alternate (label, value, label, value), each pair lands on its own row.

The rest of the page

Around the list, the page has a Back to all tickets link, the subject as its one <h1>, the StatusBadge (Figure 1.9), and an <h2> for the description. One <h1> per page, with <h2>s for its parts, lets a screen reader user jump between sections, the same as the starter's pages.
