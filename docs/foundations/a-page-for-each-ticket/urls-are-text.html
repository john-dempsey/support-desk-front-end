URLs Are Text

The ID from the URL is a string, and the tickets' ids are numbers, so the page converts it before comparing.

With the ID in hand, the page finds its ticket. The line is split here to fit; in the file it's one line:

// Figure 1.27: finding the ticket (src/pages/TicketDetailPage.jsx, excerpt)
// Everything in a URL is text, so ticketId is the string "2", not the
// number 2. Without Number(), `ticket.id === ticketId` would always be
// false, because 2 and "2" aren't strictly equal.
const ticket = sampleTickets.find(
  (sampleTicket) => sampleTicket.id === Number(ticketId),
);

Number() before ===

Everything in a URL is text, so ticketId is '2', a string. The tickets' ids are numbers. === compares the type as well as the value, so 2 === '2' is false, and without Number() no ticket would ever match.

Number('2') is 2, so the comparison works. It's the same fix as Number(req.params.id) in the back-end's Lesson 1 controllers, for the same reason.

For a URL like /tickets/hello, Number('hello') is NaN. NaN isn't equal to anything, so no ticket matches, and that's handled on the next slide.

find()

find() is the same method the back-end's in-memory ticket.service.js used: it calls the arrow function for each ticket and gives back the first one where it returns true, or undefined if none do.

The arrow function's parameter is called sampleTicket, not ticket. That's deliberate: ticket is the name of the result, the variable this line creates. Using the same name for both would work, but you'd have to stop and think which ticket each one meant.

Try it

In the browser's Console, type each of these and press Enter. Can you explain each answer?

2 === '2'
2 == '2'
Number('2') === 2
Number('two')
Number('02')
Number('2.0')

Now open http://localhost:5173/tickets/02 and http://localhost:5173/tickets/2.0. Which ticket does each one show, and why? Is that a problem?
