A Route With a Parameter

/tickets/:ticketId is one route that matches every ticket's URL, the same idea as /tickets/:id in Express.

The starter's checklist said every new page needs three things: the page, a route, and (if it belongs in the navigation) a link. Stage 1 adds two routes to App.jsx:

// Figure 1.24: the ticket routes (src/App.jsx, excerpt)
<Route path="/" element={<HomePage />} />
<Route path="/tickets" element={<TicketListPage />} />
{/* ":ticketId" matches any value, like "/tickets/:id" in Express.
    The page reads it with useParams(). */}
<Route path="/tickets/:ticketId" element={<TicketDetailPage />} />

/tickets is an ordinary route, like the starter's /. The second one is new.

A route parameter

The colon in :ticketId makes that part of the path a parameter: a placeholder that matches any value. /tickets/1, /tickets/2 and /tickets/999 all match this one route, and all show TicketDetailPage.

You've written this before:

Route The value is read with
Express router.get('/:id', ...) req.params.id
Laravel Route::get('/tickets/{id}', ...) the controller's $id parameter
React Router <Route path="/tickets/:ticketId" ...> useParams() (next slide)

ticketId is a name you choose. The page will use the same name to read it, so it says what the value is: a ticket's ID.

The ticket list already links to these URLs. Each subject is a <Link to={`/tickets/${ticket.id}`}> (Figure 1.8), so clicking ticket 2 goes to /tickets/2.

The navigation link

// Figure 1.25: the Tickets link (src/components/NavBar.jsx, excerpt)
<li>
  {/* No `end` here, so "Tickets" stays active on a ticket's own
      page (/tickets/2) as well as on /tickets. */}
  <NavLink to="/tickets">Tickets</NavLink>
</li>

The starter showed that NavLink marks the link for the current page as active, and that end means "only on exactly this URL". Without end, a NavLink is also active on every URL under it. That's what you want here: when you're looking at ticket 2, you're still in the Tickets part of the app, and the navigation should say so.

Try it

Open http://localhost:5173/tickets/2 and look at the navigation: which link is active? Now add end to the Tickets NavLink, save, and look again. Which is better for the user? Take end out again.
