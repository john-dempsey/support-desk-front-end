Your Stage 1 Checklist

The same steps for your own case study: sample data in your API's shape, a list page, a detail page, and tests for each.

The starter's checklist said the first step for your own front-end was: show your main entity with a list page and a detail page, using a hard-coded array. Here's how, using the steps Stage 1 took. The examples use a booking system; swap in your own entity.

Run npm test and look at the page in the browser after every step, and commit when both work.

1. Sample data in your API's shape

Call your API's list endpoint (for example GET /bookings) in Thunder Client or Postman, and copy three or four items from its data into src/data/sampleBookings.js. Mark the file TEMPORARY.

Then check the copy:

  • the field names are exactly the API's
  • related records (a customer, a room) are objects, if your API includes them
  • at least one item has null wherever your API can send null
  • every value of a status or category field appears at least once

2. A list component

src/components/BookingList.jsx, taking one prop: bookings. A table with <th scope="col"> headings, one row per item with .map(), key from the id, a Link to each item's own page, a ? : for every field that can be null, and an empty state.

3. A list page

src/pages/BookingListPage.jsx: an <h1>, and <BookingList bookings={sampleBookings} />. Then a <Route> for /bookings in App.jsx, and a NavLink in NavBar.jsx.

4. A detail page

src/pages/BookingDetailPage.jsx at /bookings/:bookingId: useParams(), Number(), find(), a "not found" branch, and a <dl> for the details.

5. Small pieces you can reuse

  • formatDate.js works for any API that sends ISO dates: copy it as it is.
  • If your entity has a status or category, write a badge like StatusBadge, with your own labels and a CSS Module. Keep the words: never colour alone.
  • renderWithProviders.jsx has nothing Support Desk-specific in it: copy it into src/test/.

6. The starter's leftovers

Replace HomePage's connection check with a welcome and a link to your list. Delete welcome.api.js once nothing imports it, and update the tests that used it. Do the TODOs: the title and APP_NAME.

7. Tests

One test file next to each new file, following Stage 1's: a function test for anything in utils/, a props test for each component, and page tests that pass route and path. Add your two routes to App.test.jsx.
