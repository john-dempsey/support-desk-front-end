Tracing a Click

Two clicks followed through Stage 1's code: from the navigation to the list, and from the list to one ticket.

The viva asks you to trace a click through your own code. Stage 1 has no API calls yet, so its trace is shorter than the starter's: there's no API module, no HTTP request and no state. What's left is the part every trace starts with: routes, components and props. Stage 2 adds the rest back.

Click 1: Tickets

You're on the home page, and you click Tickets in the navigation.

  1. NavBar.jsx: the NavLink changes the URL to /tickets. No request is sent.
  2. App.jsx: <Routes> matches /tickets and shows TicketListPage. The NavLink becomes active.
  3. TicketListPage.jsx: the page has the tickets (imported from sampleTickets.js) and renders <TicketList tickets={sampleTickets} />.
  4. TicketList.jsx: there are four tickets, so it skips the empty state, and tickets.map(...) makes one <tr> per ticket, each with a key.
  5. For each row: a Link to /tickets/ + the id, a StatusBadge given the status, the customer's name, the agent's name or "Unassigned", and formatDate(ticket.createdAt).
  6. StatusBadge.jsx: looks up the label and the colour class for its status.

Click 2: a ticket

You click Invoice discrepancy. This is the journey in the diagram from topic 06:

  1. TicketList.jsx: the Link changes the URL to /tickets/2.
  2. App.jsx: /tickets/:ticketId matches, so TicketDetailPage is shown.
  3. TicketDetailPage.jsx: useParams() gives { ticketId: '2' }, and find() looks for the ticket whose id is Number('2').
  4. It's found, so the page skips the "not found" branch and shows the subject, a StatusBadge, the details list and the description.

Questions to practise with

Answer these out loud, with the code open. Then try them again with it closed.

  1. In click 1, which file decides which tickets are shown, and which decides how they look?
  2. What is tickets inside TicketList, and where did it come from?
  3. Why does each <tr> need a key, and why is it ticket.id?
  4. Why does the "Assigned to" cell check ticket.assignedAgent before reading .name, when the "Customer" cell doesn't?
  5. In click 2, how does TicketDetailPage know which ticket to show? Why is Number() needed?
  6. You type /tickets/999 instead. At which step does it go differently, and what does the user see? Which component shows it?
  7. In Stage 2, the tickets will come from the API. Which of the files above do you expect to change, and which won't?
