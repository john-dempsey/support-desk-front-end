Try It Yourself

Challenges that use everything in this lesson. Run the tests after each one, and commit when they pass.

Each of these builds on something from this lesson. After each one, run npm test and npm run lint, and commit when both pass.

Warm-up

  1. A count in the heading. Make the Tickets page's heading say Tickets (4), using the length of the array rather than typing 4. Which file changes: the page or TicketList? Which tests now fail, and how should they change?
  2. Another column. Add a Last updated column to TicketList. What did you reuse to show the date?

Build something

  1. Remove the repeated check. The ? : for the agent's name appears in both TicketList.jsx and TicketDetailPage.jsx. Write a small function, agentName(ticket), in src/utils/, that returns the agent's name or 'Unassigned', and use it in both places. Write a test for it. Do all the existing tests still pass without changes? They should: that's what makes it a safe refactor.
  2. Newest first. In TicketListPage, pass the tickets to TicketList sorted by createdAt, newest first. Use toSorted(), which returns a sorted copy, not sort(), which changes the original array. (Hint: topic 05 said ISO date strings sort alphabetically into date order. b.createdAt.localeCompare(a.createdAt) compares two of them.) Did TicketList need to change?
  3. Only open tickets. Add a checkbox, Show only open tickets, to TicketListPage. Keep whether it's ticked in useState (from the starter), and pass TicketList either every ticket or only the open ones. (filter() is like find(), but it gives back a new array of every item that matches, not just the first.) Give the checkbox a <label>. Stretch: write a test that ticks it, using @testing-library/user-event (it's already installed: look up user.click in its documentation).

Investigate

  1. What if the API changed? Suppose the API renamed assignedAgent to agent. List every file that would have to change. Which ones wouldn't, and why not?
  2. Keys and order. Do challenge 4, then change the row key to the array index (.map((ticket, index) => ...) and key={index}). Does anything look different? Why might it matter later, when rows hold things that change? Put key={ticket.id} back.

Commit

git add .
git commit -m "Stage 1: ticket count, agentName(), newest first, ..."

When your own case study has its list page and detail page working with hard-coded data, it's ready for Stage 2: loading the real data from your API.
