Foundations

A list of tickets and a page for each ticket, built from components and props, with hard-coded data before any of it comes from the API.

  • From Starter to Support Desk

    What Stage 1 adds to the starter, why its tickets are hard-coded for now, and the first changes that make the starter Support Desk.

  • Pages Own the Data

    A page gets the data and passes it down; a component only displays what it's given. That split is what lets Stage 2 change where the tickets come from without touching how they're shown.

  • Lists and Keys

    Turning an array of tickets into table rows with .map(), giving each row a key, and handling the cases where there's nothing to show.

  • StatusBadge and CSS Modules

    A small component that turns the API's status values into readable, coloured labels, with styles that belong to it alone.

  • Formatting Dates

    The API sends dates in a format made for computers. One small function, built on the browser's own Intl.DateTimeFormat, turns them into dates people can read.

  • A Page for Each Ticket

    One route that matches every ticket's URL, a hook that reads the ID from it, and a page that finds the ticket and shows it, or says it isn't there.

  • Testing Stage 1

    Tests for a plain function, a component with props, components that need a router, and a page that reads the URL, plus the helper they share.

  • Making It Yours

    Tracing a click through Stage 1, then taking the same steps for your own case study's main entity.
