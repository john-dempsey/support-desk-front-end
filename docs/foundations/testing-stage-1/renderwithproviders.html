Giving useParams() a Route →

renderWithProviders

Anything with a <Link> or useParams() needs a router around it. One shared helper provides it, so no test has to set it up itself.

TicketList contains <Link>s, and a <Link> only works inside a router. In the app, main.jsx provides one. A test that renders TicketList on its own has no router, and fails with this:

Cannot destructure property 'basename' of 'React$1.useContext(...)' as it is null.

That message doesn't mention a router at all. If you see it in a test, the component you rendered needs a router around it.

One helper for every test

The starter's App.test.jsx wrapped App in a MemoryRouter itself. Stage 1 has five test files that need a router, so instead of five copies, there's one shared helper in src/test/:

// Figure 1.33: the helper (src/test/renderWithProviders.jsx, excerpt)
export function renderWithProviders(
  componentToTest,
  { route = '/', path } = {},
) {
  let content = componentToTest;
  if (path) {
    content = (
      <Routes>
        <Route path={path} element={componentToTest} />
      </Routes>
    );
  }

  return render(
    <MemoryRouter initialEntries={[route]}>{content}</MemoryRouter>,
  );
}

(The first and last lines of the function are split to fit here.)

It renders whatever component it's given, inside a MemoryRouter starting at route. The if (path) part is for pages that read the URL, on the next slide. Most tests just write:

renderWithProviders(<TicketList tickets={testTickets} />);

The options object

The second parameter is an object of options, destructured with default values: route is '/' unless the test says otherwise, and path is undefined. The = {} at the end means the whole object can be left out. A test only passes the options it needs, by name: { route: '/tickets/2', path: '/tickets/:ticketId' }.

Why "providers"?

A provider is a component that wraps the app and gives everything inside it something it needs. MemoryRouter provides the router. The helper's name says it provides whatever the app's components expect, so when the app later needs a second provider, it's added in this one file and every test gets it.

App.test.jsx uses it too now, so its renderAppAt(url) is one line: renderWithProviders(<App />, { route: url }).

Try it

In TicketList.test.jsx, change one renderWithProviders( to render( and import render from @testing-library/react. Run the tests and read the error. Then undo the change.
