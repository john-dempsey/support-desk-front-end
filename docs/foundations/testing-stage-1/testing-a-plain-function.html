Testing a Plain Function

formatDate has no React in it, so its test just calls it and checks what comes back.

Stage 1 adds five test files. The simplest is for formatDate, because it's an ordinary function: a string goes in, a string comes out.

// Figure 1.31: testing formatDate (src/utils/formatDate.test.js, excerpt)
describe('formatDate', () => {
  it('turns an ISO date string into a readable date', () => {
    // Midday UTC, so the day is the same in any time zone the tests run in.
    const readableDate = formatDate('2026-10-08T12:00:00.000Z');

    expect(readableDate).toContain('8 Oct 2026');
  });

  it('returns "Unknown date" instead of crashing for a bad value', () => {
    expect(formatDate('not a date')).toBe('Unknown date');
    expect(formatDate(undefined)).toBe('Unknown date');
  });
});

No render(), no screen, no page: just call it and check the result. It's the same kind of test as a back-end unit test for a helper in utils/. Functions like this are the easiest code to test, which is one more reason to keep logic like formatting out of components.

Choosing the test data

Two details make this test reliable on any computer:

  • Midday UTC. formatDate shows the date in the computer's own time zone. A time near midnight, like 23:30Z, would be the 9th in Ireland but still the 8th in New York, so the test would pass on one computer and fail on another. Midday is the same day almost everywhere.
  • toContain, not toBe. The test checks the date part only. The time part depends on the time zone, so checking the whole string with toBe would have the same problem.

The bad cases

The second test checks the case from topic 05: a bad value gives 'Unknown date' instead of a crash. One it can hold more than one expect, as long as they test the same idea.

Try it

Change the date in the first test to '2026-10-08T23:30:00.000Z', and run npm test. Does it pass? Would it pass on a computer in New York? Why, or why not? Change it back.
