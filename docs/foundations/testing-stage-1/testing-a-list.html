Testing a List

TicketList's tests bring their own tickets, count the rows, look inside one row with within(), and check the empty state.

TicketList's tests don't use sampleTickets. They have a small array of their own, testTickets: two tickets made up for the test, one assigned to Alex and one (Mouse missing) with assignedAgent: null. The test decides exactly which cases it needs, and nobody can break it by editing the sample data.

Counting rows

// Figure 1.35: one row per ticket (src/components/TicketList.test.jsx,
// excerpt)
it('shows one row for each ticket, plus the heading row', () => {
  renderWithProviders(<TicketList tickets={testTickets} />);

  expect(screen.getAllByRole('row')).toHaveLength(3);
});

getAllBy... is like getBy..., but it finds every match and returns an array (and fails if there are none). Two tickets give three rows, because the heading row in <thead> is a row too.

Looking inside one row

// Figure 1.36: within one row (src/components/TicketList.test.jsx, excerpt)
it('shows "Unassigned" when a ticket has no agent', () => {
  renderWithProviders(<TicketList tickets={testTickets} />);

  // within() limits the search to one row, so the test checks the right
  // ticket, not just that "Unassigned" appears somewhere on the page.
  const mouseRow = screen.getByRole('row', { name: /Mouse missing/ });
  expect(within(mouseRow).getByText('Unassigned')).toBeInTheDocument();
});
  • { name: /Mouse missing/ } finds the row by its accessible name, which for a row is all the text in its cells. The /.../ is a regular expression, so it matches if the name contains "Mouse missing".
  • within(mouseRow) gives the same queries as screen, but only searching inside that one row.

Without within(), the test would pass if "Unassigned" appeared in any row, even the wrong one.

The empty state

// Figure 1.37: no tickets (src/components/TicketList.test.jsx, excerpt)
it('shows a message when there are no tickets', () => {
  renderWithProviders(<TicketList tickets={[]} />);

  expect(
    screen.getByText('There are no tickets to show.'),
  ).toBeInTheDocument();
  expect(screen.queryByRole('table')).not.toBeInTheDocument();
});

(The first expect is one line in the file; it's split here to fit.)

Passing [] tests the early return from topic 03, which the sample data can never reach. The second expect uses queryBy, from the starter, to check the table is not there.
