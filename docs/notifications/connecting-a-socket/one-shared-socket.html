One Shared Socket

socket.js creates the socket once, when it's first imported, and every part of the app shares it. autoConnect: false waits until someone has logged in.

The top of socket.js creates the socket:

// Figure 5.12: one socket for the whole app
// (src/realtime/socket.js, excerpt)
import { io } from 'socket.io-client';
import { getSavedToken } from '../api/tokenStorage.js';

// The same base URL as client.js: Socket.IO runs on the API's own port.
const API_URL = import.meta.env.VITE_API_URL || 'http://localhost:3000';

// autoConnect: false means "don't connect yet". There's nobody to connect
// for until a user has logged in, so connectSocket() does it then.
const socket = io(API_URL, { autoConnect: false });

getSavedToken() is for the next slide.

io()

io(url, options) makes a socket object that knows where the server is. With autoConnect: false that's all it does: nothing is sent until something calls socket.connect(). Without it, every visitor to the login page would open a connection the server can't use, since they have no token to send yet.

The URL is the API's own. The back-end attaches Socket.IO to the same HTTP server as its routes, in server.js (Lesson 5, "Socket.IO: a WebSocket Library"), so it answers on port 3000 too. The URL is read from VITE_API_URL the same way as in client.js, so changing .env moves both.

Once, when it's first imported

The code at the top level of a module runs once, the first time any file imports it. Every later import gets the same module, with the same socket. So however many components use these functions, the app has one connection. It's the back-end's config/db.js and config/socket.js idea, "importing it is how you share it", in the browser.

socket isn't exported. Other files can only use the socket through socket.js's three functions, so there's one place to look when something goes wrong with it.

Why not create it in a component?

A component's function runs every time it renders. A const socket = io(...) there would make a new socket object on every render, and each one could open its own connection. Module code doesn't re-run, so creating the socket here avoids the problem altogether.

Try it

In socket.js, temporarily change autoConnect: false to autoConnect: true. Log out, then reload the login page with the Network tab open, filtered to socket.io. What do you see, before anyone has logged in? Put it back.
