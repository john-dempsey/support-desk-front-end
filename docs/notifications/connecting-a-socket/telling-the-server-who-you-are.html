Telling the Server Who You Are, Every Time

sendToken() is a connect handler, so it runs on the first connection and on every automatic reconnection, when the server has forgotten the socket's room.

Connecting, and saying who you are, are two separate steps:

// Figure 5.13: connecting and disconnecting
// (src/realtime/socket.js, excerpt)
// The server doesn't know who a socket belongs to until it's told, so the
// token is sent on *every* connect. If the connection drops (the API
// restarts, the Wi-Fi blinks), Socket.IO reconnects by itself, but the
// server has forgotten the socket's room, so it must be told again.
// The token comes from the same place as client.js's: the one saved at
// login.
function sendToken() {
  socket.emit('authenticate', getSavedToken());
}

export function connectSocket() {
  // off() first, so connecting twice never sends the token twice.
  socket.off('connect', sendToken);
  socket.on('connect', sendToken);
  socket.connect();
}

// Called on logout: no more pushes for the user who has left.
export function disconnectSocket() {
  socket.off('connect', sendToken);
  socket.disconnect();
}

on, off and emit

These are the same three words as on the server:

  • socket.on('connect', sendToken): when the connect event happens, call sendToken. Like addEventListener('click', ...) on a button.
  • socket.off('connect', sendToken): stop calling it. It has to be the same function, which is why sendToken has a name rather than being written inline.
  • socket.emit('authenticate', getSavedToken()): send a message called authenticate, carrying the token, to the server.

Why "every time"?

connect doesn't only happen once. Socket.IO reconnects by itself when a connection drops, and each reconnection fires connect again:

Sending the token from a connect handler covers the first connection and every reconnection with one line.

The same token as client.js

sendToken() reads the token with getSavedToken() each time it runs, just as client.js's getToken() does before every request. So nobody has to pass the token in, and a reconnection long after login still finds it in localStorage. As in Stage 4, no component handles the token: only the two files that send it (client.js and socket.js) read it, and only AuthProvider saves and clears it.

off before on

If connectSocket() were ever called twice, on alone would register sendToken twice, and every connection would send the token twice. Removing it first makes calling connectSocket() again harmless. disconnectSocket() removes it too, so nothing is sent for a user who has logged out.
