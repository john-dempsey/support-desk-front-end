Connecting a Socket

One shared Socket.IO connection, opened when someone logs in: it tells the server whose it is on every connect, lets components listen for pushes, and closes on logout.

  • The Server Side, Briefly

    You built the other end in the back-end: a socket says who it is by sending its token, joins its user's room, and receives notification.created.

  • One Shared Socket

    socket.js creates the socket once, when it's first imported, and every part of the app shares it. autoConnect: false waits until someone has logged in.

  • Telling the Server Who You Are, Every Time

    sendToken() is a connect handler, so it runs on the first connection and on every automatic reconnection, when the server has forgotten the socket's room.

  • Listening, and Stopping

    onNotification() adds a handler for notification.created, and gives back the function that removes it: exactly what an effect's cleanup needs.

  • Opening the Socket at Login

    The provider's effect gains four lines: connect when a user logs in, re-fetch the count on each push, and stop listening and disconnect in the cleanup.
