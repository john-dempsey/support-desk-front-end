The List, and Who Sees the Notice

The list page shows a notice for any notification about a ticket. And only people the API tells see a notice at all: a notification isn't a 'something changed' broadcast.

TicketListPage works the same way, with one difference in the handler:

// Figure 5.21: any ticket might be in the list
// (src/pages/TicketListPage.jsx, excerpt)
// Any notification about a ticket might mean the list is out of date: a
// new ticket, a new status, a new agent. (One whose ticket has been
// deleted has a ticketId of null, and there's nothing to reload for.)
useEffect(() => {
  function handleNotification(notification) {
    if (notification.ticketId !== null) {
      setHasChanged(true);
    }
  }

  const stopListening = onNotification(handleNotification);
  return stopListening;
}, []);

The list doesn't check whether the ticket is on the current page of results. A new ticket could belong on page 1, and a status change could move a ticket in or out of a filter, so "any ticket" is the honest answer. The rest is Figure 5.20 again: a reloadCount in the fetch effect's list ([queryString, reloadCount]), and the same RefreshNotice.

Who sees a notice

A page only hears about a change if the API sends this user a notification about it. So, with ticket 1's page open in three browsers:

Whoever made the change already sees it on their own screen: their page updated from the API's response. Everyone else only finds out if the API tells them.

A notification isn't a live update

That's the limit of building this on notifications. A notification means "you have something to read", and the API decides who that is. It was never meant to say "the data on someone's screen has changed". Lesson 8 made the same point from the back-end's side ("A Notification Isn't a Live Update"): keeping every open screen up to date would need a different push, such as a room per ticket that every viewer of that ticket joins.

For this app, telling the people who are told is enough: the customer hears about their ticket, and the assigned agent hears about the customer.
