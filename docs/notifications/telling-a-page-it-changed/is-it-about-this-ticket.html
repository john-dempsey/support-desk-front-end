Is It About This Ticket?

The detail page listens for notifications, and shows the notice only for one about the ticket it's showing, and not for the customer's own 'ticket created'.

TicketDetailPage listens while it's open, and decides whether each notification is about its ticket:

// Figure 5.19: listening for changes to this ticket
// (src/pages/TicketDetailPage.jsx, excerpt)
useEffect(() => {
  function handleNotification(notification) {
    // ticketId in the URL is a string ("2"); the notification's is a
    // number (2).
    const isAboutThisTicket =
      notification.ticketId === Number(ticketId);
    // A customer who has just created a ticket lands on its page, and
    // their own "Your ticket was created" arrives there. The ticket
    // hasn't changed since it loaded, so that one is ignored.
    const isNewTicket = notification.type === 'ticket.created';
    if (isAboutThisTicket && !isNewTicket) {
      setHasChanged(true);
    }
  }

  const stopListening = onNotification(handleNotification);
  return stopListening;
}, [ticketId]);

(The isAboutThisTicket line is reflowed to fit.)

A string and a number

useParams() gives ticketId as text from the URL: "1". The notification's ticketId is a number from the JSON: 1. === never calls a string and a number equal, so "1" === 1 is false. Number(ticketId) turns the URL's text into a number first. It's the same conversion EditTicketPage does before sending an agent's ID (Stage 3, topic 05).

Why ticket.created is ignored

When Casey creates a ticket, NewTicketPage goes straight to the new ticket's page. The API tells Casey too ("Your ticket … was created."), and that push arrives while Casey is on that very page. Without the check, a ticket Casey created a moment ago would say it "has changed".

[ticketId] this time

The handler reads ticketId, so the effect lists it. If the URL changes to another ticket while the page stays on screen, the cleanup stops the old handler, and a new one is registered that knows the new ID.

This handler never reads state that it then changes: it just sets hasChanged to true. So it doesn't need the function form from topic 05. That's only for a new value worked out from the old one.
