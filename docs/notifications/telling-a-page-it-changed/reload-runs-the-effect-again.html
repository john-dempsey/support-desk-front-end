Reload Runs the Effect Again

A reloadCount in the fetch effect's dependency list: adding 1 makes the effect run again. And why the page asks first, rather than reloading by itself.

The detail page already has an effect that loads the ticket and its comments (Stage 3). Reload needs to run it again. React has no "run this effect now" function, but an effect runs again whenever something in its dependency list changes. So the page adds something to change:

// Figure 5.20: Reload runs the fetch effect again
// (src/pages/TicketDetailPage.jsx, excerpts)
// How many times Reload has been clicked. Its only job is to be in the
// fetch effect's dependency list: adding 1 makes the effect run again.
const [reloadCount, setReloadCount] = useState(0);

// ... the fetch effect, whose cleanup now also calls
//     setHasChanged(false) ...
}, [ticketId, reloadCount]);

function handleReload() {
  setReloadCount(reloadCount + 1);
}

// ... and in the JSX, above the <h1>:
{hasChanged && (
  <RefreshNotice
    message="This ticket has changed."
    onReload={handleReload}
  />
)}

(Three excerpts, and the <RefreshNotice> line is reflowed to fit.)

reloadCount's value doesn't matter, only that it's different. The cleanup already puts the page back to "loading" when the URL changes to another ticket (Stage 2), so a reload gets that for free, plus setHasChanged(false) to remove the notice.

Why not reload automatically?

The handler in Figure 5.19 could have bumped reloadCount itself. It doesn't, because of step 3 in the diagram. While the page is loading, it shows Loading instead of the ticket, so CommentForm is taken off the screen, and the text in it (its own state) goes with it.

So if Alex were halfway through a reply when Casey's comment arrived, an automatic reload would wipe it. A notice can't do any harm: Alex finishes typing, posts the reply, and clicks Reload when it suits them.

Reloading quietly, without losing anything, is possible, but it needs more code. It's a challenge at the end of this lesson.

Try it

With Alex on ticket 1 and Casey in the other browser:

  1. As Alex, start typing a comment, but don't post it. As Casey, comment on ticket 1. Is Alex's text still there when the notice appears? Now click Reload. What happened to the text, and which step of the diagram did it?
  2. In TicketDetailPage.jsx, remove reloadCount from the effect's dependency list (leaving [ticketId]). Save, reload, and repeat. What does Reload do now? Run npm run lint: does it notice? (The linter asks for every value an effect uses, and this effect never reads reloadCount.) Now run npm test: which test notices? Put it back.
