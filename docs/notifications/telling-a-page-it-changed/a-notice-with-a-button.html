A Notice With a Button

RefreshNotice is a message and a Reload button, in a polite live region. The ticket pages show it when the data on screen may be out of date.

Alex has ticket 1 open. Casey comments on it, and Alex's count goes up, but the comment isn't on Alex's screen: the page loaded the comments when it opened, and hasn't asked since. It should at least say so.

That's the job of one small new component:

// Figure 5.18: a message, and a button to load again
// (src/components/RefreshNotice.jsx, excerpt)
function RefreshNotice({ message, onReload }) {
  return (
    <div role="status" className="refresh-notice">
      <p>{message}</p>
      <button type="button" onClick={onReload}>
        Reload
      </button>
    </div>
  );
}

It knows nothing about tickets or notifications. It shows whatever message it's given, and calls onReload when the button is clicked, the same "display, and call back" shape as CommentList or NotificationList. Both ticket pages use it, with their own message:

Page Message
TicketDetailPage "This ticket has changed."
TicketListPage "The tickets have changed."

role="status"

The notice appears without the user doing anything, so a screen reader user needs to be told. role="status" makes the <div> a polite live region, like Loading and the unread count (topic 03): the screen reader announces the message when it appears, without interrupting.

Asking, not doing

The notice offers to reload. It doesn't reload by itself. Slide 03 explains why: reloading the page's data would throw away anything the user was halfway through typing.

Try it

Log in as Alex in one browser and Casey in the other. As Alex, open ticket 1. As Casey, comment on it. When the notice appears on Alex's page, find it in the developer tools' Elements tab. What role does it have, and where on the page is it? Then click Reload. Which comment is new, and what happened to the notice?
