Messages on the WebSocket

The WebSocket row's Messages list the switch-over, the pings that keep it alive, and each push. A push is followed straight away by the HTTP request that counts again.

Choose the Socket filter, click the newest socket.io row (not Vite's ?token=… row), and open Messages. Each line is one message: a green up-arrow for one the browser sent, a red down-arrow for one the server sent.

What each message is

Message From Means
2probe browser "does this WebSocket work?"
3probe server "yes"
5 browser "switch to it": from now on, everything goes this way
2 / 3 server / browser a ping and its answer, about every 25 seconds, so both ends know the connection is still alive
42["notification.created",{…}] server a push: the saved notification

The first three are the switch-over from the previous slide. After that, the WebSocket is quiet, apart from the pings, until something happens to Alex.

A push, then a request

Have Casey comment on ticket 1. A 42["notification.created",{…}] message arrives; click it to see the notification laid out as a tree, as at the bottom of the screenshot. It's exactly one item of GET /notifications: id, type, message, ticketId, readAt and createdAt. Now look at the request list (switch the filter to All): straight after the push, Alex's browser sends two HTTP requests, a preflight and GET /notifications?unread=true.

That's the whole of "REST is the truth, the socket is a nudge" in two lines of the Network tab. The push says something happened, and the count is fetched over HTTP (topic 05, slide 02).

Try it

  2. Have Casey comment on ticket 1. Compare the push's data with the newest item in Alex's GET /notifications response. Are they the same?
