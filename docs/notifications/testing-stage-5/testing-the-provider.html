Testing the Provider

NotificationsProvider is tested for real, inside a plain AuthContext value. Rendering again with user: null is how a test logs out.

NotificationsProvider's test follows Stage 4's AuthProvider test: a tiny ShowCount component inside it shows unreadCount on the screen. The difference is who's logged in. NotificationsProvider only reads user from useAuth(), so the test doesn't need the real AuthProvider. It fills AuthContext with a plain object:

// Figure 5.24: logging out by rendering again
// (src/context/NotificationsProvider.test.jsx, excerpts)
function providersFor(user) {
  return (
    <AuthContext value={{ user }}>
      <NotificationsProvider>
        <ShowCount />
      </NotificationsProvider>
    </AuthContext>
  );
}

// ... the other tests, then:
it('stops listening, disconnects and goes back to 0 on logout',
  async () => {
    getUnreadNotifications.mockResolvedValue([unreadNotification]);
    const stopListening = vi.fn();
    onNotification.mockReturnValue(stopListening);
    const { rerender } = render(providersFor(agentUser));
    await screen.findByText('1 unread');

    rerender(providersFor(null));

    expect(stopListening).toHaveBeenCalled();
    expect(disconnectSocket).toHaveBeenCalled();
    expect(screen.getByText('0 unread')).toBeInTheDocument();
  },
);

(The it( line is reflowed to fit.)

{ user } is enough

AuthContext's real value has six things in it (Stage 4, topic 04). The provider uses one, so the fake has one. A fake only needs what the code under test reads.

rerender(): logging out without a login page

render() returns rerender, which renders something new in the same place, so React updates what's there rather than starting again. Rendering with providersFor(null) is the same as AuthProvider setting user to null: the effect's cleanup runs, then the effect runs with null. The test then checks all three things the cleanup does.

Faking socket.js

This file fakes the whole module with vi.mock('../realtime/socket.js'), so connectSocket, disconnectSocket and onNotification are vi.fn()s. onNotification normally returns a "stop listening" function, so the test gives it one to return, a vi.fn() it can check later: onNotification.mockReturnValue(stopListening).

Try it

In NotificationsProvider.jsx, delete setUnreadCount(0); from the cleanup. Run npm test. Which test fails, and what does it say it found instead of "0 unread"? Put it back.
