Testing the Notice

The ticket page tests push notifications about this ticket, another ticket, and a new ticket, and check the notice appears only for the first. Reload is a click.

TicketDetailPage.test.jsx gains a group of tests for the notice. They share a helper that opens ticket 1 as Alex, ready to push:

// Figure 5.27: the notice, and when it doesn't appear
// (src/pages/TicketDetailPage.test.jsx, excerpts)
// Alex is looking at ticket 1, which is assigned to them.
async function renderTicketForAlex() {
  getTicket.mockResolvedValue(ticketAssignedToAlex);
  const socket = captureNotificationHandler();
  renderWithProviders(<TicketDetailPage />, {
    route: '/tickets/1',
    path: DETAIL_PATH,
    user: agentUser,
  });
  await screen.findByRole('heading', { level: 1, name: 'Cannot log in' });
  return socket;
}

// ... the first test in the group, then:
it('says nothing for a notification about another ticket', async () => {
  const socket = await renderTicketForAlex();

  await socket.push({ ...commentPush, ticketId: 2 });

  expect(screen.queryByText('This ticket has changed.'))
    .not.toBeInTheDocument();
});

(The last expect is reflowed to fit.)

One notification, changed a little

{ ...commentPush, ticketId: 2 } is the same object spread you've used for new arrays, applied to an object: every field of commentPush, with ticketId replaced. The "ticket created" test does the same with type: 'ticket.created'. Each test changes exactly the one thing it's about.

Something that doesn't happen

Two of the four tests check that the notice doesn't appear. They use queryByText and .not.toBeInTheDocument(), the same way Stage 4 checked a customer sees no Edit button. A test that something doesn't happen is only worth having next to one that shows it does happen, for the right notification. The first test in the group does that.

Reload, and the list page

The Reload test pushes, clicks Reload, and checks the API was asked again (getTicket called twice) and the notice has gone. TicketListPage.test.jsx has the same three ideas: a notice, none for a deleted ticket (ticketId: null), and Reload asking again with the same query.

The other tests in both files don't push anything. They don't call captureNotificationHandler(), so the faked onNotification returns nothing, and the effect's cleanup is simply undefined: nothing to stop.
