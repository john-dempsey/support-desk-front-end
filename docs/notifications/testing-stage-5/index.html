Testing Stage 5

Testing code that waits for a server to speak first: a fake socket.io-client, a helper that pushes a notification in a test, and a test for each place that listens.

  • What Stage 5 Tests

    Five new test files and four changed ones. The socket is faked at two different depths, depending on what's being tested.

  • Faking socket.io-client

    socket.test.js replaces the library with a small fake socket whose on and off really keep handlers, so a test can fire a connect or a push itself.

  • A Connect, a Reconnect, a Push

    With the fake socket, a test plays the server: fire('connect') once or twice, or fire a notification, then check what socket.js did.

  • Testing the Provider

    NotificationsProvider is tested for real, inside a plain AuthContext value. Rendering again with user: null is how a test logs out.

  • Pushing in a Test

    captureNotificationHandler() keeps the handler a component passes to onNotification(), and push() calls it inside act(), as if the server had sent something.

  • Testing the Function Form

    Two pushes in a row prove the page adds to the list it has now, not the list it had when it opened. And a push during loading is tested with a promise the test resolves itself.

  • Testing the Notice

    The ticket page tests push notifications about this ticket, another ticket, and a new ticket, and check the notice appears only for the first. Reload is a click.

  • The Real Providers in App.test

    App.test.jsx's whole-visit test now runs the real NotificationsProvider too, so socket.js and the notifications API are faked, and onNotification has to return something.

  • Running Everything

    Stage 5 ends with 161 passing tests in 29 files. Break one line at a time to see which test guards it, and commit.
