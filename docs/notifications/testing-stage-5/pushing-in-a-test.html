Pushing in a Test

captureNotificationHandler() keeps the handler a component passes to onNotification(), and push() calls it inside act(), as if the server had sent something.

The provider and the pages all call onNotification(handler). With socket.js faked, nothing will ever call that handler, unless the test does. A small shared helper keeps it:

// Figure 5.25: playing the server in a page test
// (src/test/fakeSocket.js, excerpt)
export function captureNotificationHandler() {
  let savedHandler = null;

  onNotification.mockImplementation((handler) => {
    savedHandler = handler;
    // The real onNotification() returns a "stop listening" function.
    return vi.fn();
  });

  return {
    // act() tells React a change is coming from outside (here, the
    // "socket"), and waits for the screen to update before the test goes
    // on to check it.
    async push(notification) {
      if (savedHandler === null) {
        throw new Error(
          'Nothing is listening: render the component first.',
        );
      }
      await act(async () => {
        savedHandler(notification);
      });
    },
  };
}

(The throw line is reflowed to fit.)

How it's used

const socket = captureNotificationHandler();   // before rendering
renderPage();                                  // the page calls
                                               //   onNotification()
await socket.push(commentPush);                // "the server" pushes

mockImplementation() gives the fake onNotification some code to run. When the page's effect calls it, it saves the handler, and push() calls that handler later with whatever notification the test chooses.

act()

When a user clicks, userEvent tells React, and React updates the screen before the test checks it. A push isn't a click: it's ordinary code calling the handler, and React doesn't know a test is waiting. act() is React Testing Library's way of saying "a change is coming from outside; finish updating before you go on". Without it, the test checks the screen before the new notification is on it.

Every push in a test goes through push(), so act() is written once, here.

Try it

In fakeSocket.js, replace the three lines of await act(...) with just savedHandler(notification);. Run npm test. Six push tests fail: what does the first failure say it found?
