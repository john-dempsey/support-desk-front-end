Faking socket.io-client

socket.test.js replaces the library with a small fake socket whose on and off really keep handlers, so a test can fire a connect or a push itself.

socket.js calls io() once, when it's first imported, and uses what comes back. To test it without a server, the test makes io() return a fake:

// Figure 5.22: a fake socket (src/realtime/socket.test.js, excerpt)
// vi.hoisted() makes fakeSocket exist before vi.mock() below runs, which
// Vitest moves to the top of the file.
const fakeSocket = vi.hoisted(() => {
  const handlers = {};
  return {
    // `on` and `off` really store and remove handlers, so the fake works
    // like the real thing.
    on(eventName, handler) {
      handlers[eventName] = handlers[eventName] || [];
      handlers[eventName].push(handler);
    },
    off(eventName, handler) {
      handlers[eventName] = (handlers[eventName] || []).filter(
        (storedHandler) => storedHandler !== handler,
      );
    },
    // Calls every handler for an event, as the real socket would when the
    // event happens.
    fire(eventName, payload) {
      for (const handler of handlers[eventName] || []) {
        handler(payload);
      }
    },
    emit: vi.fn(),
    connect: vi.fn(),
    disconnect: vi.fn(),
  };
});

vi.mock('socket.io-client', () => ({
  io: () => fakeSocket,
}));

vi.mock() with a factory

Until now, vi.mock(path) has replaced every export of a module with a vi.fn() that returns nothing. That's no good here: socket.js needs a socket whose on and off actually remember handlers. So this vi.mock() has a second argument, a factory: a function that returns the fake module. Its io returns fakeSocket.

Half real, half fake

  • on, off and fire are real code. They keep a list of handlers per event name, just like the real socket. fire() is the test's addition: it plays the server, calling every handler for an event.
  • emit, connect and disconnect are vi.fn(). The test only needs to know they were called, and with what.

vi.hoisted()

Vitest moves every vi.mock() call to the top of the file, above the imports, so the fake is in place before socket.js is imported and calls io(). An ordinary const fakeSocket further down wouldn't exist yet at that point. vi.hoisted() moves its code to the top too, so fakeSocket is ready when the factory needs it.

Try it

Make the fake's off do nothing: replace the whole off(...) { ... } method with off() {}, and run npx vitest run src/realtime. Four tests fail. Three of them test off one way or another, but one, "sends the token again after a reconnect", never calls off itself. Why does it fail too?
