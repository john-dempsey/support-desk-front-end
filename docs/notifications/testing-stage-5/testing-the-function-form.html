Testing the Function Form

Two pushes in a row prove the page adds to the list it has now, not the list it had when it opened. And a push during loading is tested with a promise the test resolves itself.

Topic 05's function form exists for one reason: the push handler must add to the list as it is now. One test pins that down:

// Figure 5.26: two pushes, both kept
// (src/pages/NotificationsPage.test.jsx, excerpt)
it('keeps every pushed notification when several arrive', async () => {
  getNotifications.mockResolvedValue([]);
  const socket = captureNotificationHandler();
  renderPage();
  await screen.findByText('You have no notifications.');

  await socket.push(unreadNotification);
  await socket.push(commentPush);

  // Newest first: the second push is at the top, and the first is kept.
  const items = screen.getAllByRole('listitem');
  expect(items).toHaveLength(2);
  expect(within(items[0]).getByText(commentPush.message))
    .toBeInTheDocument();
  expect(within(items[1]).getByText(unreadNotification.message))
    .toBeInTheDocument();
});

(The two within lines are reflowed to fit.)

Why two pushes?

With one push, the plain form's mistake can hide: if the list it started from happened to be the right one, the result looks fine. The second push is the test: it only survives alongside the first if the handler builds on the list the first push left behind. And the list starts as [] here, so this test fails even if the handler forgot about null entirely.

A push while the page is loading

The other push test (topic 05, slide 06) needs the page to stay loading while it pushes. mockReturnValue(new Promise(() => {})) would keep it loading forever. This test needs to finish the load later, so it makes a promise whose resolve it keeps:

let finishLoading;
getNotifications.mockReturnValue(
  new Promise((resolve) => {
    finishLoading = resolve;
  }),
);

Then it pushes, and only then calls finishLoading([...]), inside act(), to play the API's answer arriving.

The gap

Topic 05's other function form, in handleMarkRead, isn't tested: no test pushes while a PATCH is on its way. Put the plain form back in handleMarkRead and every test still passes. Testing it would mean holding the PATCH open with a promise, as above, and pushing in the middle.
