What Changes, and What Doesn't

Stage 5 adds a notifications page, a second context, a realtime folder and a notice component. client.js and the other API modules don't change.

Here's every file in src/ that Stage 5 touches, leaving out the tests (topic 08):

Folder New Changed
api/ notifications.api.js
context/ notificationsContext.js, NotificationsProvider.jsx README.md
realtime/ socket.js (a new folder)
pages/ NotificationsPage TicketListPage, TicketDetailPage: the "this has changed" notice
components/ NotificationList, RefreshNotice NavBar: the Notifications link and unread count
main.jsx: wraps the app in NotificationsProvider. App.jsx: one route. index.css: notification styles

package.json gains one library, socket.io-client: the client half of Socket.IO. You've met it already: Lesson 5 named it as the package this front-end would use, and Lesson 8's watch-notifications.js script used it to print Alex's pushes.

One new route

The notifications page is for anyone logged in, whatever their role:

// Figure 5.1: the notifications page's route (src/App.jsx, excerpt)
<Route
  path="/notifications"
  element={
    <ProtectedRoute>
      <NotificationsPage />
    </ProtectedRoute>
  }
/>

There's no allowedRoles, like the ticket list's route. The API's GET /notifications has no authorize(...) either: every user may read their own.

What doesn't change

  • client.js. Not one line. notifications.api.js calls apiRequest() like every other API file, and gets the token, the JSON and the error shape for free.
  • tickets.api.js, comments.api.js, tags.api.js, users.api.js, auth.api.js.
  • AuthProvider. The new provider reads the user with useAuth(), like any other component.

Try it

Once you've got the stage-05 code, list every file in src/ that changed since the end of Stage 4:

git diff --stat stage-04 stage-05 -- src

Then check the claim about client.js:

git diff stage-04 stage-05 -- src/api/client.js

Why does it make sense that a whole new kind of data needs no change to client.js?
