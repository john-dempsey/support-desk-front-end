Only If Your API Has Notifications

Stage 5 needs an API that saves notifications and pushes them over Socket.IO, as well as a login. If yours doesn't, your app is already complete.

This stage needs an API with notifications: Step 5 of the back-end assignment, on top of Step 4's authentication. If your own API has no notifications, stop at Stage 4 (or at Stage 3, if it has no login either). Your app is complete and working without this stage: nothing in Stages 1 to 4 depends on it.

The Support Desk API has had notifications since Lesson 5, "Events & Notifications". These are the parts this stage uses:

Lesson What it gave the API
5, "Real-Time Push with Socket.IO" a Socket.IO server; a socket sends its token to say who it belongs to
7, "A User's Own Notifications" and "Idempotent Updates" GET /notifications and PATCH /notifications/:id/read
8, "The New Socket Contract" one push event, notification.created, sent only to the user it's for, after the notification is saved

What the user gets

  • A notifications page: everything the API has told this user, newest first, each with a Mark as read button until it's read.
  • An unread count in the navigation bar, on every page.
  • Live updates. When something happens, the count goes up and the notifications page shows the new one, without a reload.
  • A "this has changed" notice on a ticket's page when a notification about that ticket arrives, with a Reload button.

Your own API

Your case-study API may name its events differently, or still push them the way Lesson 5 first did. That's fine. The pattern in this stage carries over: load the saved notifications over REST, open a socket after login, tell the server who you are each time it connects, and listen for the event your server sends.

Try it

Before you start, check your own API is ready. In your REST client, logged in as a user who should have notifications:

  1. Ask for that user's notifications. Do you get a list?
  2. Find the code in your back-end that pushes over Socket.IO. What is the event called, and who receives it?

If you can answer both, your API is ready for Stage 5. Keep the event name: you'll need it in topic 04.
