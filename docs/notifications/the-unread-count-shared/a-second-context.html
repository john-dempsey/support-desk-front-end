A Second Context

The unread count is shown in the navigation bar, but changed by the notifications page. Like the logged-in user, it's shared through a context, in the same two files.

The navigation bar shows "Notifications (3 unread)" on every page. Who needs that number?

Component Needs For
NavBar unreadCount the "(3 unread)" next to the link
NotificationsPage refreshUnreadCount() after Mark as read, one fewer is unread

Two components, a long way apart: NavBar is rendered by App above <Routes>, and NotificationsPage is several levels down, inside a route. One shows the number and the other changes it.

The same answer as the user

That's the problem Stage 4 met with the logged-in user (topic 03, "Who Needs the User?"). Holding the count in App and passing it down as props would mean prop drilling again. So the count gets its own context, in the same two files:

// Figure 5.7: the count's context and its hook
// (src/context/notificationsContext.js, excerpt)
import { createContext, useContext } from 'react';

export const NotificationsContext = createContext(null);

// The one way components get the value:
//   const { unreadCount, refreshUnreadCount } = useNotifications();
export function useNotifications() {
  return useContext(NotificationsContext);
}

Line for line, it's authContext.js with different names. The second file, NotificationsProvider.jsx, holds the count and fills the context, as AuthProvider does for the user.

Why not put it in AuthProvider?

AuthProvider already shares a value with the whole app, so the count could have been one more thing in it. But it's a different job: who is logged in, versus what they haven't read yet. One job per file, as in the back-end. It also keeps Stage 4 complete without notifications: a student whose API has none simply doesn't add the second provider.

Shared state is still rare

The app now has two contexts, and that's all it needs. The ticket list, the ticket, its comments and the tags are each used by one page, so they stay in that page's useState. A context is for what many components across the app need at once.
