The Count on Every Page

NavBar shows the count in words, in a live region a screen reader announces. main.jsx puts NotificationsProvider inside AuthProvider, because it reads the user.

NavBar reads the count with useNotifications(), and shows it inside the Notifications link, for anyone logged in:

// Figure 5.10: the link and its count (src/components/NavBar.jsx,
// excerpt)
{user && (
  <li>
    <NavLink to="/notifications">
      Notifications{' '}
      {/* The count is words, not just a coloured dot, so it
          doesn't rely on colour or a number alone.
          aria-live="polite" makes a screen reader say it when
          it changes, once the reader has finished speaking. */}
      <span className="unread-count" aria-live="polite">
        ({unreadCount} unread)
      </span>
    </NavLink>
  </li>
)}

Many apps show a red dot or a bare "3". "(3 unread)" says what the number means, so it works for everyone, and the link's whole name is "Notifications (3 unread)".

aria-live="polite"

A screen reader reads a page once and moves on. If text changes later, it says nothing, unless that text is in a live region. aria-live="polite" makes the <span> one: when the count changes, the screen reader announces it as soon as it has finished what it's saying. It's the same idea as role="status" on Loading, which is a polite live region too.

Inside AuthProvider

main.jsx now has three wrappers around App:

// Figure 5.11: the providers around the app (src/main.jsx, excerpt)
createRoot(document.getElementById('root')).render(
  <StrictMode>
    <BrowserRouter>
      <AuthProvider>
        <NotificationsProvider>
          <App />
        </NotificationsProvider>
      </AuthProvider>
    </BrowserRouter>
  </StrictMode>,
);

Stage 4 said the order of providers only matters for a provider that uses another one: it has to be inside it (topic 04, "Wrapping the App"). This is that case. NotificationsProvider calls useAuth() to know whose count to load, so it must be inside AuthProvider.

Try it

  1. In main.jsx, swap <AuthProvider> and <NotificationsProvider> (and their closing tags), so NotificationsProvider is on the outside. Save, and read the error in the browser's Console. Which line of NotificationsProvider.jsx does it point to, and why is useAuth() null there? Put them back.
  2. In the developer tools' Elements tab, select the Notifications link and open the Accessibility pane. What is the link's name? Mark a notification as read and look again.
