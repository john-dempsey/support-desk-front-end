The Unread Count, Shared

A second context holds how many notifications are unread, loads it from the API whenever the user changes, and shows it in the navigation bar on every page.

  • A Second Context

    The unread count is shown in the navigation bar, but changed by the notifications page. Like the logged-in user, it's shared through a context, in the same two files.

  • The Count Comes From the API

    The provider never adds or subtracts: it asks the API for the unread list and counts it. A failure leaves the last number showing, because the count is extra information.

  • Loading the Count When the User Changes

    An effect that depends on [user] loads the count when someone logs in, and its cleanup forgets the count when they log out.

  • The Count on Every Page

    NavBar shows the count in words, in a live region a screen reader announces. main.jsx puts NotificationsProvider inside AuthProvider, because it reads the user.
