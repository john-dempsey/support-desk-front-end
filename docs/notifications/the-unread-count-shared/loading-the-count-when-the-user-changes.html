Loading the Count When the User Changes

An effect that depends on [user] loads the count when someone logs in, and its cleanup forgets the count when they log out.

The provider loads the count in an effect. Here's Part 1's version of it, with REST only:

// Figure 5.9: loading the count when the user changes, Part 1's
// version (src/context/NotificationsProvider.jsx, excerpt)
useEffect(() => {
  // Nobody logged in: no count to load.
  if (user === null) {
    return;
  }

  // The same `ignore` flag as the pages: after a logout, a late answer
  // about the old user's count must not be shown.
  let ignore = false;

  async function loadUnreadCount() {
    try {
      const count = await fetchUnreadCount();
      if (!ignore) {
        setUnreadCount(count);
      }
    } catch {
      // The count is extra information in the corner of the screen, so
      // a failure leaves the last number showing, rather than an error
      // on every page. (A 401 still logs the user out, in client.js.)
    }
  }

  loadUnreadCount();

  // When the user logs out (user becomes null) or changes: forget the
  // old user's count.
  return () => {
    ignore = true;
    setUnreadCount(0);
  };
}, [user]);

(Topic 04 adds four lines for the socket, so the stage-05 code isn't exactly this.)

[user]: the effect follows the login

Until now, an effect has run once ([]), or again when something in the URL changed ([ticketId], [queryString]). This one depends on who is logged in. user comes from useAuth(), so whenever AuthProvider changes it, this effect runs again:

The cleanup belongs to the old user

A cleanup runs just before the effect runs again, so it always belongs to the previous user. That makes it the right place to forget them:

  • ignore = true: if Alex's count is still on its way when Alex logs out, it's ignored when it lands. Without this, Alex's number could appear after Casey has logged in.
  • setUnreadCount(0): Alex's count disappears when Alex does.

user === null is checked first because logging out runs the effect too. There's nothing to load for nobody, and no cleanup is needed, so it returns nothing.

Try it

Open the Network tab, choose Fetch/XHR, and type unread in its filter box, so only the count's requests show. Log in as Alex. How many requests are there? Log out, and log in as Casey. Now open Notifications and mark one as read. For each request in the list, say which line of which file sent it.
