Tracing a Push

Questions to practise the viva's trace with, now that some changes start on the server: the socket, the provider, the function form and the notice.

The viva's trace has been component → API module → HTTP request → state update → re-render, always starting with a click. Stage 5 adds traces that start somewhere else: on the server, with a push that arrives on a socket, which then leads to an ordinary HTTP request.

Write one yourself

Write the trace for a new notification appearing on Alex's Notifications page while it's open, as a numbered list, one line per step, with the file each step is in. Start with Casey clicking Add comment, and finish with the new item at the top of Alex's list. You should need about ten steps. Topic 05's diagram, "From Casey's Click to Alex's Count", covers most of it; the last steps are topic 05's function form.

Questions to practise with

Answer these out loud, with the code open. Then try them again with it closed.

  1. What are the two channels notifications reach the browser by? What would each one miss on its own?
  2. Which file creates the socket, and when? Why isn't it created in a component?
  3. Where does the token sent over the socket come from? Which function reads it, and how often?
  4. Why is the token sent on every connect, not just the first?
  5. When a push arrives, the count goes up. Which function runs, and why doesn't it just add 1?
  6. Why can the provider trust the new notification to be in the GET /notifications?unread=true answer?
  7. Alex logs out. Name everything that happens to the socket, the listener and the count, and the file each happens in.
  8. In NotificationsPage's push handler, why does setNotifications() get a function? What would notifications be inside the handler if it didn't?
  9. Why does handleMarkRead use the function form too?
  10. A push arrives while the list is still loading. What does the handler do, and why is that usually fine?
  11. How does TicketDetailPage decide a notification is about its ticket? Why Number(), and why is ticket.created ignored?
  12. Alex clicks Reload. Which state changes, which effect runs again, and why does the notice go away?
  13. Why doesn't the ticket page reload by itself when a notification arrives?
  14. Ada has ticket 1 open when Casey comments on it. What does Ada see, and why?

Try it

Pick two questions you couldn't answer with the code closed. Find the answers in the code, then explain each to someone else without looking.
