Marking One as Read

Mark as read sends a PATCH, then swaps the updated notification into the list with map(): a new array, the same length, with one item replaced.

When Mark as read is clicked, NotificationList calls the page's handleMarkRead() with that notification. Here's the first version of it, as it is in Part 1 of this stage:

// Figure 5.6: marking one notification as read, Part 1's version
// (src/pages/NotificationsPage.jsx, excerpt)
async function handleMarkRead(notificationToMark) {
  setMarkErrorMessage('');
  try {
    const updatedNotification = await markNotificationRead(
      notificationToMark.id,
    );
    // The API sends back the notification with readAt filled in. map()
    // makes a new array the same length, swapping in the updated one
    // and keeping every other notification as it was.
    setNotifications(
      notifications.map((notification) =>
        notification.id === updatedNotification.id
          ? updatedNotification
          : notification,
      ),
    );
    // One fewer unread, so NavBar's count needs updating too.
    refreshUnreadCount();
  } catch (error) {
    setMarkErrorMessage(error.message);
  }
}

(Reflowed to fit. Topic 05 changes the setNotifications() call, for a reason that only exists once notifications arrive live, so the stage-05 code doesn't look exactly like this.)

Update from the response

The API's answer is the notification as it's now saved, with readAt set. So the page swaps it into the list it already has, rather than loading every notification again: the same choice as adding a comment in Stage 3.

map() swaps one item

Stage 3 made new arrays two ways: [...comments, newComment] to add one, and filter() to remove one. map() is the third: change one.

map() calls the arrow function once per notification and builds a new array from what it returns: the updated notification where the ids match, and the same object everywhere else. You've used map() since Stage 1, to turn tickets into rows. Here it turns notifications into notifications.

To… Make the new array with… Seen in
add one [...list, newItem] Stage 3, adding a comment
remove one list.filter((item) => item.id !== removed.id) Stage 3, deleting a comment
change one list.map((item) => item.id === updated.id ? updated : item) here

Then the count

refreshUnreadCount() asks the API how many are unread now, so the count in the navigation bar goes down by one. The next topic is about that count.
