Loading Notifications and Marking Them Read

The notifications API file, what a notification looks like, the page that loads the list, the component that shows it, and marking one as read with map().

  • Three Requests About Notifications

    notifications.api.js has one function per request: all of the user's notifications, only the unread ones, and marking one as read.

  • What a Notification Looks Like

    Six fields: what happened (type), a sentence for the user (message), which ticket it's about, whether it's been read, and when it happened.

  • The Page Loads the List

    NotificationsPage loads the saved notifications when it opens, with the same state and effect as every page since Stage 2.

  • Showing Each Notification

    NotificationList shows each notification's message and date, says New in words for unread ones, and offers View ticket and Mark as read only where they make sense.

  • Marking One as Read

    Mark as read sends a PATCH, then swaps the updated notification into the list with map(): a new array, the same length, with one item replaced.
