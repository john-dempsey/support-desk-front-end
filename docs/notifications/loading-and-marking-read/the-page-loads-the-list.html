The Page Loads the List

NotificationsPage loads the saved notifications when it opens, with the same state and effect as every page since Stage 2.

NotificationsPage is a page like TagsPage: it owns the list, loads it when it opens, and hands it to a component to display.

// Figure 5.3: the page's state and what it shows
// (src/pages/NotificationsPage.jsx, excerpt)

useNotifications() and refreshUnreadCount are for the unread count in the navigation bar. The next topic is about them.

Nothing new in the effect

The effect that fills notifications has the same shape as TagsPage's, with getNotifications() in place of getTags() and its own state names: an ignore flag, try/catch/finally, and [] so it runs once, when the page opens. Open both files side by side and compare them.

Four states, as always

State What shows
loading "Loading notifications…" in role="status"
error the API's message in role="alert"
empty "You have no notifications." (from NotificationList)
success the list

The empty message is in NotificationList, like "There are no tickets to show." in TicketList: whoever displays the list knows when there's nothing in it.

Try it

  1. Log in to the app as Alex and click Notifications. Then log in as Ada. Whose list is longer, and why? (The previous slide's table has the answer.)
  2. With the app open on another page, stop the API: docker compose stop api in the back-end's folder. Don't reload the page: click Notifications in the navigation bar. What does the page say? Then start the API again with docker compose start api.

Why not reload? Reloading starts the app again, which checks your session with GET /auth/me. With the API down, that fails, and you're logged out (Stage 4, topic 05).
