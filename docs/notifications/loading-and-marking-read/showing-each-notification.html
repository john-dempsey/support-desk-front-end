Showing Each Notification

NotificationList shows each notification's message and date, says New in words for unread ones, and offers View ticket and Mark as read only where they make sense.

NotificationList is a component like CommentList: it displays what it's given, and calls the page back when a button is clicked.

One item

// Figure 5.4: each notification's message and date
// (src/components/NotificationList.jsx, excerpt)
{notifications.map((notification) => {
  // readAt stays null until the notification is marked as read.
  const isUnread = notification.readAt === null;

  return (
    <li
      key={notification.id}
      className={
        isUnread ? 'notification notification-unread' : 'notification'
      }
    >
      <p className="notification-message">
        {/* "New" is a word, not just bold text or a colour, so
            everyone can tell which notifications are unread. */}
        {isUnread && <span className="new-label">New</span>}{' '}
        {notification.message}
      </p>
      <p className="notification-meta">
        {formatDate(notification.createdAt)}
      </p>

(The className and the date are reflowed to fit.)

{' '} is the space between "New" and the message. JSX drops spaces at the end of a line, so a space that matters is written as a string. NavBar's "Notifications" link uses the same trick.

Until now, every map() in this app went straight to (: an arrow function that returns its JSX. This one has { and a return, because it works something out first: isUnread, used three times. Working it out once, with a name, is easier to read than repeating notification.readAt === null.

The buttons

// Figure 5.5: View ticket and Mark as read
// (src/components/NotificationList.jsx, excerpt)
<div className="button-row">
  {/* ticketId is null once the ticket has been deleted, and
      then there's nothing to link to. */}
  {notification.ticketId !== null && (
    <Link to={`/tickets/${notification.ticketId}`}>View ticket</Link>
  )}
  {isUnread && (
    <button
      type="button"
      className="secondary-button"
      aria-label={`Mark as read: ${notification.message}`}
      onClick={() => onMarkRead(notification)}
    >
      Mark as read
    </button>
  )}
</div>

The aria-label is CommentList's idea from Stage 3: a page full of buttons all called "Mark as read" is no help to a screen reader user, so each one's name says which notification it marks.

Not by colour alone

An unread notification has a thicker blue left border too, but the word New is what says so. Someone who can't see the colour, or is using a screen reader, still gets the word.
