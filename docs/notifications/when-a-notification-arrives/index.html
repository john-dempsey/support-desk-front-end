When a Notification Arrives

A push from Casey's click to Alex's count, why the count is fetched again, and the function form of a state update, which a handler that's registered once needs.

  • From Casey's Click to Alex's Count

    One comment, followed through two browsers and the API: saved, turned into a notification, pushed to Alex's socket, and counted again over REST.

  • Count Again, After the Save

    Re-fetching the count picks up everything that changed, not just the push. It only works because the API saves the notification before it pushes it.

  • The Page Listens Too

    NotificationsPage adds each push to the top of its list. The obvious way to write it uses the list from when the page opened, which is the wrong list.

  • The Function Form

    Give the setter a function instead of a value, and React calls it with the state as it is now. The handler no longer needs to see the list at all.

  • Back to Mark as Read

    handleMarkRead uses the list from the moment of the click. A push that lands while the PATCH is on its way would be lost, so it gets the function form too.

  • A Push While the List Is Loading

    If a push arrives before the list has loaded, the handler leaves the list as null: the load that's on its way will almost always include the new notification anyway.
