The Page Listens Too

NotificationsPage adds each push to the top of its list. The obvious way to write it uses the list from when the page opened, which is the wrong list.

While Notifications is open, a new notification should appear at the top of the list. The page listens with onNotification(), in an effect that runs once, like the provider's. Here's the obvious way to write it, which isn't what the app does:

useEffect(() => {
  function handleNotification(newNotification) {
    setNotifications([newNotification, ...notifications]);
  }

  const stopListening = onNotification(handleNotification);
  return stopListening;
}, []);

[newNotification, ...notifications] is Stage 3's spread, with the new item at the front instead of the end. It looks right. Try it, and a push makes the Console say:

Uncaught TypeError: notifications is not iterable

Which notifications?

Every render of a component is a fresh call of its function, with its own notifications constant. A function created during a render, like handleNotification, can only see that render's notifications. It can't see later ones.

The effect runs once, after the first render, so the handler on the socket is the one from render 1, when the list was still null. By the time a push arrives the screen shows a loaded list, but the handler still sees null. JavaScript can't spread null, hence the error.

It isn't only a null problem. If the list started as [], there'd be no error, but the handler would build [newNotification, ...[]]: a list of one, and every loaded notification would vanish.

Why the other handlers didn't have this problem

Every event handler so far, such as handleAddComment on a button, was created in the render the user was looking at when they clicked, so it saw the list as it was on screen. This handler is different: it's created once and called much later, from outside React, whenever the server decides.

Try it

In NotificationsPage.jsx, replace the whole setNotifications(...) call inside handleNotification with the plain version:

setNotifications([newNotification, ...notifications]);
